# 0.8.194 — the Pathfinder strip waits to be asked (2026-08-15)

## Highlights
- **The Pathfinder strip no longer appears on its own.** Selecting two objects is the most routine
  thing you do in Yappy — you get there to move, align, group or recolour them, or because a
  rubber-band grabbed one more than you meant. A floating panel of *destructive* operations was
  appearing over the artwork for all of that. It is now off by default and pinned open when you
  want it.
- **Nothing became harder to reach.** `Ctrl+Alt+U/D/I/X` work regardless of the setting, and
  right-click → *Pathfinder* still has all nine operations. Flipping the default was only safe
  because the fast path was never the panel.

## Breaking change / migration
**The strip is off by default, including for existing users.** `showPathfinderBar` is a new
preference and an absent value reads as off, so anyone used to it appearing will find it gone.
One click on the new top-bar **Pathfinder** button brings it back for good — the choice is stored
in `localStorage` and survives reloads.

## Features
- **Pathfinder strip toggle**, reachable five ways, all on surfaces that already existed:
  - the **Pathfinder** button in the top bar, beside Shape Builder
  - **View → Pathfinder Strip** (check-marked when on)
  - **right-click → Show / Hide Pathfinder Strip**, on both the canvas and selection menus
  - the **Command Palette** → "Pathfinder Strip: Show / Hide"
  - **Settings → Canvas → Pathfinder Strip**
- Sticky rather than modal. Pathfinder acts on a selection you already have, so a mode you enter
  and leave would add an enter/exit step to every operation. Pinned open, it survives selection
  changes and sessions — it is a workspace preference, not document state.

## API
- `setShowPathfinderBar(visible)` — show/hide the strip.
- `togglePathfinderBar()` — flip it; returns the new state.
- New `globalSettings.showPathfinderBar` (default `false`), persisted to `localStorage`.

## Docs
- Illustrator-class Tools help page: the combining section no longer claims the strip appears by
  itself, and a new "Turning the strip on and off" section explains *why* the default is off, lists
  every way to switch it on, and states plainly that the four shortcuts work either way.
- Help search keywords added for "pathfinder strip", "in the way", "obstructing", "pin open" — so
  someone hitting this exact annoyance can find the answer.
- `docs/learnings.md`: why "zero travel" is the wrong default for a destructive panel, and the
  distinction that actually matters — not how far away the control is, but how often the trigger
  state is incidental.

## Tests
- `tests/boolean-ops-ux.spec.ts`: two new cases — a 2+ selection alone must summon nothing *while
  `Ctrl+Alt+U` still works with no panel at all*, and the top-bar button toggles the strip with the
  choice surviving a reload. The eleven pre-existing cases assumed auto-appearance, so the suite now
  pins the strip open in `beforeEach`; that is the deliberate contract change, documented in the
  file header. 14/14 pass.

## Notes
- One assumption worth recording as wrong: the strip was suspected of covering the *selected* shapes
  and inviting a mis-click on Subtract. It does not — placement prefers above the selection and
  flips below when there is no room. What it obstructs is other artwork, which makes this a clutter
  fix rather than a safety one.
