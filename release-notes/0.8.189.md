# 0.8.189 — Editing a shape mid-tween actually works (2026-08-12)

## Highlights
- **The selection outline you can see is now the shape you can grab.** In Animation mode,
  anywhere inside a motion tween, the canvas drew a shape (and its handles) at the tweened
  pose while every hit test used the raw keyframe pose. Handles looked perfectly placed and
  grabbed nothing; clicking a tweened shape's body deselected it; dragging one made it crawl
  after the cursor. All three were the same disagreement about where the shape is.
- **Editing mid-tween splits the span for you**, Animate-style: a keyframe appears holding
  exactly the pose that was on screen, and your edit lands on that. Nothing jumps.
- **Alt+Shift resizes from the centre**, proportionally, on every handle.
- **A live W × H chip while you drag a handle** — resizing was previously a blind gesture.

## Features
- **Alt+Shift + drag a resize handle** — proportional resize about the centre (grows equally
  on all sides) instead of pinning the opposite corner. Works on all eight handles and on
  rotated shapes. Shift alone is unchanged.
- **Live size readout.** Dragging any resize handle shows a `W × H` chip under the shape, in
  the document's measurement unit, following the shape's rotation. On by default — it only
  exists during the drag. Steps aside when the always-on dimension badge
  (`Yappy.setShowDimensions(true)`) is enabled rather than stacking with it.
- **Mid-tween editing splits the span.** Grab a transform handle, or drag the shape past the
  drag threshold, and the motion span splits at the playhead first. A plain click to select
  never adds a keyframe. Shape tweens are deliberately left alone — a mid-morph outline has
  no faithful keyframe form.
- **Panel resize handles are now visible.** The dock zones and the animation timeline have
  been resizable and persisted for a long time, but both handles were fully transparent
  strips (6px and 8px) with no resting affordance, so the feature could only be found by
  accident. Both now carry a grip that brightens on hover.
- API: `Yappy.anim.posedElements()` returns the elements as the canvas is currently drawing
  them (tween pose baked in); `Yappy.anim.splitTweenAtPlayhead(ids?)` performs the split
  directly and returns the oldId → newId map.

## Fixes
- **Selected shape showed handles that grabbed nothing** (Animation mode, inside a tween).
  Handles were *drawn* from the tweened pose but *hit-tested* against the raw store, so the
  two sat in different places on every frame strictly inside a span. On a keyframe they
  coincide, which is why it read as intermittent. All hit tests now consume the same posed
  geometry the renderer does.
- **Clicking a tweened shape's body deselected it.** The hit test composed the frame-tween
  pose and then applied the seconds-based orbit/spin state on top; that spine reports *static*
  x/y for every element when nothing is orbiting, so the last write always reverted the shape
  to its keyframe. Now layered in the renderer's order — orbit/spin first, frame override last.
- **Moving a shape mid-tween made it lag the cursor.** The move edited the span's left
  keyframe, so the tween re-interpolated and the shape travelled only `delta × (1−p)` of the
  drag. Now the span splits first and the drag tracks 1:1.
- **Width/height edits didn't match what was on screen.** On a tweened frame the properties
  panel showed the keyframe's width while the canvas drew the lerp between two cels — the
  number and the pixels genuinely disagreed. Same root cause as the above.
- **The Keyframes dope sheet's left column was unclickable.** The panel was pinned to the
  window with `left: 0`, so with the toolbar docked left (the default) the property-name
  gutter ran underneath it — the Position X stopwatch and its neighbours were visible but
  the toolbar won the pointer. Same fix the animation timeline already carried.
- **Timeline caches went stale when the playhead didn't move.** Frame visibility and the tween
  pose memo keyed on `store.animTimeline`'s object identity, which is not a valid key: Solid's
  `setStore` merges into the existing proxy, so the reference survives a structural edit. They
  only ever looked correct because the frame normally changes at the same time. All 18 writes
  now route through `setAnimTimeline()`, which bumps a revision the caches key on — undo/redo
  and scene switching were among the writes that had been bypassing invalidation.

## Internal / tests / docs
- Resize geometry extracted from the pointer handler into `utils/resize-box.ts`
  (`computeResizeBox`) so all three modifier modes are unit-testable; the pre-existing rotated
  resize E2E specs pass unchanged, which is what licensed the refactor.
- New: `poseElementsAtFrame` (pure), `animPosedElements` / `animFrameOverrides` (memoized
  store readers), `splitTweenAtPlayhead`, `renderSizeReadout`.
- 32 new unit tests across `resize-box.test.ts`, `frame-pose.test.ts`, `anim-tween-split.test.ts`,
  plus E2E specs `anim-tween-handle-edit.spec.ts` and `alt-shift-center-resize.spec.ts`. Each was
  seen to fail against the bug it guards.
- `tests/history-panel.spec.ts` waited on `.history-panel`, which has not existed in the DOM
  since the panel moved into the dock system (the component renders `.history-panel-body`;
  the class survives in CSS only). Stale selector, not an app bug.
- `history-panel` and `alt-shift-center-resize` had no cold-boot headroom: both sat at ~24s
  against the default 30s budget, passing alone and failing under two-worker contention. Both
  now use the `test.setTimeout(90_000)` the animation specs already had.
- Help docs updated: Animation Studio gains a "Editing a shape in the middle of a tween"
  section; the workspace doc gains "Size while you drag" and documents the panel resize grips;
  Alt+Shift added to the hotkeys dialog.

## Breaking changes / migration
- None. Alt+Shift was previously unbound during a handle drag, and plain Alt (3D view-angle,
  path-handle break) is untouched.
