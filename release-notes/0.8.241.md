# 0.8.241 — Text-diagram import drew slides instead of diagrams (2026-09-08)

## Highlights
- Pasting a YSL diagram into **Import from Text** produced a deck of blank slides and deleted
  whatever you were drawing. All 15 YSL templates did this; the 14 Mermaid ones did not, which
  is why it was reported as "most" rather than "all".
- Import now draws into the document you are in, at the viewport, instead of clearing it.
- While the rest of the feature is worked through, text-diagram import sits behind
  **Settings → Dev Mode** — the menu item, its `Ctrl+Shift+I` command and the *Text Diagrams*
  template category go together. `Yappy.importDSL()` is unaffected.

## Fixes
- **#359 — every YSL text diagram imported as an empty slide deck.** Three faults, stacked.

  *Detection.* The dialog sniffed the format itself, and its Markdown test claims any text
  containing a `^---$` line, because Markdown uses that as a slide break. Every YSL source
  *opens* with `---` frontmatter, so all 15 templates were badged *Markdown → Slides* and
  imported by the slide parser. The dialog also carried its own list of Mermaid headers, which
  had drifted from the adapter's: `gantt`, `gitGraph`, `journey`, `quadrantChart`,
  `xychart-beta` and `block-beta` parsed correctly and were labelled *Text DSL*.

  *Routing.* Three templates failed even on the DSL path. `isYSLScript` read a bare keyword
  prefix as proof of a script, so a flowchart's last box (`end [circle] "End"`) or a sequence
  diagram's `loop … end` fragment went to the YSL parser, where both are syntax errors — while
  the text parser handles those fragments itself.

  *Blast radius.* The dialog passed `clearCanvas: true`, which deletes every element and forces
  the document back to an infinite canvas. That flag came from v0.25.6, aimed at the AI drawing
  path; on the manual import dialog it meant pasting a diagram threw your drawing away.

  Fixed at each: detection moved into the DSL module as `detectDSLFormat`, which asks the
  Mermaid adapter directly and recognises a diagram by structure Markdown cannot produce — a
  DSL frontmatter key, an edge operator, or a node's `[shape]` bracket — leaving Markdown as
  the fallback. `isYSLScript` matches full statement forms (`let x =`, `fn name(`, `for x in`,
  …), with `end` and `else` removed entirely, because a block terminator can never *open* a
  script. And import places the diagram at the viewport when the document already has content,
  fitting to screen only on an empty canvas.

## Internal / tests / docs
- `detectDSLFormat` and `looksLikeDiagramDSL` are exported from `frontend/src/dsl`, so the
  dialog no longer keeps a second copy of format detection to drift from.
- `templates/registry.ts` filters dev-only categories on read rather than skipping
  registration, so the Dev Mode toggle takes effect with no reload; `getTemplatesByCategory`,
  `getActiveCategories`, `getAllCategories`, `getAllTemplates` and `searchTemplates` all honour
  it, and so does `Yappy.getTemplates`.
- Verified against the real app: all 29 templates and all 24 `examples/dsl/` files parse, and
  all 29 render (pie, gantt, journey, quadrant and xychart are one chart element each by
  design). In the browser the badge reads *Text DSL*, the status "Valid — 6 nodes, 6 edges",
  the button **Import Diagram**, 12 elements are added, and a pre-existing rectangle and text
  survive. Markdown decks still detect as Markdown.
- `help-docs/features/ysl-tutorial.md` and `features/design-studio.md` note the Dev Mode gate;
  the `devModeHint` string names it in all five locales.
- `docs/learnings.md`: when two formats share one import box, the permissive detector wins
  whatever the order — the fallback has to be chosen by what a format *cannot* contain.

## Breaking changes / migration
- **Import from Text is hidden by default.** Turn on **Settings → Dev Mode** to reach it. The
  `Yappy.importDSL()` API is unchanged and always available; `Yappy.getTemplates('dsl-examples')`
  returns an empty list unless Dev Mode is on.
