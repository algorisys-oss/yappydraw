# 0.8.200 — Shift+S actually toggles stabilization (2026-08-16)

The Help dialog has listed **Shift+S — Stroke Stabilization (lazy brush)** for a long time. The
shortcut never worked. The stabilizer did; the key press just never reached it.

## Highlights
- **Shift+S toggles stroke stabilization from the keyboard**, as the Help dialog has always said
  it does. Previously it silently cycled the stroke style instead.

## Fixes
- **Shift+S was unreachable.** The keydown handler lowercases `e.key` once at the top, so the bare
  `key === 's'` branch (cycle stroke style) also matched Shift+S and returned first — leaving the
  `e.shiftKey && key === 's'` branch further down the same chain dead. Guarded the bare branch with
  `!e.shiftKey`. `s` was the only shortcut affected; every other Shift branch in that chain
  (`m i x n p l c t h v q`) has no bare counterpart above it. See bug #300.

## Internal / tests / docs
- New regression test in `tests/hotkeys.spec.ts` covering both directions of the Shift+S toggle and
  asserting a bare `s` still leaves stabilization alone, so the guard cannot over-correct. Verified
  failing before the fix.
- `docs/bugs/bug-fixes.md` #300, and a learning in `docs/learnings.md` on how normalising an input
  (`toLowerCase()`) widens every comparison made against it — a bare-letter branch in such a chain
  shadows every modified variant of that letter placed below it.

## Breaking changes / migration
- None.
