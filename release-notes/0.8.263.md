# 0.8.263 — Big drawings pan smoothly (2026-09-25)

0.8.262 stopped sketch style regenerating every shape each frame, but large paths were still
slow in both styles: every frame re-read every point through the store, rebuilt the outline and
parsed it again. A page-sized doodle cost ~130 ms of JavaScript per frame; it now costs ~2 ms.

## Highlights
- **Large drawings pan and zoom smoothly** in both sketch and architectural style. Measured on
  a page-sized doodle (≈7.5k curve points): 128 → ~2 ms of JavaScript per frame; on a doodle
  several screens across: ~1.5 s → ~2 ms (architectural), ~30 ms (sketch).
- Applies to any big path (traced images, imported SVGs, pathfinder results), not only doodles.

## Fixes
- **#400** Every frame re-walked big paths through Solid store proxies: the render-cache key
  (added in 0.8.262, and slower than it measured outside the app), the path outline, and a fresh
  `Path2D` parse.

## Internal / tests / docs
- `utils/store-raw.ts` `rawOf()`: read store data without proxies, for non-reactive reads.
- Path outline memoised per anchor array (`shape-geometry.ts`); parsed `Path2D` cache in
  `CanvasRenderer`; render-cache key remembers geometry digests per array (`rough-cache.ts`).
  All three rely on geometry arrays being replaced, never edited in place, which the code
  documents and the tests check from both sides.
- Tests: `shape-geometry-path-memo.test.ts`, `rough-cache.test.ts` (replaced array
  re-digests), `rough-element-cache.spec.ts` (a pan parses no big `Path2D`; fails with the
  cache removed).

## Breaking changes / migration
- None.
