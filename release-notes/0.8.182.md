# 0.8.182 — Storage that tells the truth (2026-08-07)

A user reported that all their saved local drawings had disappeared. The data was not deleted by
anything in the app — but the app had no way to say so, and one path could actively destroy the
last recovery copy. That's the bulk of this release.

## Highlights

- **A failed IndexedDB open no longer looks like deletion.** The gallery now says "your drawings
  can't be read right now — nothing has been deleted" instead of "No saved drawings yet".
- **A save that doesn't reach disk is reported as a failure**, and no longer deletes the
  crash-recovery copy on the way.
- **A transient storage failure no longer poisons the session** — it retries instead of caching
  the failure until reload.
- Marquee selection now picks up whole groups, matching Illustrator/Figma and matching what
  clicking already did.

## Fixes

### Saved drawings appearing to vanish

First, what it wasn't: neither v0.8.180 nor v0.8.181 touched `frontend/src/storage/`, and
`idb-kv.ts` has one commit in its whole history — database `yappy`, version 1, no upgrade path,
no `deleteObjectStore`. There is no migration that could have dropped anything.

What the code did allow is worse than a bug in one feature. The drawings gallery, autosave **and**
version history all sit behind a single IndexedDB handle, and every failure to open it resolved
to `null`, silently:

- Reads fell through to an empty in-memory map, so the gallery showed its "No saved drawings yet"
  empty state — identical to having lost everything — with both recovery copies invisible at the
  same moment.
- The failed open was cached for the whole page session, so a *transient* cause (`onblocked` —
  simply having a second Yappy tab open) was permanent until reload.
- `idbSet` reported success for writes that only reached memory, so the UI said "Saved" for data
  that dies with the tab.
- And `saveCurrentToGallery` then cleared the autosave slot on the premise the document was "now
  safely on disk" — so a save into dead storage **deleted the crash-recovery copy** while
  reporting success.

Now: opens retry instead of caching failure (and drop the handle on `onclose`/`onversionchange`);
`idbSet` returns false when a write only reached memory; `saveDrawingDoc` throws
`StorageUnavailableError` **before** the autosave slot is cleared; and the gallery distinguishes
"nothing saved" from "cannot read", telling the user plainly that nothing has been deleted and to
close other tabs and reload.

> **If you hit this:** your drawings are almost certainly still on disk. Close every other Yappy
> tab and reload. You can confirm in DevTools → Application → IndexedDB → `yappy` → `kv`, where
> `yappy:drawings:index` lists them. Private windows have their own, separate storage.

### Marquee vs. groups

Dragging a selection box over part of a group selected the individual members, while *clicking*
any member selected the whole group — so the two gestures disagreed, and you could rubber-band
three shapes out of a group and drag them away from their siblings. Marquee and lasso now select
whole groups, as in Illustrator and Figma. Inside an isolated group they still select individual
members, which is the point of stepping in.

## Internal / tests / docs

- `tests/storage-failure.spec.ts` — stubs `indexedDB.open` to fail from boot; covers the honest
  failure, the retry after a transient failure, and the gallery's wording.
- **59 spec files defaulted to port 5180** (nothing serves it; `playwright.config.ts` starts
  5173), so they only passed when `YAPPY_URL` was set by hand. All 157 references now point at
  5173.
- `tests/group-isolation.spec.ts` gains the marquee case.
- `docs/bugs/bug-fixes.md` 277; a new entry in `docs/learnings.md` on fallbacks that lie.

**Not a bug:** `tests/game-export.spec.ts` was reported failing in 0.8.181's notes. It wasn't —
those specs import `/src/…` paths and can only run against the dev server, not a preview build.
Both pass.

## Breaking changes / migration

None. `Yappy.saveToGallery()` now rejects with `StorageUnavailableError` when local storage is
unavailable, where it previously resolved as though the save had worked — scripts that relied on
it never throwing should add a `catch`.
