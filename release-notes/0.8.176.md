# 0.8.176 — Real italics, and Knife pieces that are still curves (2026-08-05)

Closes the two gaps flagged as known limitations in 0.8.175.

## Highlights

- **Create Outlines handles italics properly** — from the family's real italic face where there
  is one, and matching the browser's own slant where there isn't.
- **Knife pieces come back as curves**, with the shape's corners and the cut edge still sharp.

## Features

### Italic outlines

`Create Outlines` ignored `fontStyle` entirely, so italic text converted to upright paths.

- Real italic faces are now bundled for **Inter, Poppins, Merriweather, Source Code Pro and
  JetBrains Mono**, at Regular and Bold where a parseable one exists.
- Face selection follows CSS's own order — **slant first, then weight**. That is what keeps
  letterforms right: a true italic is a different design, not a sloped roman (in a serif the
  `a` changes shape entirely), so a Bold Italic in a family whose italic exists only at 400
  uses the 400 italic rather than a sheared Bold.
- Families with **no** italic face (Virgil, Marker, Caveat), and user-added fonts where the
  selected file is upright, are slanted by 0.2 — Chrome's synthetic oblique, i.e. exactly what
  the canvas is already showing. The vector therefore matches the text it replaced.
- The slant is applied per *line*, about that line's own baseline; a single reference line
  would slide successive lines sideways instead of slanting each of them.

Sourcing note for future maintenance: four of the five families have moved to variable fonts
upstream, and Merriweather's variable italic is 4.6 MB. fontsource's static per-weight **WOFF**
instances are 48–77 KB with full glyph coverage, and opentype.js 1.x reads WOFF (just not
WOFF2). Merriweather's bold-italic WOFF fails to parse and is deliberately not bundled — Bold
Italic uses its 400 italic.

### Knife results are curves again

Cutting a circle produced pieces whose arc was ~20 corner anchors — accurate, but not editable
as the curve it obviously is, and dozens of points where the original had four.

New `utils/curve-refit.ts` detects corners by turn angle, keeps those sharp, and fits curves
only to the runs between them. Cutting a circle in half now gives **5 anchors per piece**: two
corners at the ends of the straight cut, three smooth along the arc. A knifed rectangle keeps
square corners and flat sides, and the cut edge itself stays a straight line.

Opt-in (`buildPathFromPoly(..., refit)`) and currently used only by the Knife; Pathfinder
booleans still return literal polygons.

## Fixes

- The Create Outlines glyph binaries are **excluded from the PWA precache**. They are fetched
  lazily, only when something is actually outlined, so precaching them made every visitor
  download megabytes up front for a feature most never touch. They are not the fonts the app
  renders with — nothing about display changes.

## Internal / tests / docs

- New module `utils/curve-refit.ts` (+12 tests); suite 487 → 499.
- Two implementation notes worth keeping, both recorded in `docs/learnings.md`:
  Douglas–Peucker is the wrong simplifier when a *curve* replaces the dropped points (it kept
  all 48 points of a flattened circle at any sane tolerance); and `chord/3` handles are 4%
  short at 45°, a systematic inward bias that the exact `(4/3)·tan(θ/4)` arc factor removes.
- Help docs updated: the "italic outlines upright" limitation is gone from the Logo Toolkit
  page and replaced with how italics actually resolve; the Knife/Scissors note now describes
  the refit.

## Breaking changes / migration

**None.**
