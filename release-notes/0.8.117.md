# 0.8.117 — Set the pace, and ten new things to do

**Date:** 2026-07-20

## Highlights

- Animated figures get a **Speed** control that works everywhere — in-place clips,
  action sequences *and* walking a path.
- **Ten new motion clips** for everyday actions: Sit, Type, Squat, Lift weights,
  Stretch, Kick, Cook, Sweep, Drink, Think. Twenty in total.
- Fixed: **"Walk this path" did nothing** when the route was a plain Line.

## Features

- **Speed slider.** Select an animated figure and drag **Speed** (0.25×–3×, or type any
  value from 0.05 to 8). It scales in-place clips, action sequences and path-following
  alike, so one control means the same thing everywhere. **Reset** returns to 1×.

- **Lap time.** A figure following a path now shows **Lap time** — how many seconds one
  trip along the route takes at 1×. Reshaping the path keeps the same lap time, so a
  longer route simply means a faster walk; use Speed on top to scale it.

- **Ten new motion clips**, all authored to read from the side like the existing ones:

  | Clip | What it does |
  |---|---|
  | **Sit** | Seated and breathing, hands on the thighs |
  | **Type** | Seated at a desk, hands tapping |
  | **Squat** | A full squat cycle — hips back, feet planted |
  | **Lift weights** | A bicep curl, both arms together |
  | **Stretch** | Reach overhead and ease back down |
  | **Kick** | One leg swings forward and back |
  | **Cook** | Leaning over the hob, one hand stirring |
  | **Sweep** | Both hands on a broom, pushing forward and back |
  | **Drink** | Raise a cup to the mouth, tip, lower |
  | **Think** | Hand at the chin, slow head tilt |

  They combine with everything that already existed — expressions, action sequences,
  path-following and Bake. Pair Sit or Type with a chair/laptop prop from the library.

- **API.**

  ```js
  Y.setAnimatedFigureSpeed(2, [id]);   // 2x; clamped to 0.05–8
  Y.setFigurePathDuration(8, id);      // 8s for one lap of the route, at 1x
  Y.listStickFigureClips();            // now 20 clips
  Y.insertAnimatedFigure('cook', { x: 200, y: 200 });
  ```

## Fixes

- **"Walk this path" silently did nothing on a plain Line.** The button reported success
  and the panel switched to "Stop following path", but the figure kept animating in
  place. A `line`/`arrow` element carries no anchor or point list — it is defined purely
  by its box — so the route sampled to nothing while the capability check accepted the
  type by name. Routes now fall back to the element's own box (corner to corner, with any
  control points folded in). Curve and pencil routes were unaffected, which is why this
  survived so long. See `docs/bugs/bug-fixes.md`.

- **Path-following ignored the figure's `speed`.** It computed progress straight from
  wall time, so the new Speed control would have appeared dead for exactly the figures
  most likely to use it.

## Internal / test changes

- 5 new Playwright tests (`tests/stick-animation-speed.spec.ts`): all 20 clips are
  registered and render real pixels at multiple phases (a NaN joint draws nothing),
  speed persists and clamps, a figure on a plain line actually travels it, speed scales
  path traversal (measured from rendered pixels, not state), and lap time is applied and
  floored.

- Clip authoring conventions are now written down at the top of the daily-actions block:
  a negative limb offset swings forward/up, and `footTargets` are pelvis-relative, so a
  clip that drops the pelvis by D must raise its targets by D or the feet sink through
  the floor.

- `docs/learnings.md`: a capability predicate must be derived from the function that
  implements the capability (or every type it admits needs a case there); when one rate
  control exists, every clock read must honour it; and "hand to face" on a 2-bone limb is
  near-degenerate IK that should be solved from the geometry rather than nudged.

## Breaking changes / migration

None. Existing figures default to `speed: 1` and behave exactly as before — except
path-followers on a plain Line, which now actually move.
