# 0.8.125 — Centred shape labels; Properties panel stops popping up (2026-07-21)

## Highlights
- Text you type into a shape is now **centred by default** instead of left-aligned.
- The **Properties panel no longer opens by itself** when you pick a drawing tool — it opens only
  when you ask for it, and stays put once docked.

## Features
- **Centred text by default.** `defaultElementStyles.textAlign` changed from `'left'` to
  `'center'`, so every newly drawn shape (and every new text element) starts centred. The
  renderers already fell back to `'center'` when `textAlign` was unset — creation now agrees with
  them, so the label you see while typing matches the label you get. Override per element with the
  alignment buttons in the Properties panel / smart toolbar, or `textAlign` in
  `Yappy.createElement(...)`. Deliberate exceptions are unchanged: code blocks and UML
  attribute/method sections stay left-aligned, and table cells keep their per-cell alignment.
- **Properties panel opens on request only.** Selecting a drawing tool used to force the panel
  open, which during a long brainstorming session meant the panel sliding in over the canvas on
  every tool switch. Open it deliberately with `Alt+Enter`, the sliders button in the bottom-left
  cluster, or by right-clicking a tool group (which still opens the panel on that tool's
  defaults). Once open it stays docked while you work.

## Fixes
- None.

## Internal / tests / docs
- `api.ts`: the `textAlign` fallbacks in the element-creation paths now read `'center'` instead of
  the now-unreachable `'left'`, so the documented default matches the store.
- Help docs: "Properties panel" section of the Workspace doc documents the open-on-request
  behaviour; Basic Shapes doc gains a "Text labels" subsection covering the centred default and
  how to override it.
- Learnings entry on keeping creation defaults and render fallbacks in agreement.

## Breaking changes / migration
- New shapes are centred where they used to be left-aligned. **Existing documents are untouched** —
  elements carry their own `textAlign` and keep it. `textAlign` is not among the persisted
  `SETTINGS_KEYS`, so no localStorage migration was needed; the new default applies immediately.
- Scripts that relied on the implicit `'left'` default from `Yappy.createElement(...)` should pass
  `textAlign: 'left'` explicitly.
