# 0.8.204 — Ungroup came back to the right-click menu (2026-08-20)

Reported with a screenshot: an outlined word, selected, and a right-click menu offering four
path-editing items and nothing else. No Ungroup, no Group, no Pathfinder, no Copy — and on a
tablet no `Ctrl+Shift+G` to fall back on, so the group could not be taken apart at all.

## Highlights

- **Right-clicking a path shows the whole menu again.** The path-editing actions (Make Smooth /
  Corner, Delete Anchor, Insert Point Here, Constrain Handles) sit at the top; everything you
  normally get — Group/Ungroup, Pathfinder, Arrange, Copy, Lock, Export — follows underneath.

## Fixes

- **Ungroup was unreachable whenever you pressed on the artwork itself.** Fallout from 0.8.202,
  where anchor editing moved off the Select tool and into the right-click / long-press menu: that
  menu was wired in as a *replacement* for the element menu rather than an addition to it. It
  opens whenever the press lands on a selected path's anchor **or** anywhere along its outline,
  which on an outlined word or an imported icon is most of the artwork — so the natural place to
  press produced a four-item menu, and pressing slightly off the shape produced the full one.
  Hence "not available in some cases". The two menus are now merged, Illustrator-style, with the
  more specific actions first.

## Internal / tests / docs

- `frontend/src/utils/path-menu-merge.ts` — a small pure `mergePathMenu(anchor, generic)` that
  does the join and trims the seam so the two lists never draw two separators in a row. Unit
  tested (`path-menu-merge.test.ts`, 5 tests) and verified live in the browser: anchor press,
  outline press, and a press away from the path, plus Ungroup actually dissolving the group from
  the merged menu.
- Bug #306 in `docs/bugs/bug-fixes.md`; the general rule ("a context-sensitive menu prepends, it
  does not replace") in `docs/learnings.md`; help doc `shapes/vector-paths.md` updated.

## Breaking changes / migration

None.
