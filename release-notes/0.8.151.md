# 0.8.151 — LaTeX equations, vector fields and clock-driven properties (2026-07-28)

## Highlights
- **`Yappy.tex`** — typeset real LaTeX as vector artwork. Fraction bars, integrals with
  limits, matrices, radicals: the things Unicode could only approximate. Individual
  symbols are addressable, so you can recolour or animate just the `π`.
- **`Yappy.setExpression`** — drive a property from a formula in `t` instead of keyframes.
  The practical equivalent of manim's `ValueTracker` + `always_redraw`.
- **`plot.vectorField`** and **`plot.polarGrid`** — gradient flow, phase portraits, polar curves.
- The SVG importer now resolves `<use>`/`<defs>` references, which fixes sprite-sheet and
  Illustrator SVGs generally, not just maths.

## Features

### LaTeX (`Yappy.tex`)
Async — MathJax (~1 MB) loads lazily on first use and is cached, so app startup is unaffected.

```js
const eq = await Yappy.tex(200, 200, 'e^{i\\pi} + 1 = 0', { fontSize: 48 });
eq.ids       // one path per glyph, in reading order
eq.parts     // [{ index, char: 'e', node: 'mi' }, …]

// address one symbol — manim's equation[R"\pi"]
Yappy.texPart(eq.groupId, 'π').forEach(id =>
    Yappy.updateElement(id, { backgroundColor: '#dc2626' }));
Yappy.texPart(eq.groupId, 0);   // …or by index
Yappy.texParts(eq.groupId);     // every glyph
```

Each glyph is an ordinary path element, so equations scale, restyle, animate and export
like any other artwork. Symbols are keyed by the character they **render as** — MathJax
emits Mathematical Alphanumeric Symbols (`𝑒` is U+1D452), which are NFKD-normalised back
to `e`/`π` so the lookup behaves as expected. Invalid TeX reports an error and creates
nothing rather than failing silently.

### Expression tracks (`Yappy.setExpression`)
```js
Yappy.setExpression(dot, 'y', '300 + 120 * Math.sin(t * 3)');   // bobbing
Yappy.setExpression(dot, 'angle', 't * Math.PI');                // spinning
Yappy.clearExpression(dot, 'y');
```
Stored as a string, not a closure, so a composition stays JSON-serialisable across
save/load and the embed bridge. An expression replaces keyframes on that property. One
that throws or returns a non-finite number is skipped and not retried, so a typo cannot
spam the console every frame.

### Vector fields and polar grids
```js
Yappy.plot.vectorField(ax, (x, y) => [-y, x], { step: 0.5 });   // rotational
Yappy.plot.vectorField(ax, '2*x', '2*y');                        // two scalar functions
Yappy.plot.polarGrid(ax, { ringStep: 1, spokes: 12 });
```
Arrow lengths are normalised so the longest vector on the grid is `maxLength` units —
otherwise a single large vector flattens the rest into invisible stubs.

### Plot functions accept both string shapes
`'Math.sin(x)'` (an expression body) and `'x => Math.sin(x)'` (a whole arrow function)
now both work, in `graph`, `parametric` and `vectorField`.

## Fixes
- **SVG import ignored `<use>` and `<defs>` entirely.** Both were in the importer's skip
  list, so any SVG built as a sprite sheet — a shape defined once in `<defs>` and placed
  by `<use>` — imported as nothing at all. `<use>` now splices in the referenced subtree
  with its `x`/`y` offset and transform, `<symbol>`/`<svg>` targets act as groups, and
  self- or mutually-referencing `<use>` chains are depth-guarded rather than hanging.

## Internal / tests / docs
- New: `frontend/src/utils/tex.ts`; `mathjax-full` added as a dependency (lazy-loaded).
- `vite.config.ts` defines `PACKAGE_VERSION` in both the Rollup build and the dev-server
  pre-bundle — MathJax reads its own version via `eval('require')`, which no bundler can
  rewrite; defining the constant skips that branch. See `docs/learnings.md`.
- `PropertyTrack` gains an optional `expr` field; `DrawingElement` gains `texPart` /
  `texGroupId`.
- Specs: `tex-and-fields.spec.ts` (8). Full related suite 44 green.
- Help doc **Math Plotting** is now **Maths & Plotting** and covers LaTeX, vector fields
  and polar grids; the Animation doc gains an "Expression tracks" section.

## Known limitations
- Tick labels are plain text, not TeX — place a `tex()` equation beside the axis if you
  need notation there.
- Symbols are keyed by rendered character, not LaTeX source. Structural marks with no
  glyph (fraction bars, radical vinculums) have no `data-c` and are not individually
  addressable.
- No logarithmic or 3D axes. 3D would need a scene graph and camera.

## Breaking changes / migration
None. Everything is additive, and all of it produces ordinary elements and composition
tracks.
