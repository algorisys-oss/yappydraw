# 0.8.179 — The specs that were testing nothing (2026-08-07)

Test-only. No product code changed: a long-red family of end-to-end specs now actually exercises
what it claims to, and three of them were worse than red — they were **green while testing
nothing**.

## Highlights

- **47 tests across 13 spec files, all passing** — 16 of them had been failing, 3 passing
  vacuously.
- A shared `tests/_canvas-coords.ts` so no spec has to re-derive where the canvas is.

## Why they were broken

Four separate causes, all the same shape: *the spec describes a UI that has since moved.*

### 1. World coordinates handed to `page.mouse`

`page.mouse` is in **viewport** pixels. The app's world→screen maths
(`utils/viewport-transforms`) is in **canvas-local** pixels — `clientX/Y` minus the canvas's
bounding rect. The canvas is inset by the docked chrome (46px tool column, 52px top bar), so
"press the middle of the rectangle at (490, 390)" landed 46px left and 52px up: on the element's
resize handle, on the tool column, or on empty canvas.

That is why three of these were **green**. Before 0.8.178 the app opened on a pen, so the press
started a stroke, the element under test never moved, and `expect(x).toBe(250)` — its
*unchanged* position — passed. Switching the default tool to Select turned two of them red, which
is how the whole family got noticed.

### 2. Overlays that were fixed, breaking the specs that clicked them

`getPathNodes()` reports world coordinates, and the node-tool overlay moved onto `worldToWindow`
in 0.8.163 — so the anchors started being drawn where they belong, and five `node-tool` specs,
still clicking raw world coordinates, started missing them.

### 3. UI that was restructured

- `uml-tool-group.tsx` **is no longer rendered anywhere** — UML shapes are in the Architecture
  group now — so `button[title="UML: Class"]` could never match. The toolbar also opens in
  Brainstorm mode, which has no tool groups at all, so the spec has to ask for the full toolbar
  first.
- The Swatches panel moved onto the dock, so `.swatches-panel` / `.swatches-panel-header`
  stopped existing. Exactly the migration that had already left `builtin-panel-drag.spec.ts` red
  against `.layer-panel` — with a comment saying so.

### 4. A target parked under other chrome

`artboard-overlay` moved its artboard down 40px, putting the SE resize handle at viewport y≈832 —
**underneath the status bar**. `boundingBox()` still reported it (covered is not hidden), so the
press went to the status bar and the resize silently did nothing.

## The fix

New **`tests/_canvas-coords.ts`**:

- `canvasOrigin(page)` — the canvas's top-left in viewport px.
- `toViewport(page, x, y)` — world → viewport, honouring the live zoom/pan.
- `addOrigin(page, x, y)` — for values that already have the view transform baked in.
- `worldMouse(page)` — a `page.mouse` bound to world coordinates, so a spec keeps saying
  "press (490, 390)" and actually lands there.

`canvasOrigin` **waits for the rect to stop moving** rather than reading it once. The canvas is
positioned by `handleResize` after mount, so an early read comes back (0, 0) — reintroducing the
very bug the module exists to prevent. That bit during this work: one spec stayed red with a
suspiciously round pointer coordinate, which was the tell.

Retargeted specs: `uml-tools` leaves Brainstorm mode, uses the Architecture group, and waits on
the tool being armed rather than on a sleep; `panel-drag` drives the dock panel and asserts what
the dock actually promises (the panel follows the cursor and ends up floating), matching
`builtin-panel-drag`; `artboard-overlay` pans so its handle clears the status bar.

Files: `node-tool`, `snapping`, `point-snapping`, `path-intersection-snap`,
`select-and-constrain`, `spacing-guides`, `text-autosize`, `uml-tools`, `artboard-overlay`,
`panel-drag`.

## Breaking changes

None — no product code changed.
