# 0.8.169 — Every drawing tool gets its options in the top bar (2026-08-01)

## Highlights
- The contextual tool-options bar handled only the **Node tool and the freehand brushes**;
  for every other tool the middle of the top bar was blank. Shapes, connectors and text now
  each get their own controls — bound to the *tool's* settings, so what you set is what the
  next thing you draw comes out as.
- The controls are the **same widgets the floating quick toolbar uses**, extracted rather
  than re-implemented. A newly added shape type inherits its options for free.

## Features
- **Shape tools** — stroke colour, fill colour, stroke style, opacity, corner roundness (on
  shapes that have corners), and the font/size/alignment used for text typed inside the
  shape.
- **Connectors** (line, arrow) — stroke colour, line width, stroke style, line type
  (straight / curved / elbow) and the arrowhead at each end.
- **Text tools** — colour, font, size, bold, italic, alignment.
- **Freehand brushes** — gained stroke colour and width, alongside the Fill and Symmetry
  controls they already had.
- Each tool keeps its own settings (`setSelectedTool` already saved/restored per-tool
  styles), so a red brush and a black rectangle stay that way as you switch between them.

## Fixes
- **Controls that would have been ignored are not offered.** `draw-handler` overrides
  `curveType` for the Bezier, Elbow, Polyline and Organic Branch tools — those tools *are* a
  line type — so a "Line Type" picker there would silently discard the choice. Likewise
  `curvedText` and the image filters need an element that already exists and mean nothing as
  a default. Both exclusions live in one tested function rather than in the component,
  because the rule is about what the draw handler does.
- **Popovers in the bar are no longer clipped.** `.topbar-center` is `overflow: hidden` and
  the bar itself sets `overflow-x: auto` — either alone is enough to cut a dropdown off,
  since a box that scrolls in one axis is a scroll container in *both*
  (`overflow-y: visible` computes to `auto`).

## Internal / tests / docs
- New `components/quick-controls.tsx`: the icon set, the five controls (colour dot, collapsed
  icon-select, icon toggle, mini slider, preset select) and a `QuickControl` dispatch, moved
  out of `quick-toolbar.tsx`'s 840 lines. It takes a value accessor and a commit callback and
  knows nothing about what it edits — the quick toolbar binds it to the selected element, the
  options bar to `defaultElementStyles`. The caller owns history: the selection side
  snapshots per discrete edit (sliders once per drag), the defaults side has nothing to undo.
- New `getToolDefaultProperties(tool)` in `config/quick-toolbar-config.ts`, derived from the
  existing `getElementFamily` families — which is why an unrecognised type falls through to
  `shape` and a new shape gets options without touching the config.
- **Popover portalling is opt-in per host** (`float`). Converting the quick toolbar's
  popovers to fixed as well would have introduced a detach-on-pan bug to fix a problem it
  does not have — it has no overflow of its own. Portalled popovers leave their stacking
  context, so `.qt-floating` clears the top bar's 10050/10060 band rather than the 10002
  that worked inside it.
- `.tool-options-bar button` → `.tool-options-bar > button` so the bar's indigo pill styling
  stops at its own buttons and leaves the nested quick controls alone.
- `config/quick-toolbar-config.test.ts` (7 cases) pins the exclusion rules;
  `tests/tool-options-bar.spec.ts` +4 e2e, including a draw-and-read-back proving a colour
  picked in the bar lands on the next rectangle, and a regression test that the quick toolbar
  still edits *and still undoes* after the extraction. 400 unit / 10 spec, all green.
- Help: new "Tool options (top bar)" section in the Drawing Tools doc.
- **Roadmap housekeeping** — two "known issues" at the top of `todo.md` were stale and are
  closed: the `react/jsx-dev-runtime` test error (fixed in v0.8.168), and "backend dev server
  fails under Bun", which was flagged as *the* item affecting the daily dev loop but no
  longer reproduces on bun 1.3.13 / tsx 4.21 / node 24.18 — re-verified that `bun run dev`
  brings up both halves. The `tsx watch` vs `bun --watch` policy question it was blocked on
  is moot.

## Breaking changes / migration
None. The bar edits existing tool defaults; no API surface changed and no document data is
affected.
