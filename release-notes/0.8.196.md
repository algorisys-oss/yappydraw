# 0.8.196 — two tools that stopped working underneath you (2026-08-15)

Both fixes come from user feedback after a session spent building a cartoon character with vector
shapes and lines. Bugs only; the feature requests from the same report are being worked separately.

## Highlights
- **Undo no longer kills the Pen tool.** Pressing Ctrl+Z mid-path left the Pen convinced it was
  still building a path that no longer existed, so every later click did nothing at all until you
  pressed Escape.
- **The Knife cuts lines into lines.** It used to turn a cut open path into *filled shapes*, and on
  a plain straight line it silently did nothing whatsoever.
- **The Scissors can cut a plain line**, which it previously refused outright — same root cause.

## Fixes
- **#298 — Undo made the Pen tool stop working.** The Pen's building state lives in a module-level
  `pState`; the element it writes to lives in the store. Undo rewinds only the store, so a Ctrl+Z
  mid-path restored a snapshot from before the path existed and left `currentId` naming a deleted
  element. Measured: three anchors, Ctrl+Z, two more clicks → **zero** elements. Now every Pen
  entry point drops building state whose element has gone, so the next click just starts a fresh
  path. Guarding the entry points rather than hooking undo means redo, deleting the element, a
  script or a cleared layer all recover too.
- **#299 — The Knife turned a cut line into filled shapes.** Everything went through
  `elementToMultiPolygon`, i.e. was treated as a filled region. A 2-point line produced a ring
  below the 4-point minimum and was silently skipped; a 5-anchor open path came back as **4 closed
  shapes**. Open geometry is now split at the crossings using the Scissors' exact cut instead of
  being polygonised. A drag crossing the same open path several times cuts it at each crossing,
  and the whole drag is one undo step.
- **#299b — The Scissors refused a plain line.** A line created from a bounding box has no
  `points`, and `getShapeGeometry` has no `line` case, so `shapeToPath` returned null and the tool
  answered "cannot split this shape". `shapeToPath` now converts a point-less line or arrow from
  its endpoints, repairing both cutting tools from one place.

## Internal
- `splitPathAt(id, point, { history?, toast? })` — the Knife drives it once per crossing, so it
  needed to opt out of the per-call undo snapshot and toast and take one of each for the whole
  stroke. Existing callers are unaffected.

## Docs
- Illustrator-class Tools help page: the Knife entry no longer claims it always produces
  "fully-closed pieces", and spells out that lines and open paths stay open.
- `docs/bugs/bug-fixes.md`: entries 298 and 299 with the measured symptoms.
- `docs/learnings.md`: why tool state in a module plus document state in the store is a latent bug
  in any tool holding an element reference across gestures, and how one geometric assumption
  produced two symptoms that read as unrelated bugs.

## Tests
- `tests/pen-undo-recovery.spec.ts` — 3 cases: the Pen keeps working after a global undo mid-path
  (and the new path finishes normally without needing Escape first); undoing the *second* of two
  paths leaves the first intact and the tool usable; and deleting the in-progress element from
  anywhere else does not wedge the tool.
- `tests/knife-open-paths.spec.ts` — 7 cases: a straight line cuts into two OPEN pieces, an open
  drawn path keeps both halves open with no invented fill, a closed shape still cuts into closed
  pieces (the behaviour that must not regress), a stroke crossing an open path twice makes three
  pieces, a miss changes nothing, the whole cut is one undo step, and the Scissors splits a plain
  line.
- Re-ran `knife-scissors`, `knife-exit`, `path-intersection-snap`, `pen-features` and `pen-resume`
  for regressions, plus 563 unit tests. All pass.

## Known knock-on
- `cornerTargets` in `vector-tools-panel.tsx` treats "convertible by `shapeToPath`" as "has
  corners", so a selected line now offers the Live Corners control. A 2-anchor open path has no
  interior anchor to fillet, so the control does nothing. Noted rather than fixed to keep this
  change scoped to the reported bugs.
