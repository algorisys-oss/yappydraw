# 0.5.30 — Page thumbnails, font pairings & stock photos (2026-07-04)

## Highlights
- The Pages panel now shows a **live thumbnail for every page**, refreshing as
  you edit.
- The Elements panel grew into three tabs: **Elements / Fonts / Photos** —
  curated font pairings and keyless openly-licensed stock photo search.

## Features
- **Page thumbnails** — non-active pages get thumbnails automatically (loaded
  documents no longer show blank name tags), and thumbnails refresh ~1s after
  any edit, not just when the element count changes.
- **Font pairings** (Elements → Fonts) — 10 curated heading/body combos
  (Modern, Editorial, Bold Statement, Classic, Geometric, Friendly, Elegant,
  Playful, Technical, Magazine), previewed in their own faces. One click
  refonts the document (40px+/bold → heading font, rest → body) and sets the
  body font as the default for new text; Google fonts load on demand.
  `Y.getFontPairings()`, `Y.applyFontPairing('editorial')`
- **Stock photos** (Elements → Photos) — search openly-licensed images via
  the Wikimedia Commons API (no key, official anonymous CORS). Click to
  insert centered on the active page; the file-page link and attribution
  (artist + license) are kept on the element (`link`/`tag`). Insertion uses
  the 1280px rendition to keep documents lean.
  `Y.searchStockPhotos('mountain')`, `Y.insertStockPhoto(photo)`

## Fixes
- **"Photo search failed"** — the initial Openverse provider intermittently
  rejected real-browser requests with 401 (bot scoring) and caps anonymous
  use at 200/day; switched to Wikimedia Commons and verified search + insert
  live in a browser.
- **Dev-server page reload when opening Elements** — lazy-chunk dependencies
  (lucide-solid and friends) are now pre-bundled via `optimizeDeps.include`,
  so Vite never discovers them mid-session and forces a full reload
  (dev-only issue; production builds were unaffected).
