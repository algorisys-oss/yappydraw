# 0.8.253 — the drawing API on npm (2026-09-14)

## Highlights
- **`npm install @algorisys/yappydraw`.** The SDK that v0.8.250 put on jsDelivr is now also an npm package,
  with type declarations. It holds the same files as the release's `cdn/` folder on GitHub.

## Features
- **npm package `@algorisys/yappydraw`.**
  - ES module (`import { Yappy, toSVG, mount, fontsReady, clear, version } from '@algorisys/yappydraw'`).
  - `yappy.d.ts` types every named export. `Yappy` is typed loosely (`Record<string, any>`) because
    the full API is too wide to declare by hand.
  - It is also served by jsDelivr's npm mirror: `https://cdn.jsdelivr.net/npm/@algorisys/yappydraw@0.8.253/yappy.js`.
- **Help → Embedding** and the README show the npm install next to the CDN import.

## Fixes
- None.

## Internal / tests / docs
- **`scripts/publish-npm.sh`** (`npm run publish:npm`).
  - It does not rebuild. It shallow-clones the OSS tag `v<version>` and packages its `cdn/`, so npm
    and the GitHub CDN hold identical files.
  - Before publishing, it runs `verify-sdk.mjs` on the staged package and checks that the bundle
    contains its version string.
  - It refuses a version already on npm.
  - Dry run by default; publish with `--publish`.
  - The npm account uses 2FA, so publishing needs a one-time code: npm prompts in a terminal, or
    pass `NPM_OTP`.
- **"Ship it"** step 8 in `CLAUDE.md` now runs the npm publish after the OSS push.
- **Not yet tested:** consuming the package through a bundler (Vite, webpack). The core loads its
  lazy features from `chunks/`, relative to `yappy.js`; only a plain browser import has been
  verified.
