# v0.8.237 — One contribution, any amount

**Date:** 2026-09-07

`/founders/` becomes a contribute page: one payment, an amount the payer chooses, and two
published thresholds instead of a cohort. Nothing had been sold under any earlier wording,
which is the only moment an offer can be rewritten with nobody affected.

## Highlights

- **One contribution, from ₹100 upwards.** ₹1,000 or more earns a permanent credit in the
  app's supporters list; ₹2,499 or more makes you a founding member. No cap, no count,
  no deadline.
- **The scarcity apparatus is gone for the second and last time.** v0.8.232 hid a
  "1,000 of 1,000 places remaining" bar behind a flag. Its replacement — seasons, a window
  opening and closing on published dates — was drafted and cut before shipping, for the
  reason its own code admitted: this page is prerendered, so a window would appear to close
  only on the next deploy. That is the counter's flaw wearing a date.
- **Prices are quoted in rupees.** International cards are enabled, but the charge is INR and
  the payer's bank converts, so dollar figures are marked "about $29" rather than stated as a
  price we do not take.

## Features

- `frontend/src/data/founders.ts` replaces the cohort model with `CONTRIBUTION`: a floor
  (`minInr`/`minUsd`) and ascending `tiers`, each written as what it *adds*. `benefitsUpTo()`
  flattens them for display, so the page renders the whole of what a payer gets while the data
  stays written the way tier decisions are actually made.
- **Two benefits added to founding membership**, both recorded with what they cost to honour:
  source access to the collaboration server once it exists, and packaged desktop builds for
  macOS, Windows and Linux.
- The Support dialog now offers **one** way to give. `buildSupportLinks()` shows the direct
  Razorpay link only as a fallback, when no contribute page is configured — otherwise it sends
  people to `/founders/`, which is the only page that says what an amount reaches.

## Fixes

- **The refund and delivery policies described a different offer than the page selling it.**
  Both still said "a fixed payment" for a benefits list (founder badge, early access, roadmap
  vote) that no longer existed. Refund terms turn on "something is promised in return", so the
  page taking the money and the pages stating the terms have to list the same things.
- The `/founders/` sitemap `lastmod` was a hand-kept date in the data file. It now derives from
  the file's own last modification, so it cannot be right only by accident.

## Internal / tests / docs

- `docs/collaboration-plan.md`: **D1 revised, D3 reversed.** The free year of hosted
  collaboration was sized against a 1,000-person cap; removing the cap removed that arithmetic,
  so it becomes a permanent discount. D3 rejected source access as a benefit and now grants it,
  framed as access rather than exclusivity, with its four costs recorded — an access list, its
  irrevocability, the terms the grant needs, and its total dependence on D2 holding. D2 (the
  server imports nothing from `frontend/src`, or §13 pushes its source to everyone) is unchanged
  but is now what this benefit rests on.
- **Standing test for any new benefit:** it must cost the same whether fifty people join or five
  thousand. A per-user monthly bill fails it; a discount, a build, a channel invite pass.
- `docs/learnings.md`: *"A deadline a static site cannot enforce is the same lie as a counter it
  cannot verify"* — the general form being that a static site can only publish facts about
  itself, and the more carefully an unverifiable claim is built the longer it takes anyone to
  notice it has gone stale.
- `buildSupportLinks()` extracted as a pure function with 5 new tests covering the fallback rule,
  the at-most-one-primary invariant, and an unsafe checkout URL dropping to the fallback rather
  than linking a page that cannot take payment.
- `.env.example`: `VITE_SUPPORT_FOUNDERS_URL` keeps its name (so no deployment needs
  reconfiguring) but now documents a *Customers Decide Amount* Payment Page with a minimum
  matching `CONTRIBUTION.minInr`, and custom fields for a credit name and a contact handle —
  the CSV export being the only record of who a founding member is.

## Breaking changes / migration

- **The Razorpay Payment Page must be reconfigured**, or the site and the checkout disagree.
  Required: *Customers Decide Amount*, minimum ₹100, title and description matching the new
  offer, and input fields for a preferred credit name and a contact handle. The amount, minimum,
  expiry and custom fields were done for this release; **the page title and description were
  still the previous offer's copy at the time of shipping.**
- `FOUNDERS`, `FOUNDER_BENEFITS`, `SUPPORTER_BENEFITS`, `foundersRemaining()`,
  `foundersSoldOut()`, `foundersAsOfLabel()` and `dateLabel()` are removed from
  `data/founders.ts`. Only `prerender/render.ts` imported them; there is no public API here.
- No dollar payment route exists as a separate price. International cards are enabled and are
  charged in INR.
