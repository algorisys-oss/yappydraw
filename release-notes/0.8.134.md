# 0.8.134 — Whole-app contrast audit (2026-07-21)

## Highlights
- Small text across the whole app now meets **WCAG AA** in light, dark *and* focus themes.
  **635 failing instances across 11 distinct selectors** — now zero.

## Fixes
- Bug #192: **faint text throughout the UI failed AA contrast.** Found by sweeping every element
  that owns visible text in three themes across nine surfaces, compositing each against its real
  backdrop (translucent layers and inherited opacity included).

  | Element | Was | Now |
  |---|---|---|
  | `.hotkey-badge` (every toolbar button, 8px) | 1.83 | 4.83 / 6.57 |
  | `.command-palette-item-shortcut` | 1.47 | pass |
  | `.menu-item .shortcut` | 2.33 | pass |
  | `.group-chevron` | 2.33 | pass |
  | `.status-heart` | 2.50 | pass |
  | status-bar links (Privacy / Terms) | 2.76 | pass |
  | `.status-attribution` | 2.76 | pass |
  | version button | 3.00 | pass |
  | `.status-hint` | 3.28 | pass |
  | `.text-logo-draw` ("Draw" wordmark) | 3.84 | pass |
  | `.mode-badge` | 4.34 | pass |

  **Nine of the eleven were caused by `opacity`** — the same anti-pattern behind the 0.8.133
  button-hover bug. Fading text composites it toward whatever sits behind, so an already-muted
  colour loses the contrast it was designed to have. In every case `--text-secondary` at full
  strength (4.83 light / 6.57 dark) was more legible than the same token faded, so the fix was
  usually to delete the `opacity` rather than change any colour.

  The remaining two were colour choices that no single value could satisfy across themes, so
  they became per-theme tokens: `--link-color` / `--link-color-hover` (the global `#646cff`
  measured 4.07–4.09:1 in *every* theme), `--logo-accent`, and `--danger-text` (`--danger-color`
  is fine as a fill or icon but only 3.8:1 as a label on white).

  Two chips in the command palette became outlined instead of filled: a wash over the row's
  accent lightened them enough to put their own labels below AA, and no non-zero alpha cleared
  it in light mode.

## Internal / tests / docs
- `tests/contrast.spec.ts` gains a whole-app sweep per theme (light, dark, focus) that fails
  with a readable list of every offending element, ratio, colour pair and opacity.
- The sweep asserts the page actually rendered (>200 elements) before auditing. This mattered:
  an early run reported a clean pass that was really Vite's cold start serving a blank page —
  indistinguishable from success without the guard.
- **Changes are strictly visual.** Every modified line is a colour, an opacity, or a comment;
  the single `.tsx` edit removes an `opacity` key from an inline style and touches nothing else.
- The 6 pre-existing failures in `arcade-visual`, `eyedropper`, `graphic-styles`,
  `productivity-features` and `toolbar-pos` were confirmed identical on the committed baseline
  by stashing this work and re-running — they are not caused by these changes and remain
  outstanding.

## Breaking changes / migration
- None. No layout, spacing or behaviour changed.
