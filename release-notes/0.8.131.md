# 0.8.131 — Regression suite for video & GIF capture (2026-07-21)

Test-only release. No user-facing changes.

## Internal / tests / docs
- New `tests/recording-capture.spec.ts` (8 tests) covering the capture features shipped in
  0.8.129–0.8.130, which had no committed coverage at all — every check to date was a scratch
  spec that was deleted after use.
- The GIF tests assert the **downloaded bytes**, not just UI state: `GIF89a` header, sane
  dimensions within the 960px cap, and the NETSCAPE application extension that makes a GIF loop
  forever. A GIF that plays once and freezes on its last frame is useless in a README and looks
  identical from the UI side.
- Coverage: start/stop capture on a paged document; the same on an infinite canvas (where live
  capture is the only route to a GIF); the scripted fixed-length path; the MP4 record toggle
  round-trip; and the three fixed bugs — #187 (Ctrl+Shift+E must not strand the Export dialog),
  #188 (both presentation toolbars carry the capture buttons), #189 (a failed capture must clear
  the busy flag rather than disabling the feature until reload).
- **Each regression test was verified to fail against the bug it guards** by temporarily
  reintroducing the defect. That check earned its keep: the first version of the #188 test passed
  against the bug, because reloading the page restores the last auto-saved document — so the
  "infinite canvas" half was inspecting the paged toolbar twice. It now sets the document type
  explicitly and asserts which toolbar is on screen (via the slide counter) before asserting
  about its buttons.
- Run with `npx playwright test tests/recording-capture.spec.ts`; the config starts its own Vite
  server. Stable across three consecutive full runs.

## Breaking changes / migration
- None.
