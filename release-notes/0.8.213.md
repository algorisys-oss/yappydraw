# 0.8.213 — the translation pipeline's missing first step (2026-08-21)

## Highlights
- **`parts()`** — the interpolation primitive Phase 3 was blocked on. Without it the first
  sentence containing an inline link forces the translator to work in fragments.
- **`scripts/i18n-translate.mjs`** — step 1 of the plan's translation pipeline (§5), which had
  never been built. Phase 3 is ~681 keys per locale; that is not a by-hand job.

## Features
- **`parts(template)`** in `frontend/src/i18n/format.ts` splits a message into literal chunks
  and token markers, so a token can render as an *element* — a link, a `<strong>` — instead of
  text. `resolveTemplate` interpolates strings only, and the tempting workaround (three keys
  concatenated around the element) hands translators fragments and freezes English word order:
  "See our {{ policy }} for details" puts the link late in English and mid-clause in German.
  Ported from yappykit with one deliberate change — the token syntax is `{{ name }}`, not
  yappykit's `{name}`, because that is what `resolveTemplate` and `plural()` already use here.
  A verbatim port would have compiled and silently disagreed with `t()` about what a token is.
- **`npm run i18n:translate <locale>`** reads `en.ts`, sends the still-missing keys to
  `claude-opus-5` in batches, and writes a flat `temp/i18n/<locale>.json` table that
  `i18n-scaffold.mjs` turns into typed source. The two stay separate on purpose: a human
  reviewer (§5 step 2) edits a JSON table rather than a 900-line `.ts`, and re-scaffolding never
  re-spends money.
  - **Resumable**, which at 681 keys is a requirement rather than a nicety — the table is saved
    after every batch and a key already in it is never re-sent. A run that dies at key 400
    resumes at 400.
  - `--dry-run` prints the exact prompt and batching without calling the API. `--only <ns>`,
    `--limit n`, `--batch n`, `--effort <level>` scope a run for costing it first.
  - The do-not-translate glossary (§3.3 — shortcut letters, product and standard names, YSL
    keywords) sits in a cached system prompt, so it is not re-billed across ~17 batches.
  - Handles `stop_reason: "refusal"` and per-batch failures by leaving those keys out of the
    table, so the next run picks them up rather than writing a gap.

## Fixes
- The English parser initially read only single-quoted literals and silently dropped
  `statusBar.whatsNew`, which is double-quoted because it contains an apostrophe — 680 keys
  found where the file has 681. It now reads both quote styles and *reports* anything it still
  cannot parse rather than skipping it quietly.
- The prompt said "translate into de". It now says "German (Deutsch)", read from
  `SUPPORTED_LOCALES` rather than a second hardcoded list that could drift from the picker's.

## Internal / tests / docs
- 10 new tests for `parts()`, including one pinning that single-brace `{token}` is deliberately
  *not* recognised — the exact regression a verbatim port would have introduced.
- Verified the translate → scaffold handoff end to end with a scratch locale: both parsers agree
  on 681 keys, and the double-quoted key round-trips correctly.
- `@anthropic-ai/sdk` added as a **devDependency** — it is build/tooling only and never ships to
  users. `scripts/` is excluded from the OSS publish by `.ossignore`, so this tool stays internal.
- Plan §5 updated to record what is now built, and to note that step 3 (`i18n-check.mjs`) is
  largely superseded: `en.ts` defines the `Dictionary` type, so a locale missing or inventing a
  key is a **compile error** — stronger than a script, and unskippable.
- Suite: 1085 tests across 74 files.

## Known limitation
**The API request path has not been executed.** There are no Anthropic credentials in the
authoring environment, so everything except the live call is verified — parsing, batching,
resumability, the refusal branch, the scaffold handoff, and the full dry-run output. Do a
`--limit 5` run before committing to a full locale.

## Breaking changes / migration
None.
