# 0.8.170 — Bullet lists survive the text editor; align icons match their axis (2026-08-02)

## Highlights
- Bulleted and numbered lists now render on the canvas the way they looked in the editor —
  nested items are no longer dropped, items no longer run together, and a wrapped item no
  longer grows a second bullet.
- The Properties panel's alignment buttons carry the icon for the axis they actually align.

## Features
- None (both changes are fixes to shipped behaviour).

## Fixes
- **Nested list items vanished.** `htmlToSpans` walked only the `<li>` *children* of a
  `<ul>`/`<ol>`, but browsers emit a nested list as a **sibling** of the `<li>` it belongs to —
  that is what `execCommand('indent')` produces and what pasted outlines contain. Every nested
  item was dropped: the editor showed four bullets, the canvas three. The walker now iterates
  children in document order and handles both nesting shapes.
- **Items merged onto one line.** A line break was only emitted when an item's next *element*
  sibling was an `<li>`. After a nested list, between two adjacent lists, or before text
  following a list, no break was emitted and `mergeAdjacentSpans` fused the texts — "Three" +
  "Plain tail" rendered as a single bullet. Breaks are now emitted before every item and after
  the list block.
- **Wrong indent after a break, and duplicate bullets on wrapped items.** `layoutRichText` only
  recomputed the list indent when the line started at x=0, which after a break never happened,
  so a deeper level kept its parent's indent and text *after* a list stayed in the list's text
  column. Both canvas renderers also drew a marker for the first list span on every line, so a
  word-wrapped item drew a second bullet on its continuation line. The indent is now recomputed
  at every line start, and the layout tags the item's first segment (`RichTextSegment.listMarker`)
  as the only one that gets a marker.
- **Editing a list repeatedly grew blank lines.** `spansToHtml` re-emitted the newline that butts
  against a `<ul>`/`<ol>` block as a `<br>`, so edit → commit → re-edit added a line each cycle.
  List HTML generation is now stack-based (matching the browsers' own nesting shape) and drops
  that newline, making the round-trip a fixed point.
- **Alignment looked swapped.** `calculateAlignment` was always correct; the Properties panel
  picked its icons by name. Lucide names an align icon after the axis of its *guide line*, so
  `AlignStartVertical` (a vertical rule at the left) means "align left", not "align top" — the
  panel's second row read as left/centre/right while doing top/middle/bottom, and the first row
  used text-align icons. Horizontal alignment now uses the `*-Vertical` set and vertical
  alignment the `*-Horizontal` set, matching the dock Align panel. Behaviour and tooltips are
  unchanged.

## Internal / tests / docs
- New `tests/rich-text-lists.spec.ts` — editor round-trip through a real double-click and paste,
  the left-margin return after a list, and one bullet per wrapped item (pixel-sampled). All
  three fail against the pre-fix code.
- Help doc corrected: Tab does **not** indent inside the rich-text editor (it commits and leaves
  the box), so nested levels come from pasted content; SVG/PNG export keeps list indentation but
  does not draw the markers. Both are now stated as known limitations.
- `docs/bugs/bug-fixes.md` entries 244/245; four new entries in `docs/learnings.md`.

## Known limitations
- SVG/PNG export lays out list text with the indent but does not draw bullet/number markers
  (`utils/export.ts`) — pre-existing, unchanged by this release.
- There is no indent shortcut inside the rich-text editor.

## Breaking changes / migration
- None. `RichTextSegment` gained an optional `listMarker` field; no stored document format,
  `window.Yappy` method or element attribute changed.
