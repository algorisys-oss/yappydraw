# 0.8.231 — exports honour the canvas background (2026-09-03)

## Fixes

- **A black canvas exported as blank white paper** (#340). Set the canvas background to
  black and the text to white, and every download came back white: the artwork was in the
  file and none of it was visible. Every non-slide exporter hardcoded a white page fill and
  never read `canvasBackgroundColor`, which is the setting that drives what you see on
  screen.

  Six paths were affected: PNG, JPG, per-page PNG, copy-as-image, and the single-page
  branches of PDF and PPTX. Slides were never affected, because they already read their own
  background. All six now share one helper, which defaults to white, so nothing changes for
  anyone who never set a background colour.

- **A transparent PDF exported as a solid black page** (#341). Found while investigating the
  above and a separate fault: PDF pages were encoded as JPEG, which has no alpha channel, so
  with the background switched off every transparent pixel became black. PDF now uses PNG
  when the background is off and keeps JPEG when it is on.

## Known trade-off

A PDF exported with the background **off** is now considerably larger, because PNG is
lossless: a small test drawing went from 40 KB to 4.2 MB. This was chosen deliberately, on
the grounds that a black page is unusable while a large file is merely large. If the size
becomes a problem the alternative is to treat a PDF page as white paper and keep JPEG
throughout, which is a one-line change.

## Internal

Colour fidelity was measured rather than assumed after both fixes. Sampled against the source
hex values, the PNG path reproduces colours exactly and the JPEG path is off by at most 1 in
a single channel. Dark theme does not leak into exports.
