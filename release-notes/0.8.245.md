# 0.8.245 — Updates arrive on their own (2026-09-12)

## Highlights
- **Yappy now keeps itself up to date.** It checks for new releases, tells you when one is
  ready, and installs it while you are away from the tab. No refresh, no clearing anything,
  no knowing what a service worker is.

## Features
- **Update checking.** Yappy asks for a new build about once an hour, whenever you return to
  the tab, and whenever your connection comes back. Until now it asked exactly once, when the
  page first loaded, and never again — so a tab left open for days never found out a release
  had happened.
- **A badge that stays put.** When a build is waiting, the version number in the status bar
  carries an **amber** dot until you take it. The existing **blue** dot still means "release
  notes you haven't read". Two dots, two jobs — documented in Help → Workspace.
- **Automatic install while you're away.** Once the tab has been *continuously* hidden for
  three minutes, the waiting build is applied and the page reloads in the background, so you
  come back already running it.
  - It never reloads while the tab is on screen. Reloading the page someone is drawing on is
    worse than running an old build, however stale.
  - The timer resets every time you come back, so flicking to another tab for a reference
    image never triggers it.
  - It never interrupts a recording.
  - Your drawing is saved first, so nothing in progress is lost.
- **One click if you'd rather not wait.** Click the version number while the amber dot shows
  and the update applies immediately.
- **API:** `window.Yappy.isUpdateWaiting()` and `window.Yappy.applyUpdate()`, for a kiosk or
  embedded host that would rather pick its own moment.

## Fixes
- **#362 — a tab left open never discovered a new release.** The site would serve the current
  build (provable with `curl`, on repeated fetches) while a browser that had used the app
  before kept running the previous one, indefinitely. A shipped fix read as "not shipped", a
  new API as "missing". The only cure was to unregister the service worker and clear caches
  by hand — fine for a developer, not something to ask of users.

  The cause was not the caching strategy but the absence of a clock: nothing ever *looked* for
  a new build after boot, so the cached copy served itself offline-first forever. Note this is
  the opposite case to the stale-build recovery already in the app — that one handles an old
  build that **breaks**, and it works. This was an old build that kept working perfectly, so
  there was no error to recover from and nothing ever fired.

## Internal / tests / docs
- `frontend/src/utils/pwa-update-policy.ts` — the auto-apply decision as a pure function with
  no imports, split out of `pwa.ts` specifically so it is testable: `pwa.ts` imports
  `virtual:pwa-register`, which exists only inside a Vite build. 5 unit tests cover never
  -while-visible, never-while-recording (checked before the grace period, so it cannot be
  outwaited), the quick-glance case, and the grace boundary.
- `applyPwaUpdate` calls `forceAutoSave()` before reloading. The autosave is debounced and
  applying an update reloads the page, so without this an update taken seconds after an edit
  would drop it — likeliest of all in the auto-apply path, which fires exactly when someone
  has just walked away from a fresh change.
- The service worker stays on `registerType: 'prompt'`. `autoUpdate` would reach stale clients
  sooner but reintroduces the precache-eviction race that produced the "blank on first load"
  bug — the wrong trade for a drawing app. Hidden-tab auto-apply gets the same outcome without
  ever interrupting anyone.
- Help → Workspace gained a "Getting the latest version" section; the new status-bar string is
  translated across all five locales.

## Breaking changes / migration
None — but one limit worth stating plainly: **an update mechanism can only be fixed forward.**
A client still on a pre-0.8.245 build has none of this code, so it will not start polling; it
will pick up a new build when its tabs close, or when the existing stale-build recovery fires.
This release is the last one with that property rather than a retroactive cure for the ones
before it.
