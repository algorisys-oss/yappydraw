# 0.8.234 — Dev Mode: unfinished features stop charging everyone rent (2026-09-04)

## Highlights

- **Dev Mode** (*Settings ▸ General ▸ Dev Mode*, **off by default**) hides features that are
  still being built. The Arcade game builder is the first thing behind it, and future
  work-in-progress features will hang off the same switch.
- Only the **entry points** are hidden. Documents that already contain a game keep their
  behaviors, script and HTML export, and the `Yappy.*` game APIs keep working with Dev Mode
  off. Nothing in a saved file breaks either way.
- It is a **per-browser preference**, and a document cannot turn it on — opening a `.yappy`
  file someone sent you can never unlock unfinished UI on your machine.

## Features

- `GlobalSettings.devMode` (default `false`), persisted to `localStorage` under `devMode`,
  alongside `teachingMode` / `showDimensions` / `defaultTool` as an app-level preference.
- `isDevMode()` in `store/app-store.ts` — **the** gate for work-in-progress UI. New WIP
  surfaces read this rather than the setting, so `grep isDevMode` lists the app's entire
  hidden surface in one command, and one place decides what "on" means.
- Settings ▸ General ▸ **Dev Mode**, last row in the category, with a hint line that appears
  while it is on saying where the revealed features went.
- API: `Yappy.setDevMode(on)`, `Yappy.getDevMode()`, `Yappy.toggleDevMode()`.
- Gated today: the whole **Game** menu group (New Game, My Games, Build, Node Graph,
  Blueprint, Play, Code) with its separator, **Edit Behaviors (Game)…** in the right-click
  menu, and the `games` bullet on the welcome screen's capability list.
- Strings translated into all five shipped locales (en / es / fr / de / ja) — the locale
  dictionaries are typed `Dictionary`, so English-only keys would not compile.

## Fixes

- **#343** — the Arcade help doc's opening step named **Menu → Game Builder** and
  **Edit Behaviors**; the menu has said **Menu → Game → Build** and
  **Edit Behaviors (Game)…** since the game tools were collapsed into a group. A stale path
  in a doc's *first* step is invisible to everyone except beginners, who cannot tell a wrong
  instruction from a broken feature.

## Internal / tests / docs

- `frontend/src/store/dev-mode.test.ts` — 6 tests: default off, round-trip, localStorage
  persistence, `'0'`/`'1'` parsing, isolation from unrelated settings updates, and the one
  that matters — **a loaded document cannot set it.** `loadDocument` spreads the document's
  `globalSettings` over the store, so the override in it is the only thing standing between a
  developer's saved file and someone else's menu. Commenting that line out is the only change
  to this feature that fails a test, which was verified rather than assumed.
- Help docs: a **Dev Mode** section in `features/workspace.md` (next to Teaching mode, its
  sibling app-level preference), and a note at the top of `features/arcade.md`.
- `docs/learnings.md` — why the gate is a named function rather than a field read, why Dev
  Mode deliberately does *not* guard at the choke points the way Teaching mode does, and why
  the menu separator is inside the `<Show>`.

## Breaking changes / migration

None. Dev Mode defaults to **off**, so the Game group is no longer in the menu for anyone who
has not asked for it — turn it on in *Settings ▸ General ▸ Dev Mode* to get it back. Existing
game documents, exports and scripts are unaffected.
