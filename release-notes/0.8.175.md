# 0.8.175 — Designer review: type, cusps, cutting and locked objects (2026-08-05)

Five issues from a hands-on logo and poster session, each fixed at its root rather than
patched at the surface. Four of them turned out to be the visible end of something structural,
and fixing them properly turned up six more bugs nobody had reported.

## Highlights

- **Font Family and Font Style are two dropdowns**, as in Illustrator — and `fontWeight` is a
  real 100–900 axis, so Light, Medium, SemiBold and Black finally exist.
- **Alt-drag breaks a Bézier handle pair** into a cusp, while drawing with the Pen and while
  editing an existing anchor.
- **Scissors cuts exactly where you click**, including mid-curve, instead of jumping to the
  nearest anchor.
- **Locked objects can be unlocked again** — previously a one-way door.
- **Create Outlines uses the font you actually chose**, instead of silently substituting
  sans-serif for anything not bundled.

## Features

### Font Family / Font Style split, on a real weight axis

Font files are named `Family-Weight`, so installing a family used to fill the picker with
entries that looked like unrelated typefaces: `Montserrat-Light`, `Montserrat-Regular`,
`Montserrat-Bold`, `Montserrat-SemiBoldItalic`. They are now grouped — **Font** lists each
family once, **Style** lists that family's weights and italics.

- `fontWeight` is a number on the CSS 100–900 axis (`300` Light, `600` SemiBold, `900` Black).
  `fontStyle` is `'normal' | 'italic'`.
- Both legacy encodings (`true`, `'bold'`) are still read correctly, so **saved documents need
  no migration and render identically**.
- Switching family keeps the style you were in wherever the new family has it — Montserrat
  SemiBold → a family whose heaviest is Bold lands on Bold, not Regular.
- The Style row only appears when the family has more than one style. Built-ins keep their
  curated label and offer only the styles they can synthesise (`fontCapabilities`).
- Bold/Italic buttons still work, as a two-state view of the axis (Bold lights for ≥ 600).
- New `utils/font-variants.ts`: `normalizeFontWeight`, `normalizeFontStyle`, `fontShorthand`,
  `parseFontVariant`, `groupFontFamilies`, `pickVariant`, `resolveActiveVariant`.
- API: `fontWeight` documented on `ElementOptions` as the numeric axis.

### Alt breaks a Bézier handle pair

A smooth anchor keeps its handles in line; hold <kbd>Alt</kbd> while dragging one to break the
pairing and give the anchor a cusp — one side curved, the other running straight in.

- Works while **drawing** with the Pen (hold Alt partway through the handle drag) and while
  **editing** with the Selection or Node tool.
- The break is permanent, not just for that drag: the anchor becomes a corner, so releasing
  Alt does not snap the two sides back into line. Alt-click the anchor to re-pair it.
- Alt on an *anchor* (convert smooth ↔ corner) and Alt on a *segment* (insert anchor) are
  unchanged — this claims Alt only over the in/out handles themselves.
- New `utils/anchor-handle.ts` is the single rule all three tools now share.

### Unlocking without selecting

Locking was a one-way door: hit testing skips locked elements, so they can never enter the
selection, and every unlock path read the selection.

- **Right-click the object → `Unlock "…"`**. The context menu works from a world point rather
  than from the selection, so it reaches something nothing can select. Overlapping locked
  objects are listed individually, topmost first.
- **Unlock All** — <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>2</kbd> (Illustrator's Object ▸ Unlock
  All), also in the right-click menu with a live count, and in the command palette.
- Unlocking selects what it freed.
- API: `Yappy.setLocked(ids, bool)`, `Yappy.getLocked()`, `Yappy.unlockAll()`.

## Fixes

### Scissors cut at the nearest anchor, not where you clicked

A circle drawn as the usual four-anchor Bézier could only be cut in four places; clicking its
45° point cut **76 units away** at the nearest quadrant. The click is now projected onto the
outline and that segment subdivided with de Casteljau — exact, so the halves reproduce the
original curve and the shape does not shift when cut. It also read only `pathAnchors` (so
compound paths were invisible to it) and ignored rotation.

### Knife mangled curves and filled in holes

- `PathUtils.parsePath` emitted no command for `M`, so contour boundaries were absent from its
  output entirely and the flattener walked multi-contour paths as one ring — knifing outlined
  text or a donut produced nonsense. Commands now carry a `subpath` index.
- Flattening used a fixed sample *count* (96 across the whole path) rather than a tolerance, so
  detailed paths came back faceted. Now adaptive subdivision against a flatness tolerance, with
  the ellipse segment count derived from the same number instead of a flat 64-gon (which is 1.2
  units off on a 1000-unit circle).
- `elementToMultiPolygon` ended in `rings.map(r => [r])` — every ring its own *solid* polygon —
  so any shape with a counter lost it through any polygon operation.
- `splitPathAt` minted piece ids without a batch set, so both halves of every two-piece split
  were getting the **same id**.

### Create Outlines produced the right letters in the wrong typeface

`text-to-outlines.ts` ended with `FONT_FILES[key] ?? FONT_FILES['sans-serif']`, so any font the
user had added was outlined in sans-serif — a correct-looking path of the wrong design, with no
error and no log. Custom typography is exactly the case where you are never on a bundled font.

- Fonts added **from a file** (.ttf/.otf/.woff) now outline for real, from the binary already
  held in the font's `dataUrl`.
- Fonts added **by name from Google Fonts** cannot be outlined (WOFF2 is Brotli-compressed and
  unparseable client-side) and now say so, naming the fix, instead of substituting silently.
  Unknown font keys and uploaded WOFF2 files error the same way.
- The source text is left untouched when outlining fails.

### Bold had never worked on connector or BPMN labels

Found while centralising the weight handling. `connector-renderer`, `bpmn-renderer` and the
in-place text-editing overlay built their font as
`${el.fontWeight || 'normal'} ${size}px ${family}` — which with the old boolean produced
`"true 16px Inter"`, not a valid CSS font string, so the canvas discarded the whole assignment
and kept the previous font. `text-renderer` tested `=== true || === 'bold'`, so every weight
except exactly 700 would have rendered Regular. SVG export collapsed weight to bold/normal, so
a Light or SemiBold wordmark exported as Regular.

### Handle mirroring was inconsistent between tools

The Selection tool forced the opposite handle to the *dragged* handle's length, so adjusting one
side of an anchor quietly retensioned the segment on the other side. A zero-length drag divided
through a `|| 1` fallback rather than bailing, snapping the far handle onto a unit vector. The
Node tool's existing Alt-break left the anchor `smooth`, so the next unmodified drag undid the
cusp.

- 68 new unit tests (`anchor-handle`, `path-cut`, `path-boolean-flatten`, `font-variants`);

## Breaking changes / migration

**None.** `fontWeight`/`fontStyle` accept every encoding they ever have — `true`, `'bold'`,
`'italic'`, numbers and numeric strings — and are read through `normalizeFontWeight` /
`normalizeFontStyle` everywhere, so existing documents, templates and API calls are unaffected.
New writes use the numeric axis.

One behaviour change worth noting: breaking a handle pair with Alt now demotes the anchor from
`smooth` to `corner`. This is deliberate (it is what makes the break survive letting go of Alt)
and changes no geometry — rendering reads the handles, not `kind`.
