# 0.8.265 — Frame-exact rendering, and a render CLI (2026-09-27)

Animations can now be rendered one frame at a time, at an exact time, instead of recorded
in real time. The same scene always gives the same frames, so a loaded laptop or a headless
CI browser produces the same file as a fast machine. `npm run render` uses this to turn a
saved document or a scene script into a PNG, GIF, MP4, WebM or PNG sequence.

## Highlights
- **`Yappy.renderFrame(t)`** returns the frame at `t` seconds as a PNG (or JPEG) data URL.
  Frames can be rendered in any order.
- **`npm run render -- <input> -o <out>`**: headless rendering of a `.yappy` document or a
  `.js` scene script. The output's extension picks the format.

## Features
- `Yappy.getAnimationDuration()`: the in/out range of an animation document, otherwise the
  last composition keyframe (what `Yappy.scene` writes). Returns 0 for untimed, looping motion.
- `Yappy.getFrameRegion({ seconds, padding, background })`: the active page in paged
  documents. On an infinite canvas it is the content plus padding, taken as the union over
  `seconds` of animation so that moving content stays in frame.
- `Yappy.renderGif(seconds, { fps, scale, region, background })`: a looping GIF as bytes,
  rendered frame by frame on GIF's 10 ms delay grid. Downloads nothing.
- CLI options: `--seconds`, `--fps`, `--at`, `--scale`, `--padding`,
  `--background <css|transparent>`, a repeatable `--eval`, and `--url` to reuse a running
  dev server. MP4/WebM need `ffmpeg` on PATH.

## Fixes

## Internal / tests / docs
- `recording-manager.ts`: frame posing is split out (`poseAt`) and shared by the drawing and
  the bounds. `makeRegionFrameRenderer` draws any world rectangle at an absolute export time.
  `makePageFrameRenderer` is now a thin wrapper over it, so the existing page video and GIF
  exports behave as before.
- `export.ts`: `elementsBounds` is exported.
- New spec `tests/render-frame.spec.ts`: deterministic frames regardless of render order,
  pixel position of a keyframed shape, the swept region, GIF header and loop block, and the
  empty document. The existing export specs pass unchanged.
- The OSS mirror now keeps `scripts/render.mjs` (`OSS_KEEP`), so `npm run render` works there.
- Help: new **Frame-exact rendering** section in the Animation doc.

## Breaking changes
