# 0.8.91 — Hatch-fill clip fix + text autosize / fixed-width (2026-07-13)

## Highlights
- **Zig-zag / hachure fills no longer bleed outside the shape** in sketch style — the
  intermittent overflow is gone.
- **Text tool now has two behaviours, like Excalidraw / tldraw:**
  - **Click** (no drag) → **autosize** text: the box grows as you type, Enter adds a new
    line, nothing wraps.
  - **Click-drag** → **fixed-width box**: text word-wraps within the width you dragged.

## Fixes
- **Sketch-mode hatch / zig-zag fill bled past the outline (#161).** In sketch style the
  hatch fill was drawn by RoughJS, whose unclipped, randomized hachure endpoints overshoot
  the shape edge — and the overshoot depends on the element's seed, so the same shape looked
  fine or bled inconsistently. Fix: route hatch fills through the clean, shape-**clipped**
  `applyHatchFill` in **both** render modes (previously architectural only); RoughJS still
  draws the sketchy outline stroke. Covers all five hatch styles at once — hachure,
  cross-hatch, zigzag, zigzag-line, dashed. `render-pipeline.ts`.

## Features
- **Text element autosize vs fixed-width box.** A click-placed text element is now
  `autoResize: true` (grows both width and height to the content, no wrapping); a
  drag-placed one is `autoResize: false` (fixed width from the drag, word-wraps). Behaviour
  is gated entirely on `autoResize`, so **every existing text element renders exactly as
  before** — the only change is that clicking the text tool now autosizes instead of
  dropping a 200 px fixed box. Scoped to the plain **text** tool; the rich-text tool keeps
  its fixed-width default.
  - Implemented across creation (`tool-handlers/minor-handlers.ts` `textOnUp`), rendering
    (`renderers/text-renderer.ts` — no-wrap branch), the live editing overlay
    (`text-editing-overlay.tsx` — grows width, `wrap="off"` / `white-space: pre`), and commit
    (`tool-handlers/text-editing-handler.ts` — width from `measureMaxLineWidth`, height from
    line count). All four stay in lock-step so the editor and canvas match while typing.

## Known limitations
- The autosize path is verified to **build**; live behaviour (typing, click vs drag, wrap)
  should be spot-checked in the app.
- Rich-text autosize width uses a plain-text metric (ignores per-span bold widening) — close
  but not pixel-exact for mixed-weight lines.

## Breaking changes / migration
- None. Existing text elements are unaffected (`autoResize` stays falsy).
