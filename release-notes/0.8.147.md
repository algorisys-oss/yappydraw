# 0.8.147 — The app can no longer hang on a loading screen (2026-07-28)

## Highlights
- Fixes the intermittent **"stuck loading"** report: three separate ways the editor could sit on a loading state forever, none of which had any recovery path.
- Whatever goes wrong at startup now ends in a **Reload button**, never an endlessly bouncing mascot.

## Fixes
- **The boot splash was only dismissed if the first render succeeded.** `index.tsx` faded the splash out on the line *after* `render(...)`, outside any guard — so any exception during the initial render skipped it and left the mascot on screen permanently. The dismissal now runs in a `finally`, and a render failure replaces the page with a short "failed to start / Reload" message instead of a silent hang.
- **A corrupt `localStorage` value crashed the first render.** Two component initializers used `JSON.parse(localStorage.getItem(k) || '[]')`, where the `|| '[]'` only guards a *missing* key, not a corrupt one — a truncated write (e.g. under quota pressure) or a value from an older build threw at component construction, which is what triggered the stuck splash in practice. Both now go through the new `utils/safe-storage` helpers, which fall back to the default and discard the bad key so it can't keep re-breaking every boot. This explains the *intermittency*: it only ever hit profiles whose stored value had gone bad.
- **A failed lazy-route chunk showed "Loading..." forever.** `#help`, `#examples` and `#/embed/` are `lazy()` behind `<Suspense>`, which has no notion of "this will never resolve" — so a chunk that 404s (the classic cached `index.html` pointing at pre-deploy hashes, with a service worker in play) hung indefinitely. They're now wrapped in an `ErrorBoundary` offering **Reload** and **Try again**.
- **A last-resort failsafe now lives in `index.html` itself**, outside the module graph: if the app hasn't mounted after 15 seconds the splash swaps its animated dots for "This is taking longer than it should" plus a Reload button. This is the only layer that survives a module-level throw or a missing entry chunk, where no application code runs at all. `index.tsx` clears the timer as part of dismissing the splash.

## Also fixed (found reviewing 0.8.146 before release)
- **Asset thumbnails are now bounded.** The capture renders at the artwork's natural size supersampled 2×, and thumbnails live in the library *index* — which every listing reads in full. Saving a large selection would have written a multi-megabyte preview and made listing progressively slower. Previews are now capped at 128px on the longest edge (matching how the drawings gallery bounds its own).
- **Saving a symbol instance now stores self-contained artwork.** A `symbolId` only resolves in the document that defines it, so an asset holding a raw instance would have inserted as a grey placeholder anywhere else. Instances are flattened into positioned copies on save (nested instances too, with a depth cap). The expansion logic is now shared with **Detach Instance** rather than duplicated, so the two can't drift.
- **Procedural texture tiles no longer show seams.** The tile side is snapped to a whole number of grain cells; previously the partial cell at the right/bottom edge didn't line up with the next repeat, leaving a faint grid visible even at overlay opacity. The same snap makes the grunge lattice period exact so its octaves wrap cleanly.

## Internal / tests / docs
- New `utils/safe-storage.ts` — `readJson` / `readJsonArray` / `writeJson`, tolerant of missing keys, corrupt values, and storage being unavailable entirely (private mode, blocked cookies).
- New `tests/boot-resilience.spec.ts` (6 tests) covering all four layers: a healthy boot dismisses the splash and never shows the stuck state; corrupt values in both keys boot cleanly with zero page errors and a usable canvas; the corrupt key is discarded rather than re-read; the failsafe is armed before any module runs; a blocked route chunk shows the recovery UI instead of bare "Loading..."; and a blocked *entry* chunk still surfaces the Reload button.
- `docs/learnings.md` and `docs/bugs/bug-fixes.md` (#210–#212) updated.
