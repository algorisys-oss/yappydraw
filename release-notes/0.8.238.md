# v0.8.238 — The deploy that never deployed (2026-09-07)

A build fix. v0.8.236 and v0.8.237 were published and never reached production;
this is the release that lets them.

## Highlights

- **`/learn/` articles are a build input, and the OSS publish was stripping them.** Every
  OSS-built deploy since v0.8.236 died in `npm run prerender`. The live site served
  v0.8.235 for a day while two releases sat published and unbuilt.

## Fixes

- `.ossignore` excluded `articles` outright, added the day before v0.8.236 under the
  comment *"authoring source, not consumed by the build"*. It is consumed: `readArticles()`
  in `prerender/render.ts` scans it to generate `/learn/`. It now excludes the single
  article marked `internal: true` (`articles/vibe-architecting-yappydraw`) instead of
  the parent directory.
- `readArticles()` turns a missing `articles/` into an error that names `.ossignore` as
  the likely cause, rather than a bare `ENOENT` naming a path. It deliberately does **not**
  skip and continue — that would produce a *successful* deploy with `/learn/` missing,
  404ing an indexed section of the site while the editor looked fine.

## Internal / tests / docs

- `docs/bugs/bug-fixes.md`: the full trace. Hostinger reported a failed build with no logs,
  which is bug #344's signature for an OOM kill — and the wrong answer here. A clean
  `git clone` + `npm ci` + `npm run build` of the OSS mirror reproduced it in three minutes
  with a plain `ENOENT` the host never surfaced. Peak RSS measured at 1.62 GB, where
  v0.8.235's heap cap left it, which disproved OOM rather than confirming it.
- `docs/learnings.md`: *"A known signature is a hypothesis, not a diagnosis."* #344
  established that an empty log means killed-not-failed; it does not follow that every
  silent host failure is the same kill. Reproduction beats recognition, and it is usually
  faster.

## Breaking changes / migration

- None. `articles/vibe-architecting-yappydraw` remains unpublished in the OSS mirror and
  unpublished on the site (`internal: true`).
