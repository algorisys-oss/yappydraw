# 0.8.174 — Exported SVG keeps the bullets (2026-08-03)

## Highlights
- A bulleted or numbered list exported to **SVG** now carries its markers. Previously the text
  came out correctly indented with nothing in the gutter, so the list read as oddly-indented
  prose. PNG/JPG/PDF were never affected — they render through the canvas.

## Features
- None (this is a fix to shipped behaviour).

## Fixes
- **SVG export dropped every list marker.** `exportToSvg` emits a `<tspan>` per laid-out segment
  but never looked at `RichTextSegment.listMarker`, the flag the layout engine sets on the first
  segment of each list item (added in 0.8.170 so a word-wrapped item doesn't grow a second
  bullet). The canvas renderers — `text-renderer.ts` and `render-pipeline.ts` — both drew the
  marker from that flag; the SVG path was the only one of the three that didn't, and it kept the
  20px gutter `layoutRichText` reserves for it, which is what made the output look wrong rather
  than merely plain. Both rich-text branches of the exporter (standalone text/richtext elements
  and rich container text) now emit a marker `<tspan>` via a shared `listMarkerTspan` helper,
  positioned at `xOffset + level * 20` and styled from the span's own colour/font/size/weight —
  the same arithmetic the two canvas renderers use, so an exported list lines up with the one on
  screen.

## Internal / tests
- `tests/rich-text-lists.spec.ts` gains **SVG export keeps the bullets and the numbers**: exports
  a mixed list (a wrapping top-level bullet, a nested bullet, two numbered items) and asserts one
  `•` per *item* rather than per rendered line, that ordered items keep their own index, and that
  each marker sits exactly one 20px indent step left of its text with the nested level one step
  further in. It fails on the pre-fix code (zero markers found).

## Notes
- Two other differences between the editor and the canvas are known and unchanged: the editor
  draws the browser's `disc` marker while the canvas draws a `•` in the element's own font (so it
  reads lighter in a hand-drawn font), and lists exist on rich-text elements only — text typed
  inside a shape is plain. The Design Studio help page now says so.
