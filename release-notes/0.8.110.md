# 0.8.110 — Connectors that space themselves out

**Date:** 2026-07-19

## Highlights

- Connectors meeting the same side of a shape now fan out into evenly spaced
  points instead of piling onto one anchor — and they're ordered so the lines
  don't cross.
- Two connectors between the same pair of shapes (or one in each direction) get
  their own lanes, so both arrowheads stay visible.
- Elbow connectors steer around each other instead of running along the top of
  another connector.

## Features

- **Connector port allocation.** When two or more connector endpoints land on the
  same side of a shape, they are distributed into evenly spaced "ports" along that
  edge. The order follows the neighbouring shapes' positions, so a fan-in doesn't
  produce crossed lines. Ports snap to the shape's real outline, so circles,
  diamonds and other non-rectangular shapes get endpoints on the boundary rather
  than on the bounding box.
- **Move-aware endpoints.** An endpoint sits on the side that *faces* its
  neighbour. Drag a shape across to the other side and the endpoint follows,
  instead of staying on a stale edge.
- **Bundle separation.** Duplicate connectors between the same pair of shapes, and
  bidirectional pairs (A→B plus B→A), are separated into distinct lanes. This
  replaces the older pair-only spread with one mechanism that also covers hub
  fan-in.
- **Elbow connectors avoid each other.** The orthogonal router now treats other
  connectors' bodies as soft obstacles and prefers a neighbouring lane over
  running collinearly along an existing connector. Plain crossings are left alone
  — crossing is normal in diagrams; overlapping *along* each other is not.

All of this is automatic: there is no new setting, and a lone connector behaves
exactly as before. Spacing is applied while drawing and dragging and is **not**
persisted into the document — saved anchor points are untouched.

## Fixes

- **Connector endpoints no longer collide after a drag.** Port assignment depends
  on every endpoint sharing a node side, so moving or adding a connector now
  re-lays-out the whole group. Previously only the moved element's own connectors
  were refreshed, and peers could keep positions computed for a stale group —
  putting two connectors on the same point.
- **Routes no longer drift after unrelated edits.** Connector refresh is now
  de-duplicated and processed in a deterministic order, so a route is a function
  of the current shape positions rather than of edit history. Moving a shape away
  and back now restores identical geometry.
- **Busy diagrams keep proper obstacle routing.** The set of connector obstacles
  is bounded and spatially filtered, so a large document can't inflate the router's
  search grid to the point where it gives up and falls back to a naive elbow that
  cuts through shapes.
- **AssemblyScript compiles under Bun.** `bun run dev` failed with
  `/bin/sh: 1: npx: not found` because the Vite plugin shelled out to `npx asc`.
  It now runs the local compiler with whatever runtime is already running Vite.
- **WASM memory pool.** Buffers are allocated before any typed-array views are
  created. Growing the heap for a later buffer used to detach an earlier view,
  which could silently break WASM viewport culling and batch shape paths (opt-in
  paths only — WASM features are off by default).

## Internal / test changes

- New `utils/connector-routing.ts` (port allocation) and
  `utils/connector-obstacles.ts` (connector bodies as router obstacles). The
  obstacle helper lives in its own module so the JS router and the WASM bridge
  share one source of truth without an import cycle.
- WASM parity: the AssemblyScript router takes the connector-segment buffer and
  applies the same penalty as the JS path, with the overlap maths kept identical.
- Removed the ad-hoc sibling-spread (`getOverlappingSiblingIndex` /
  `computeSpreadOffset`) — port allocation subsumes it.
- 24 new unit tests covering port distribution, crossing minimisation, re-facing
  after a move, outline snapping, bundle/bidirectional separation, degenerate and
  non-finite geometry, rotated-node ordering, overlap detection, priority
  filtering, end-to-end avoidance and idempotency.
- Verified in the running app with a Playwright harness: routes stable at rest,
  identical after move-and-return, and endpoints distinct on fan-in.
- Background: `docs/routing-channel-plan.md` and
  `docs/microsoft-comic-chat-algorithm.md` (the SIGGRAPH '96 "routing channel"
  idea this borrows from).

## Breaking changes / migration

None. No document format or API change; existing drawings open unchanged.
