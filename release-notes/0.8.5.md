# 0.8.5 — Game stage, cleaner landing, Blueprint fix (2026-07-07)

## Highlights
- **Games get a real stage.** A game is now a fixed-size **page** you play inside,
  not the whole infinite canvas — so edit, play, export and the launcher all agree
  on the play area.
- **A calmer landing page** — one bold invitation over a quiet feature list.

## Features
- **Game stage:** **New Game** now creates a paged game with a chosen **stage size**
  — Landscape (800×600), Wide 16:9 (1280×720), Portrait (540×960) or Square (720×720).
  The page is the play window: `game.width/height/x/y` bind to it, Play fits it to the
  screen, and HTML export + the My Games launcher are deterministic.
- **Landing page redesign:** the hand-drawn pointer arrows and UI callouts are gone.
  In their place: a bold **"Click anywhere to sketch your first idea"** over a muted,
  organized two-column feature list.

## Fixes
- **Blueprint empty-state box collapsed** to a ~80px sliver (one word per line) — it
  now uses an explicit width. (Bug #139.)
- **Manual Save dropped game data:** saving a game via the Save dialog omitted its
  Blueprint and authoring mode, so a saved-to-disk game could lose its logic and a
  code game could be regenerated from blocks. Both are now persisted. (Bug #138.)

## Internal / tests / docs
- New Game builds `design` docs via `handleNew('design', stageSize, …)`; the runtime
  already staged on `pageRect()` so no runtime change was needed. `welcome-screen.tsx`
  rewritten (drops the rough.js arrow layer). e2e verified (New Game → 1280×720 stage →
  Pong plays; landing shows the CTA; `.bp-empty` width restored). Help, learnings,
  bug-log and roadmap updated.

## Breaking changes / migration
- None. Existing infinite-canvas games still run (their stage falls back to the page).
