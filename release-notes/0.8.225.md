# 0.8.225 — Fill & Stroke, and a palette that could not remove a colour (2026-08-26)

## Highlights
- **Fill & Stroke lives in the tool column now** — the Illustrator swatch pair, with *None*, an eyedropper, swap and reset one click away instead of a scroll through the Properties panel.
- **Every colour palette can take a colour away.** `transparent` was a swatch in one palette out of five, and not the one most people get by default.
- The **eyedropper** — which reads the exact colour out of the document, and the rendered pixel from an image — is now where someone matching a palette off a reference photo would actually look for it.

All three came from one piece of user feedback, and two of them were about reach rather than capability: the feature existed and could not be found.

## Features

**Fill & Stroke, in the tools area.** Two overlapping squares at the head of the tool column: a solid one for the fill, a ring behind it for the stroke. They show what the selection is painted with — or, with nothing selected, what the **next shape you draw** will be painted with. A red slash means that channel is empty.

Clicking either opens a panel aimed at that channel:

- **A palette of swatches**, with the palette dropdown at the top.
- **None** — removes that fill or stroke. This is the one-click "no outline" that used to mean scrolling the Properties panel to find the control.
- **Pick** — the eyedropper. Click anything on the canvas and its colour lands in the channel.
- **Swap** and **Reset** — swap fill ⇄ stroke, or return to a black stroke with no fill.
- A full colour picker with a hex field and recents.

<kbd>X</kbd> switches which channel you are setting; <kbd>Shift</kbd>+<kbd>X</kbd> swaps the two colours.

Illustrator keeps this pair at the *foot* of its tool column. It sits at the head here because ours scrolls — with twenty-odd tool groups it routinely overflows, and the last item in a scrolling strip is the one you have to go looking for, which is the complaint the control exists to answer.

```js
Yappy.setPaintColor('stroke', 'transparent');   // remove the outline
Yappy.setPaintColor('fill', '#e03131');         // paint the fill red
Yappy.getPaintColor('fill');                    // → '#e03131'
Yappy.setActivePaint('stroke');                 // what X toggles
Yappy.resetPaint();                             // black stroke, no fill
```

**Transparent in every palette.** Each palette now leads with the checkerboard swatch, in the same first position, so clearing a fill or a stroke is the same gesture whichever palette you are on — including from the top-bar palette popup.

**The eyedropper, twice more.** It is a button in the palette popup and in the Fill & Stroke panel. It paints whichever channel is currently aimed at, so <kbd>X</kbd> decides whether the colour you sample becomes a fill or a stroke. It reads colours out of the *document* rather than the composited screen, so what you pick is bit-for-bit what the shape is; over an image it samples the pixel under the cursor, which is what makes matching a palette off a pasted reference work.

## Fixes

**The default palette could paint a colour but never take one away.** `transparent` existed in the `default` palette only. `defaultPaletteId()` returns `p3` on any wide-gamut display, so the palette most people actually open was one of the four that could not express *none*. Fixed in the palette data; every palette leads with it.

**<kbd>Shift</kbd>+<kbd>X</kbd> did nothing on an empty canvas.** The swap was guarded by `if (store.selection.length > 0)`, so the one moment the shortcut is most useful — setting up the colours for the next shape before drawing it — was the one moment it was inert. It now swaps the armed defaults.

**Reset took two undos.** The new *Reset* clears the fill and sets the stroke in two calls, each of which was snapshotting history for itself. One snapshot now covers the pair.

## Internal / tests / docs

- `setPaintColor(channel, color, ids?, history?)` in the store is the single path for painting a channel. It keeps `fillStyle` coherent (a colour under `fillStyle: 'image'` would not be visible; clearing a colour *keeps* the fill style, so a gradient survives being hidden), and sets `textColor` alongside `strokeColor` for text — whose visible colour is `textColor || strokeColor`, so every call site that skipped it had the same bug: setting a text element's colour appeared to do nothing.
- `utils/popover-placement.ts` — the flip-and-clamp geometry for a panel anchored to a bar that can be docked to any of four edges, extracted so it can be tested against a viewport rather than only observed in one.
- 17 store unit tests, 5 placement tests, 4 Playwright specs — including one that drives the real eyedropper over a real image element, since the pixel-sampling path only exists in a browser.
- **A bare `.empty { padding: 20px }` in `file-open-dialog.css` is global.** The fill square rendered at 42px for one revision — a 17px border-box square plus 20px of padding — swallowing the stroke ring behind it. Same defect class as #329. The Fill & Stroke classes are all prefixed; the loose rule is still there for the next component that uses a plain state-class name.
- Strings in all five locales, `workspace.md` gains a Fill & Stroke section, and the hotkeys dialog lists <kbd>X</kbd>.

## Breaking changes / migration

None. `swapFillStroke()` now acts on the armed defaults when nothing is selected, where it previously returned early.
