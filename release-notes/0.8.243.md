# 0.8.243 — Type while you drag to label a shape (2026-09-10)

## Highlights
- **Start dragging a shape and just type.** The characters land in that shape's label as you
  size it; release and the shape arrives already labelled. Drag, type `A`, release. Drag,
  type `B`, release. No double-click, no <kbd>Enter</kbd>, no mode to leave.

## Features
- **Type-to-label during a creation drag** (spec F3). Pick any shape tool, press, drag, and
  type — the label appears live inside the shape being drawn.
  - <kbd>Backspace</kbd> deletes a **character**, never the shape being dragged.
  - <kbd>Space</kbd> is a space, so `Load Balancer` works. It is not hold-to-pan here: one
    pointer cannot pan and size a shape at once, and drawing past the viewport edge is
    already handled by auto-scroll.
  - Modifiers are untouched — <kbd>Shift</kbd> still constrains proportions while you type.
  - The shape and its label are **one undo step**. `updateElement` defaults to
    `recordHistory: false`, so the keystrokes do not each become an undo entry.
  - Freehand strokes (Fineliner, Marker, Ink Brush), bare connectors, the text tools and the
    vector Pen deliberately ignore it: those drags run long or own those keys already, and a
    stray keystroke should not become a caption.
- Advertised in the status bar (**Type · Label while drawing**) whenever a shape tool is
  armed, and in the in-app help dialog — nobody discovers this by accident.

**Why it needed no new rendering code:** the element already exists in the store during the
drag and is mutated on every `pointermove` — that is how the live preview resizes. So a
keystroke is just `updateElement(id, { containerText })`, and the label renders through the
ordinary containerText path: in place, live, in **both** sketch and architectural styles.
Verified visually in both.

## Fixes
- None. This release is the F3 half of `docs/type-to-label-spec.md`; the bug that had to be
  fixed before it could exist (#360, single-key shortcuts corrupting a live drag) shipped in
  v0.8.242.

## Internal / tests / docs
- `tests/type-to-label.spec.ts` — 6 new e2e tests: live label, Backspace-deletes-a-character,
  single undo step, Space as separator, freehand opt-out, and no buffer carry-over between
  shapes.
- `pState.dragLabelBuffer` on the pointer state (cleared in `drawOnDown`, so it is owned by
  one gesture), and `acceptsDragLabel()` exported from `draw-handler.ts` as a *reject* list —
  so a newly added shape opts in by default.
- **Spec correction:** the F3 design table claimed Escape "cancels the drag (existing)". It
  does not — Escape is wired only for crop/polyline/pen, which are multi-click construction.
  A single-drag shape has never been Escape-cancellable. F3 leaves that unchanged and the
  current behaviour is now pinned by a test; whether it *should* change is logged in
  `todo.md` rather than bundled in here.
- New help-dialog row and status-bar hint, translated across all five locales.

## Breaking changes / migration
None. Those keystrokes previously did nothing during a drag (as of v0.8.242) — this gives
them a use rather than taking one away.
