# 0.8.88 — Element search: illustrations, semantic aliases, scriptable API (2026-07-13)

## Highlights
- The unified **Elements** search now includes a bundled **Illustrations** library
  — a curated, colourful **OpenMoji** set that drops in as fully **editable,
  recolourable vectors** (a real edge over flat graphics). New **Illustrations**
  chip in the blended feed. This is **Phases 2–3** of the unified-search plan
  (`docs/unified-element-search-plan.md`), completing Phase 1 (v0.8.87).
- Search got noticeably smarter: a hand-curated **keyword-alias map** (~180 words)
  means everyday words find the right asset even when it's named differently —
  `money → dollar / coin / money-bag`, `idea → lightbulb / brain`, `secure →
  lock / shield`, `goal → target / trophy`.
- The whole panel is now **scriptable** (`Yappy.searchElements` / `insertElement`)
  and has a keyboard shortcut (**Alt+E**).

## Features
- **Illustrations library** (Phase 2): 85 curated OpenMoji SVGs (hearts, rockets,
  charts, trophies, tools, weather, food, travel…), bundled offline and inserted
  via the same `importSvgToCanvas` path as icons — so they're editable vectors with
  sketch/architectural render parity. New **Illustrations** type chip; OpenMoji
  **CC BY-SA 4.0** attribution shown under the results. Regenerate the bundle with
  `scripts/build-illustrations.mjs`.
- **Semantic keyword aliases** (Phase 2): `library/elements/aliases.ts` expands a
  query into related concept tokens across the icon and illustration providers.
  Direct-name matches still rank first; aliases fill in behind them.
- **Scriptable search API** (Phase 3, `window.Yappy`):
  - `searchElements(query, { kinds?, includePhotos? })` → `Promise<AssetHit[]>`
    across icons + illustrations + shapes + photos (offline kinds resolve first;
    photos append when the network call finishes; photo errors degrade to none).
  - `insertElement(hit, at?)` drops a hit onto the canvas (centred, or at a world
    point). Each hit also exposes `insert()` directly.
- **Alt+E** toggles the Elements panel; also added as a Command-palette entry
  ("Toggle Elements Panel").

## Fixes
- **Connector quick-connect ports swarmed a multi-selection** (#159): grouping /
  selecting several elements (e.g. an imported icon = many path parts) painted N×4
  green connector handles. The connector-handle block in `selection-renderer.ts`
  now gates on `selectionLength === 1`, matching the adjacent path-anchor / resize
  blocks — ports appear only for a single selected shape.
- **Right-clicking an existing group offered "Group" instead of "Ungroup"** (#160):
  clicking a group selects all its members, so the context menu showed a prominent
  "Group" (the buried Ungroup was ~68 lines lower). `context-menu-builder.ts` now
  detects a fully-grouped selection (`isFullyGrouped`) and shows **Ungroup** in the
  top grouping slot; the lower Ungroup only appears for mixed selections, never
  duplicated.

## Known limitations / next (Phase 4)
- Search still covers the **element** tier only. Phase 4 will fold Yappy's existing
  **template** search (`templates/registry.ts`) into the same feed — Canva's
  element + template two-tier.
