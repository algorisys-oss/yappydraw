# 0.8.178 — Select all, change the font (2026-08-06)

Two Properties-panel fixes, a safer opening tool, and a tidier top bar.

## Highlights

- **Ctrl+A → change the Font now works.** The text controls used to disappear from a mixed
  selection instead of applying to the parts that could take them.
- **Bold and Italic show the truth.** They rendered as ticked on plain Regular, upright text.
- **Yappy opens on Select**, so the first click doesn't draw on the drawing you just reopened.
- **The selection's dimension badge is opt-in**, and no longer sits offset from its object.
- **Pan, Commands, Vector Tools and Shape Builder moved to the top bar**, out of the drawing-tool column.
- **Tablets get the full top bar** — an iPad portrait used to collapse to the phone layout.

## Changes

### The dimension badge is off by default, and lands on its object

Every selection carried a live `W × H` / `X, Y` badge with no way to switch it off. It earns its
place *during* a resize and is clutter the rest of the time, sitting on top of the artwork and
the quick-connect handle.

- New `globalSettings.showDimensions`, **default off**, persisted in localStorage.
- Toggled from a **Proportions button in the top bar** beside Settings and Properties (active
  state shown), plus a *Show Dimensions* entry in the mobile View menu.
- API: `Yappy.setShowDimensions(on)`, `toggleShowDimensions()`, `getShowDimensions()`. Distinct
  from `addDimension()` (a permanent annotation) and `setExportIncludeDimensions()` (bakes those
  into an export).
- Read from **localStorage only**, never from the loaded document. The first cut used `lsBool`,
  whose fallback is the document's own value — so a drawing autosaved while the badge was on
  turned it back on for good and the default never applied. It's an app-level preference like
  `defaultTool`, so it gets its own reader (`readShowDimensions`).

### Pan, Commands, Vector Tools and Shape Builder are top-bar controls now

The left column is for things you draw with. These four aren't: one moves the view, one opens a
searchable action list, one a floating palette, one enters a mode. They now sit in the top bar's
view-control cluster ahead of Settings / Properties / Show Dimensions / Help, keeping their
active-state highlight (Pan lights up while it's the active tool and clicking it again returns to
Select). Selection stays in the column — it's what you come back to between drawing tools.

Below 700px the cluster collapses, so all five are mirrored in the hamburger menu beside
Rulers & Guides.

### The top bar no longer collapses to its phone layout on an iPad

`isMobile` was `innerWidth <= 768` — *exactly* an iPad portrait. A tablet therefore showed the
full desktop tool column and the phone top bar at the same time, and once the controls above moved
up there, they were reachable on an iPad only through the menu.

The gate is now `< 700`. Deliberately not `PHONE_MAX_WIDTH` (600): the bar is a `nowrap` flex row
with `overflow: visible`, so anything that doesn't fit is *clipped* rather than scrollable —
measured, the full row needs 628px, and at 601 the theme toggle hung 14px off the right edge. 700
leaves headroom and puts every iPad (mini 744 through Pro 1024) on the full bar.

Swept 390 / 430 / 600 / 601 / 699 / 700 / 744 / 768 / 834 / 1024 / 1366: zero clipping and zero
horizontal page scroll at every width.

While the dimension badge was open: `TransformHud` positioned itself with `worldToScreen` (canvas-local px) on a
`position: fixed; inset: 0` layer (window px) — the third instance of the frame mismatch fixed in
0.8.177, so the badge drew 46px left and 52px above its anchor. It uses `worldToWindow` now and
sits centred under the selection.

### The opening tool is Select, not the Ink Brush

Reloading (or starting a new sketch) left the Ink Brush active, so the first click on the canvas
laid down a stroke instead of picking up the thing you clicked. The cost of that default is
asymmetric: opening in Select and wanting to draw is one keystroke; opening in a pen and not
wanting to draw is a stray mark, noticing it, and an undo.

- `readDefaultTool()`'s fallback is now `selection`, exported as `DEFAULT_TOOL_FALLBACK` and
  shared by `api.ts`'s `getDefaultTool()` and the Settings dropdown (where Select is now listed
  first).
- **Your preference still wins.** This is only the fallback — Settings → Pen & Input → *Default
  Tool* is read from localStorage first, so anyone who has picked the Ink Brush or the Fineliner
  keeps it.
- `resetToNewDocument` now resets `selectedTool` to that default tool and clears `toolLocked`.
  A new sketch previously inherited whatever tool the *previous* document ended in.

## Fixes

### Ctrl+A hid the Font control instead of applying it to everything

`activeProperties` required **every** selected element's type to list a property in
`applicableTo`. A freehand stroke doesn't take `fontFamily`, so one stroke in the selection
removed Font, Size, Bold and Align from the panel — and "select all and restyle the type", the
most common bulk edit there is, had no way to be expressed at all.

A property now shows when **any** selected element supports it — the same any-of rule the
`dependsOn` check beside it has always used. Which elements an edit lands on is computed once by
a new `supportedSelection(key)` helper:

- Every multi-select **write** in `handleChange` goes through it — the generic patch and the
  mesh / pattern / gradient-preset / image-filter / openBox-preset / text-effect / numeric-
  transform special cases — so changing Font with a stroke in the selection restyles the labels
  and leaves the stroke alone rather than stamping `fontFamily` onto it.
- The **read** in `getPropertyValue` goes through it too. That part is easy to miss and fails
  quietly: comparing values across an element that doesn't have the property at all would make
  every text row report "Mixed" no matter how consistent the actual text was.

### Bold and Italic showed as ticked on Regular, upright text

Leftover from the 0.8.175 boolean → 100–900 weight axis change. The panel's toggle rendered
`checked={!!value}`, and after the migration `fontWeight` is `400` and `fontStyle` is `'normal'`
— both truthy — so both boxes lit up on text that was neither, and the first click appeared to do
nothing because it was turning them *off*.

The checkbox now reads through `normalizeFontWeight` / `normalizeFontStyle`: on means
SemiBold-and-up (so picking ExtraBold in the Style dropdown doesn't leave Bold unticked) or
`fontStyle === 'italic'`. It writes back `700`/`400` and `'italic'`/`'normal'` instead of a bare
boolean. This matches `IconToggleControl` in `quick-controls.tsx`, which was updated at the time
and had it right — only the Properties panel's checkbox was missed.

## Verification

The top bar, the dimension toggle and the moved buttons were checked in the running app: the
badge is absent on a fresh load (`getShowDimensions() === false`, no localStorage key), the
Proportions button turns it on and off and persists `1`/`0`, and the badge lands centred under
the selection; Commands / Vector Tools / Shape Builder are present in
`.topbar-view-controls` and gone from `.toolbar-container`.

In the running app, with a rectangle label, a circle label, a text element **and** a freehand
stroke all selected: the Font row is present, picking Merriweather changes all three text
elements and leaves the stroke's own `fontFamily` untouched, Bold writes `700` (and `400` when
unticked) to the three and nothing to the stroke, Italic writes `'italic'`, and the Style
dropdown stays in sync with the checkboxes throughout.

`comprehensive-features`, `ui-panels`, `font-metrics`, `font-picker-check`, `quick-wins-batch1`
and `select-and-constrain` run clean apart from four failures that reproduce on the unmodified
tree (`font-picker-check:23`, `quick-wins-batch1:13`, `select-and-constrain:5`,
`select-and-constrain:37`). `comprehensive-features:34` (theme toggle) failed once under load and
passes 4/4 on its own with these changes — a flake, not a regression.

## Breaking changes

None. A multi-selection now offers more controls than before, never fewer.
