# 0.8.250 — The drawing API on a CDN (2026-09-14)

## Highlights
- **YappyDraw's API without the editor, from jsDelivr.** Every release now publishes the
  drawing API as an ES module to the `cdn/` folder of
  [algorisys-oss/yappydraw](https://github.com/algorisys-oss/yappydraw), tagged with the
  version. A page can build a sketch and animate it with tinyfly, GSAP or CSS, with no iframe
  and no build step:

  ```html
  <script type="module">
    import { Yappy, mount, fontsReady } from 'https://cdn.jsdelivr.net/gh/algorisys-oss/yappydraw@v0.8.250/cdn/yappy.js'
    await fontsReady()
    const sun = Yappy.createCircle(40, 40, 120, 120, { backgroundColor: '#ffd166', fillStyle: 'hachure' })
    mount('#stage')
    tinyfly.to(`[data-yappy-id="${sun}"]`, { rotate: 360, duration: 4, repeat: -1 })
  </script>
  ```

## Features
- **SDK exports:** `Yappy` (the full `window.Yappy` API), `toSVG(options?)`,
  `mount(target, options?)`, `fontsReady()`, `clear()`, `version`.
- **`toSVG()` never downloads a file.** `Yappy.exportSVG()` still does.
- **`fontsReady()` loads the built-in fonts on the host page.** Without it, text on an SDK page is
  measured against a fallback font: 180.39 px instead of 187.00 px for the reference string.
- **`clear()` starts a genuinely fresh drawing.** Unlike `Yappy.clear()`, it also removes pages
  left behind by `importMarkdownSlides`.
- **API:** `Yappy.exportSVG(onlySelected, { elementIds: true })` wraps every element in
  `<g data-yappy-id="…">`. The wrapper has no transform of its own, so animating it composes
  with the shape's rotation and flip instead of replacing them. Off by default, so ordinary
  exports are unchanged. The attribute is not `id`, because every drawing has a `rect-1`.
- **Example:** `examples/ganesh-chaturthi.js` (with its saved `.yappy`) is a festive
  illustration and a seamless 16-second loop, built entirely with the public API.

## Internal / tests / docs
- `frontend/src/sdk/index.ts` is the SDK entry point. `vite.sdk.config.ts` builds it
  (`npm run build:sdk` → `dist-sdk/`), with a no-op stand-in for `virtual:pwa-register`.
- **Bundle:** `yappy.js` is a 4 KB entry and the core chunk is 2.3 MB (608 KB gzipped).
  MathJax, the exporters and similar features stay lazily loaded chunks. Build peak is 1.36 GB.
- `exportToSvg` is split into `renderSvgString` (build) and a save step.
- **Verification script:** `scripts/verify-sdk.mjs` (`npm run verify:sdk`) loads the built SDK
  in headless Chromium. Its 11 checks cover exports, version, ids, `mount`, a lazy chunk
  resolving from `chunks/`, `clear`, and that no download started.
- **Publishing:** `publish-oss.sh` builds the SDK from the published tree into `cdn/` and
  smoke-tests it on every run. It tags the OSS commit `v<version>` and never moves an
  existing tag. The mirror's `package.json` keeps `build:sdk`.
- `tests/svg-element-ids.spec.ts` (2 tests): each element gets a transform-free wrapper, in
  render order, and the rotation stays on the inner node. The default export is unchanged.
- **Checked by hand:** with tinyfly's browser bundle on a mounted sketch, a circle rotated in
  place, and a box pre-rotated 15° moved exactly 100 px and kept its 15°.
- **Docs:** Help → Embedding gains *Use the API without the editor (CDN SDK)*. README documents
  the CDN and the publish step.

## Breaking changes / migration
None.

**Known limits:**
- ES module only.
- One drawing per page.
- AGPL-3.0, like the rest of the project: load it at runtime rather than bundling it.
- Each publish adds about 7.4 MB of `cdn/` to the OSS repository's history.
