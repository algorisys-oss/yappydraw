# 0.5.16 — Google Fonts, custom-font hardening & UML in the Architecture group (2026-06-30)

## Highlights
- **Google Fonts** — search a curated list of popular Google Fonts and add one by name, right from the Font picker.
- **UML tools** are now part of the unified **Architecture** group (UML Structure + UML Behavior sections).

## Features
- **Google Fonts dialog** (`google-fonts-dialog.tsx`): the Font picker gains a **🔍 Google Fonts…** entry that opens a searchable list of ~100 popular families, each previewed in its own font (loaded on demand). Selecting one loads it via the Google CSS API (no API key), registers it, persists it, and applies it.
- `addGoogleFont(family)` + a curated `GOOGLE_FONTS` list in `utils/custom-fonts.ts`; `CustomFont.kind` (`file` | `google`) so reloads re-activate uploads vs Google links correctly.
- **UML in Architecture** — the Class/Interface/Enum/Package/Component/Note and Actor/UseCase/State/Lifeline/Fragment/Signal/Interface tools move into the Architecture fly-out (45 shapes across 7 sub-sections). The standalone UML toolbar group is removed.

## Fixes
- **Custom fonts could silently fall back to the default font** — `registerFontFamily` and the renderer's `resolveFontFamily` could touch different module instances of `text-utils`; the custom-font registry is now backed by `globalThis` so a registration is visible everywhere (hardens both uploaded and Google fonts).

## Internal / tests / docs
- `docs/uml-completeness-review.md` — UML coverage matrix by diagram type + prioritized gaps (Deployment Node/Artifact, Object instance, Port, History pseudostate, dedicated Activity action).
- Help docs updated for Google Fonts; learnings logged.
- e2e checks for the Google Fonts flow and the Architecture/UML grouping.

## Breaking changes / migration
- None for documents. The UML toolbar dropdown is replaced by the **UML Structure / UML Behavior** sections inside the **Architecture** group (same shapes).
