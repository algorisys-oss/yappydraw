# 0.8.149 — Dependency audit clean: 8 vulnerabilities → 0 (2026-07-28)

## Highlights
- `npm audit` goes from **1 critical + 5 high + 2 low** to **0**, in both this repo and the published OSS mirror.
- No production code changed — this is entirely a dependency-tree fix.

## Fixes
- **`seroval` (critical, GHSA-mv8w-475r-vwqw)** — prototype/type confusion in `seroval.fromJSON()` invoking attacker-controlled methods during deserialization. This one matters most because `seroval` arrives via `solid-js` and therefore ships in the production bundle. Resolved by a semver-compatible upgrade.
- **`postcss`, `fast-uri`, `shell-quote`/`concurrently`, `brace-expansion`** — all resolved by semver-compatible upgrades (`npm audit fix`, no `--force`).
- **The remaining 8 highs all traced to a single root** and needed a different approach. The chain was `vite-plugin-pwa → workbox-build → @trickfilm400/rollup-plugin-off-main-thread → ejs → jake → filelist → minimatch → brace-expansion`, where every package above `brace-expansion` was flagged purely for depending on it.
  - npm's own suggestion was to "upgrade" `vite-plugin-pwa` to 1.2.0 — a **downgrade** from the 1.3.0 already installed, so a dead end.
  - Overriding `brace-expansion` to the only patched version (5.0.8) **breaks the build**: 5.x's CommonJS entry exports an object (`{ expand, … }`) where 2.x exported the function directly, and `filelist`'s bundled `minimatch@5.1.9` does `const expand = require('brace-expansion')` and then calls it. Verified rather than assumed — the call throws `be is not a function`.
  - The clean fix is one level up: **`ejs@6` dropped its `jake` dependency entirely** (ejs 6.0.1 has *zero* dependencies), which removes `jake → filelist → minimatch → brace-expansion@2.x` from the tree outright. Pinned via `overrides: { "ejs": "^6.0.1" }`. Three packages removed, nothing forced onto an incompatible consumer.

## Internal / tests / docs
- Verified `ejs@6`'s CommonJS shape still matches what `@trickfilm400/rollup-plugin-off-main-thread` expects (`require("ejs")` → object with `render`/`compile`), then confirmed the real thing: the production build succeeds and the PWA service worker still generates with an identical **202 precache entries**.
- Simulated the OSS mirror's stripped `package.json` + regenerated lockfile and audited it separately — `overrides` carries through the publish script, and that tree is **0 vulnerabilities** too. (The mirror also drops `concurrently`, which was the source of the `shell-quote` high.)
- 63 e2e tests re-run after the dependency change, including the offline/PWA check.

## Breaking changes / migration
- None. `overrides` affects only the resolved dependency tree; no application code or API changed.
