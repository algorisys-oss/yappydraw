# 0.8.162 — The shell becomes a real frame: Properties docks, the header stops floating (2026-07-29)

## Highlights
- **Properties is an ordinary dock panel.** Dock it left or right, float it, resize it,
  collapse it — and your arrangement comes back next time. It was the last panel still
  hard-pinned to the right edge with chrome of its own.
- **The top bar is a real header.** The logo/menu, tool options and view controls are laid
  out *by* the bar instead of being four `position: fixed` pills floating on top of it.
- **Settings and Help are navigable and searchable.** Settings gains a category rail;
  both dialogs gain a search box.
- **Settings / Properties / Help moved out of the bottom-left corner** into the top bar,
  where they no longer sit on top of the drawing.

## Features
- Properties registers as the `'properties'` dock panel: title-bar buttons for dock-left,
  dock-right, float, collapse and close; drag the title bar to re-dock; drag a zone's
  inner edge to resize. Placement persists with the rest of the dock layout. It defaults
  to docked right — it is a persistent inspector, and a floating one would sit over the
  drawing it describes.
- Duplicate and Delete moved into the panel body, with the object's properties. They act
  on the selection, not on the panel, so they never belonged next to Close.
- **Settings** is two panes: a category rail (General, Pen & Input, Defaults, Mindmap,
  Time-lapse, Cloud Storage) and the active category beside it, instead of one scroll
  through seven unrelated sections.
- **Search in Settings** spans every category at once, for when you know what you want but
  not where it lives. The rail hides while searching, since highlighting one category
  would misrepresent what is on screen.
- **Search in Help** filters shortcuts by name *or* by keys — "duplicate" and "ctrl+d"
  find the same row. Categories that match nothing drop out.
- On phones, Settings / Properties / Help fold into the top bar's existing ⋮ overflow menu
  rather than a separate floating rail.

## Fixes
- **The colour-palette and theme buttons were invisible.** They sat at `z-index: 10000`,
  below the header's own opaque `10050` background, so the bar painted over them. See
  `docs/bugs/bug-fixes.md`.
- **Three onboarding-tour steps had stopped highlighting anything.** The tour resolves
  targets with `querySelector` and silently degrades to an unanchored card on a miss, so
  `.property-panel-container`, `.floating-tools-cluster` and `.help-btn` had gone dangling
  without any build or typecheck noticing.
- Panel-adjacent UI no longer assumes Properties is 280px wide on the right. The
  quick-toolbar's collision avoidance and the header's right-hand offset read the live
  `--dock-right`, so they stay correct when you resize the zone, dock it left, or float it.

## Internal / tests / docs
- `showPropertyPanel` and `isPropertyPanelMinimized` are gone from app state — the dock
  layout already held that information. Eighteen tool groups were writing them in pairs;
  they call `showPropertiesPanel()` now. The fields were deleted rather than left as dead
  flags so the compiler pointed at every writer.
- `dockInsets()` drops its hard-coded 280px right-hand special case; the panel's width
  comes from `layoutInsets()` like every other panel's.
- The header's drag rig (per-cluster x/y offsets, drag handles, window-level
  mousemove/mouseup listeners) is deleted, along with `.tool-options-bar`'s
  `left: 296px; right: 130px` gutters — a manual re-creation of a layout flexbox does.
- The mobile bottom-sheet geometry in `property-panel.css` was deleted rather than ported:
  `dock.css` already applies the identical sheet to every panel on phones.
- Help doc (`help-docs/features/workspace-doc.tsx`) covers the dockable Properties panel,
  the Settings categories and both search boxes. `api.ts` documents `'properties'` as a
  dock-panel id.
- Verified in a real browser at 1440px, 768px, 600px and 420px: bar layout, no horizontal
  overflow, category switching, both searches, all six tour targets resolving, and no
  console errors.
- **E2E selectors updated across 10 spec files.** The suites addressed panels by their
  old private containers (`.property-panel-container`, `.layer-panel`) and read
  `state.showPropertyPanel`; they now use `.dock-panel[data-panel-id="…"]` and
  `Yappy.isPanelOpen(id)`. Two assertions were rewritten rather than repointed, because
  the behaviour they described genuinely changed: `PanelChrome` snaps a dragged panel to a
  fixed offset from the cursor instead of translating it by the pointer delta, and the
  right-hand inset is the dock zone's (resizable) width rather than a 280px constant.
  Some of these had been red since the earlier Layers migration — a CSS selector is an
  untyped reference, so a renamed element breaks a test silently, the same failure mode
  that had left three onboarding-tour steps dangling.
- 42/42 shell specs pass (toolbar-dock, ui-panels, hotkeys, builtin-panel-drag,
  tool-options-bar). Three pre-existing failures remain in `productivity-features` (layer
  context menu) and `comprehensive-features` (font-family select) — confirmed by A/B
  against `dc3e8061` to predate this work, and untouched by it.

## Breaking changes / migration
- `state.showPropertyPanel` and `state.isPropertyPanelMinimized` no longer exist. Scripts
  reading them should use `Yappy.isPanelOpen('properties')`; scripts setting them should
  use `Yappy.togglePropertyPanel(visible?)`. Both already existed and are unchanged.
- `minimizePropertyPanel()` is removed — the dock's collapse control replaces it.
