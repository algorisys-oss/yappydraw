# 0.8.284 — Elbow connectors that route (2026-10-11)

## Highlights
- **Elbows inside a container route again.** A frame, pool or cluster box around your services used to switch the router off: every elbow inside it was a plain mid-point jog, straight through whatever sat between its ends. Containers are no longer obstacles, and 20 of 20 connectors in the reference architecture diagram now route.
- **Square in, square out.** Elbows made with `Yappy.connect`, the DSL's `=>`, or re-attached after you moved a shape round, used to leave a box *along* its edge. Exit and entry sides now come from where the endpoint actually is.
- **Clear of shapes, clear of each other.** Routes keep 10px from any shape they pass, so no more running along a box's border; connectors — including several fanning out of one box — take separate lanes rather than one trunk. 0 overlaps on both test diagrams (94 elbows on a 48-node grid routes in under 100ms).
- **Re-routes when a shape lands on a path**, whether you drag it, resize it, move it from a script or undo onto it.
- **Hand-adjusted elbows stay adjusted.** Drag a segment or bend; the shapes can move and your bends survive. Right-click → **Re-route automatically** to give it back.

## Features
- `manualRoute` element option (elbows): keeps the current waypoints across shape moves; set automatically by a segment/bend drag, cleared by **Re-route automatically**, a curve-style change, or re-attaching an end.
- Context menu: **Re-route automatically** on hand-routed elbows (translated: de, es, fr, ja).
- Segment drag on a bound elbow's first/last segment grows a 20px stub at the port instead of pulling the end off the shape; bend drag keeps right angles.

## Fixes
- **#441** Enclosing frames hard-blocked A*; every elbow inside fell back to the naive route.
- **#442** API/DSL and re-faced bindings had no usable side; routes left along the shape's edge.
- **#443** Long hops across a dense grid exceeded the 800-step A* budget; now a heap with 4000 steps (WASM mirrored).
- **#444 / #449** Shapes moved, resized, scripted or undone onto an elbow didn't re-route it; after Clear a rebuilt diagram was never routed.
- **#445** Routes ran along the border of shapes they passed.
- **#446** Connectors sharing a shape merged into one trunk; the 48-segment avoidance cap hid long hops from each other.
- **#447** A re-routed connector landing on another's lane left both overlapping.
- **#448** Hand-dragged bends were overwritten by the next shape move; first-segment drags detached the end.

## Internal / tests / docs
- `collectShapeObstacles` is the one obstacle filter for the JS router and the WASM bridge; `OBSTACLE_CLEARANCE`, `MAX_ROUTE_ITERATIONS` mirrored in `assembly/routing.ts`.
- `refreshConnectors` (port groups → id order → one cascade) replaces per-caller `expandToPortGroups` loops; the canvas effect diffs shape boxes instead of refreshing every connector on every change.
- Tests: `routing.test.ts` (+9), `connector-routing.test.ts` (+4), new `binding-logic.test.ts` (+7). Audit harnesses in `temp/elbow-audit.test.ts` and `temp/elbow-visual2.mjs`.
- Help: Connectors → "Elbow routing" and "Adjusting an elbow by hand". Bug log #441–#449, learnings, routing plan status.

## Breaking changes / migration
- None. Existing elbows re-route on their next refresh (a shape move). Elbows you had adjusted by hand before this release carry no `manualRoute` flag and will re-route once; drag a segment again to pin them.
