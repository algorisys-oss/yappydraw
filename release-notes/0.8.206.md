# 0.8.206 — A cloud that survives being dragged wide, a checkmark that isn't a triangle (2026-08-20)

Four reports in one message, three of them shapes drawing the wrong thing and one about the
Properties panel showing everything except the one control you were looking for.

## Highlights

- **The cloud keeps its shape at any size.** Dragged wide and short it used to collapse into a
  spiked bowtie.
- **The checkmark is a checkmark.** It was rendering as a triangle.
- **The heart lost the spike** through the notch between its lobes.
- **The Properties panel follows the tool you picked.** Choose Polygon and *Polygon Sides* is
  right there, before you draw anything.

## Fixes

### Cloud, dragged horizontally

Every arc radius was computed from the width alone, so a short, wide box asked for arcs bigger
than the height could hold. SVG clamps a radius it cannot honour, and what came out was a spiked
bowtie. The outline is now built from scallops whose radius comes from the chord between
neighbouring bumps, with the bumps placed on an ellipse from both axes — so the cloud follows
whatever box you drag, from 900 × 90 to 80 × 400.

### Checkmark rendered as a triangle

The three points were right; they were returned as a *closed* shape, so the renderer joined the
tip back to the tail and drew the third side. It is an open path now, in both drawing styles.

### Heart had a spike through the top

The path started 30% down the middle, drew the left lobe, then drew the left lobe again at the
end — so closing it drew a straight line from the notch back down to the start. It now starts and
ends at the notch, with each lobe drawn once.

### The Properties panel ignored the active tool

*"It took me a lot of time to find the polygon sides while making polygons."*

The panel already filtered its controls by what the target supports, and already had a "defaults
for the active tool" mode — but that branch sat below the slide check, and slides are the default
document type, so it was unreachable. Picking the Polygon tool showed slide Transition and
Background instead, and *Polygon Sides* was not findable until you had drawn a polygon and
selected it.

The tool is checked first now. Polygon shows *Polygon Sides*, Star shows *Star Points*, the
eraser shows only its width. Tools that select rather than draw — Select, Pan, Lasso, Crop — still
fall through to the slide and canvas properties, and an explicit *Canvas Settings* still wins.

## Internal / tests / docs

- `frontend/src/utils/shape-geometry-fixes.test.ts` — asserts the geometry, not a screenshot: no
  cloud arc may be smaller than the chord it spans (the exact condition that caused the clamping),
  the cloud stays inside its box at six aspect ratios, the heart closes where it started and draws
  each lobe once, and the checkmark is an open three-point tick. Five of the seven fail with the
  fixes reverted.
- The WASM shape path had the checkmark right all along — its `OPEN_SHAPES` set includes it — so
  this was the JS fallback disagreeing with the fast path, in the direction that ships.
- 1,031 unit tests.

## Breaking changes / migration

None. Existing clouds, hearts and checkmarks are stored as type + box, so they pick up the
corrected geometry on load — which is the fix. If you had worked around the broken cloud by
resizing it to something nearly square, it will now look like a cloud at that size too.

## Known, not fixed here

A **sketch-style** shape at sloppiness above 0 draws each edge twice — that is what makes it look
hand-drawn — and at a stroke width of 1, zoomed in, the two passes read as two separate outlines
rather than one sketchy line. Since 0.8.205 new shapes start at sloppiness 0, so this only appears
if you turn it up. Reducing the separation for thin strokes would change how every existing sketch
drawing looks, so it is a deliberate decision rather than a quiet tweak.
