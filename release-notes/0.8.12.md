# 0.8.12 — Blueprint sample games + a canvas view switcher (2026-07-07)

## Highlights
- Two **Blueprint** sample games under **Menu → Game → New Game…** — a full game
  wired as nodes so you can learn the Blueprint editor by example.
- A floating **Simple · Graph · Blueprint · Code + ▶ Play** bar on the game canvas,
  so you can switch views without opening the menu.

## Features
- **Platformer · Blueprint** and **Breakout · Blueprint** starters
  (`game/blueprint-examples.ts`): they build a ready-made Blueprint graph on the
  sprites and open the Blueprint editor. Platformer is the same level as the block
  version (3 platforms, 3 coins, a goal flag) authored as nodes; Breakout shows off
  a scene+sprite split and Blueprint **variables** — a brick counter that declares
  the win at zero. Both compile through the same pipeline as the block games, so
  physics/scoring/win-lose behave identically.
- **Game-mode bar** (`components/game-mode-bar.tsx`): whenever you're editing a
  game document with no editor panel open (and not playing), a compact
  Simple/Graph/Blueprint/Code switcher plus a Play button sits at the bottom of the
  canvas. It hides once an editor is open (that panel already has the switcher).

## Fixes
- None (feature release).

## Internal / tests / docs
- New specs: `tests/blueprint-games.spec.ts` (both Blueprint games author, compile
  to real gameplay code, and play in the real runtime) and
  `tests/game-mode-bar.spec.ts` (bar shows on a game canvas, opens Blueprint, and
  hops to Code). Deterministic harness confirms the Blueprint Platformer matches
  the block version and Breakout's counter/win/lose.
- Arcade help doc, learnings updated.

## Known / follow-ups
- **Blueprint Slingshot** needs new engine nodes: the palette has no pointer-drag
  input and no clean projectile respawn, so a true drag-aim Slingshot isn't
  expressible yet. Planned unlock: a small pointer node group (pointer-down event +
  pointer x/y/pressed data).
- The blueprint **compiler** already supports `hit`/`touching`/`leaveScreen`
  events, but the palette's node list doesn't offer them yet — a DX follow-up so
  users can author collision rules the way the samples do.
