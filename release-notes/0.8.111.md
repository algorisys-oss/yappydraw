# 0.8.111 — Script → comic panel

**Date:** 2026-07-19

## Highlights

- Write a few lines of dialogue and get a drawn comic panel: figures posed from
  what they say, turned toward each other, with speech balloons above them in the
  correct reading order.

## Features

- **`api.createComicPanel(script, opts?)`.** A screenplay-style script —

  ```js
  Yappy.createComicPanel(`Alice: Hi Bob!
  Bob: I think we should ship it.
  Alice: ARE YOU SURE?`);
  ```

  — becomes a laid-out panel. Each `Name: line` row is one balloon. Also accepts a
  structured array: `[{ speaker: 'Alice', text: 'Hi Bob!' }]`.

  - **Poses come from the text.** A greeting waves, ALL CAPS or `!!!` shouts, `:-(`
    is sad, `lol` laughs, "maybe" thinks, "you" points, a bare "?" shrugs, anything
    else stands neutral. Competing cues resolve by priority rather than blending, so
    "HI THERE!!!" shouts instead of waving.
  - **Characters are arranged, not just placed.** Conversational partners end up
    standing next to each other and are mirrored so they turn inward — two people
    accusing each other genuinely point at one another.
  - **Balloons follow comic conventions.** Read top-down then left-to-right, never
    overlapping, each one positioned so its tail can point down at its own speaker.
  - **Options:** `x`, `y`, `figureHeight`, `frame`, `monochrome`, `fontSize`, and
    `variants` to pick a figure per speaker (`{ Alice: 'female', Sam: 'boy' }`).

  Up to 4 speakers per panel, one pose each. The panel is grouped, so it moves and
  undoes as one unit, and every part stays editable afterwards.

## Internal / test changes

- New `library/comic/`: `pose-rules.ts` (the text→pose table), `panel-layout.ts`
  (character ordering and balloon layout — pure and deterministic) and `index.ts`
  (element composition). Built on the existing stick-figure library, `speechBubble`
  shape and text measurement rather than new art.
- Ports the remaining two algorithms from the Microsoft Comic Chat study
  (`docs/microsoft-comic-chat-algorithm.md`) — §4.1 pose rules and §4.3/§5.2
  placement and balloon layout. The first idea from that study shipped in v0.8.110
  as connector routing channels.
- 34 unit tests: rule priority, script parsing, character ordering, balloon reading
  order and non-overlap, shared ground line, tail reach, and idempotency.
- Two gotchas worth remembering, both recorded in `docs/learnings.md`: `generateId`
  derives its next number by scanning the store, so a generator creating many
  elements before committing must thread a `batchIds` set through or every id
  collides; and imported SVG paths default to the `architectural` render style, so a
  generated panel must force the document's current style to avoid mixing rough
  balloons with clean figures.

## Breaking changes / migration

None. New API only; no document format change.
