# 0.8.107 — Clean construction guides (no stray arrowheads) (2026-07-16)

## Highlights
- **Rectangular Grids and scripted lines are now plain lines** — inserting a construction grid (or drawing lines via the scripting API) no longer sprouts little arrowhead/chevron end-caps. The separate **arrow** tool is what adds a head.

## Fixes
- **Stray arrowheads on `createLine` / `createRectGrid`.** `window.Yappy.createElement` fell back to `endArrowhead: 'arrow'` for *every* element type, so plain lines, bezier curves and construction grids created through the API (and the UI's **Vector Tools → Rectangular Grid**) rendered arrowheads — inconsistent with the interactive line tool, which draws a plain line. Lines/beziers/non-connector shapes are now headless by default; `createArrow` (type `arrow`) still gets its head, and an explicit `endArrowhead` option still wins.

## Internal / tests / docs
- New regression spec `tests/line-arrowhead-default.spec.ts` — asserts `createLine`/`createRectGrid`/`createBezier` are headless, `createArrow` keeps its head, and an explicit override wins.
- Root-cause fix in `frontend/src/api.ts` (`createElement`): `endArrowhead … ?? (type === 'arrow' ? 'arrow' : null)`.
- Retroactively removes the need for the `startArrowhead:null, endArrowhead:null` workaround that five logo specs (`propeak-1`, `algorisys-logo`, `algorisys-poster`, `mono-logo`, `propeak-variations`) were carrying.
- Bug-fix log (#172) and learnings updated.

## Breaking changes / migration
- None. Existing calls that explicitly set `endArrowhead` are unaffected; only the *default* for non-arrow types changed from `'arrow'` to none (which matches the interactive line tool).
