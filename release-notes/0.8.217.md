# 0.8.217 — The cylinder is a cylinder (2026-08-22)

## Highlights
- Making a cylinder taller now makes a taller cylinder. It used to make a flatter
  ellipse, because the element box sized the shape's *cap* rather than the whole
  solid, and the barrel was separately clamped to half the short side.
- Both end circles take the perspective, from one **Cap Perspective** control.
  Previously only the far cap moved, so the angle sheared the shape instead of
  turning it.
- An unfilled cylinder reads as a solid: the far cap's hidden half is no longer
  drawn, and the stray line across the middle of a squat cylinder is gone.

## Features
- **Cylinder rebuilt as a tube inscribed in its box.** Width is the diameter,
  height is the whole solid (caps included). Resizing behaves the way the
  silhouette suggests it should.
- **New `capRatio` property — "Cap Perspective"** (2–100, default 25): the cap's
  along-axis radius as a percentage of its cross-section radius. 2 is almost
  edge-on, 100 is face-on. It applies to **both** caps.
- **`viewAngle` is now the axis direction** for a cylinder, labelled "Axis Angle".
  90° (the new default) is upright; 0° lays the can on its side; anything between
  gives a genuinely tilted tube with rotated cap ellipses. To tip a whole cylinder
  over in place, rotate the element — rotation turns the caps with it.
- **The control handle does both.** It rides the far cap's centre: swing it round
  the shape to set the axis, pull it out or push it in to flatten or open the caps.
- **`Yappy.createCylinder(x, y, w, h, opts)`** added to the API, with `capRatio`
  and `viewAngle` documented.

## Fixes
- **Bug #312 — a taller cylinder collapsed flat, and only one of its two circles
  moved.** Reported from a pillar drawing. One modelling mistake behind all of it:
  `cylinder` was a box-sized ellipse extruded by a `depth` clamped to
  `min(w, h) × 0.5`, with the near cap pinned at the box centre. Dragging a
  100-wide cylinder to 400 tall therefore produced a 100×400 ellipse with a 50px
  stub. The `database` shape, whose box genuinely is the whole drum, consequently
  looked more like a cylinder than the cylinder did.
- Two rendering defects from the same geometry: the barrel quad's end edges are
  chords through the cap centres and were being stroked, and the far cap was drawn
  as a full ellipse, so a transparent cylinder showed two crossed ovals.
- The tangent formula used `rx²/ry²` where it needed `rx/ry` — wrong for every
  extrusion that was not axis-aligned, which is why a diagonal cylinder never read
  as 3D. The new frame does not need it: in the tube's own coordinates the barrel
  meets each cap at its ±r poles.
- **Bug #313 — a property declared twice only ever wrote to the first
  declaration's shapes.** `supportedSelection()` narrowed writes using
  `properties.find(p => p.key === key)`. `renderStyle` had been duplicated for a
  while and had this latent; `viewAngle` now needs two declarations (a block's
  "View Angle", a cylinder's "Axis Angle"). It unions `applicableTo` across all
  declarations sharing a key.

## Internal / tests / docs
- `getCylinderFrame()` is the single source of truth for the cylinder's caps and
  barrel, shared by the geometry, the selection overlay, hit-detection and the drag
  handler — four places that previously re-derived the same formula independently.
  It solves a 2×2 system so caps plus barrel exactly fill the box, with a fallback
  for the degenerate diagonal-axis-in-a-square-box case.
- `ShapeGeometry` faces gained `noFill` alongside `noStroke`; the architectural 3D
  face loop now handles `path` faces via `fillPath`/`strokePath`. Verified in both
  sketch and architectural styles.
- `multi` geometry gained an optional `outline` — the silhouette of a multi-face
  solid as one closed path — so `shape-to-path` (and therefore node editing and
  boolean ops) converts the whole solid rather than whichever cap happened to be
  the first `path` face.
- New `tests/cylinder-geometry.spec.ts`: 9 tests pinning all three reported
  behaviours, the diagonal case, hidden-line removal, the silhouette, and the drag
  handle's distance ↔ cap-ratio round trip.
- Help: a Cylinder section in **Geometric Shapes** covering both controls, the
  handle and the rotate-vs-axis-angle distinction, plus a note in **Flowchart**
  distinguishing the fixed `database` drum from the adjustable cylinder.

## Breaking changes / migration
- Cylinders in existing drawings render differently, and in almost every case
  better: shape creation never wrote `viewAngle`, so a cylinder left alone has it
  `undefined` and picks up the new upright default. A cylinder whose angle was
  explicitly changed becomes a tilted tube at that angle rather than a sheared
  ellipse.
- `depth` no longer applies to `cylinder` and has been removed from its property
  panel — the box bounds the whole solid, so there is no free extrusion length to
  set. `capRatio` divides the box instead. The property is untouched for
  `solidBlock`, `perspectiveBlock` and `openBox`.
