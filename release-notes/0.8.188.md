# 0.8.188 — Zoom and pan work again in presentations and designs (2026-08-11)

## Highlights

- **Loading a presentation or design template no longer kills zoom and pan.** Reported as "when
  using any template, zooming and panning are completely disabled" — and every route was dead at
  once: <kbd>Ctrl</kbd>+<kbd>+</kbd>/<kbd>−</kbd>, <kbd>Ctrl</kbd>+scroll, the status-bar zoom
  buttons, the Pan tool and <kbd>Space</kbd>+drag. The view was being written correctly and then
  immediately snapped back to "fit slide".

## Fixes

- **Zoom and pan in paged documents (#293).** The canvas re-lays-out when the toolbar docks, zen
  mode toggles or a panel changes zone, and the last thing that layout does is redraw the canvas —
  which reads the view state. Solid therefore tracked the view as a dependency of the *layout*
  effect, so any zoom or pan re-ran it, and the layout re-fits the slide for a paged document. The
  view was set and unset within the same frame, so nothing appeared to happen.

  Fixed by untracking the layout call: the effect's real dependencies are still read explicitly, so
  it fires exactly as often as before, but the render can no longer smuggle the whole document in.
  Window resize and fullscreen changes still re-fit the slide — they call the same layout through
  their own listeners, outside any effect.

  Diagram templates were unaffected because they stay `infinite` documents: the same feedback loop
  existed there, it just re-drew instead of re-fitting. That is also why the bug read as "templates
  break zoom" rather than "paged documents break zoom".

## Internal / tests

- New `tests/paged-doc-zoom-pan.spec.ts` (4 specs): zoom sticks after loading both a presentation
  and a design template — and is still there 300ms later, since the old bug re-fit asynchronously
  and a read taken immediately would have looked fine; <kbd>Space</kbd>+drag pans; and a viewport
  resize still re-fits the slide. Three of the four fail on the pre-fix build.
- Verified against the docked-toolbar cycle (left/top/right/bottom/float) that the layout effect
  still reserves the correct edge at every position — the canvas rectangle is exact in all five.

## Breaking changes

None.
