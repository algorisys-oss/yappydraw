# 0.8.224 — Français, and a palette that could not be searched in it (2026-08-25)

## Highlights
- **YappyDraw speaks French.** All 543 interface strings, following Illustrator/Photoshop FR terminology so the vocabulary is the one French users already know.
- Writing it exposed a bug older than the translation: the command palette matched on a plain lower-case comparison, so a French keyboard could not type the names of the commands it was showing.

## Features

**Français.** The fifth interface language, joining English, Deutsch, Español and 日本語 — every command, shape name, shortcut description, menu entry, tooltip and settings label.

Terminology follows the French builds of the tools these features mirror, so a user who knows the operation elsewhere recognises it here: fill and stroke are *fond* and *contour*, a layer is a *calque*, a path a *tracé*, rasterize is *pixelliser*, create outlines is *vectoriser*, an artboard a *plan de travail*. Stacking order uses Illustrator's four verbs — *Premier plan*, *Rapprocher*, *Éloigner*, *Arrière-plan* — rather than a literal translation of "bring/send", which would have produced phrases no French user has seen in a drawing tool.

Also carried over: sentence case rather than English title case (*Premier plan*, not *Premier Plan*), guillemets « » for quoted text, the space French typography puts before `:` `;` `!` `?`, and infinitives for commands (*Annuler*, *Grouper*) as French menus use.

French plurals come out right, including the rule English does not share — **0 élément**, singular, where English says "0 elements".

It ships as its own 39.9 KB lazy chunk: nobody who is not reading French downloads it.

## Fixes

**#332 — The command palette could not be searched in the language it was displaying.**

Found while testing the French UI, and not French-specific: `searchCommands` compared with `toLowerCase()` and nothing else. Two invisible characters sat between what the user types and what the label contains.

*Apostrophes.* French labels use the typographic apostrophe U+2019 — *Tranche (zone d’exportation)* — which is correct French. An AZERTY keyboard types the straight U+0027. The two never matched, so every command containing *l’* or *d’*, a large share of them, was unreachable by typing its own name.

*Accents.* Typing `elements` did not find *Éléments*, `etoile` did not find *Étoile*. People type the unaccented spelling; nothing came back.

`foldForSearch` now strips combining marks and unifies apostrophe variants on both sides of the comparison. It only ever widens the match — every search that worked before still works. German and Spanish gain from it too: `losung` now finds *Lösung*, `simbolo` finds *Símbolo*. English command ids are still searched, so an English tutorial can be followed in a French interface.

## Internal / tests / docs

- **102 wrong apostrophes.** The first draft of `fr.ts` used U+02BC MODIFIER LETTER APOSTROPHE, which renders identically to U+2019 in every font but is classified by Unicode as a **letter** — it breaks word boundaries, sorting and search, and cannot be spotted by reading the screen. Found by counting characters rather than looking. Normalised, with a test that fails if one returns.
- `fr-search.test.ts` also checks every interpolation placeholder survived translation (a dropped `{{ name }}` fails nothing, it just resolves to a label with a hole in it), that shortcuts and standard names stayed untranslated, and that the stored document name is still the literal `Untitled` while only its display string is French.
- That test cannot import `command-registry` — it pulls in the store — so it lifts `foldForSearch` out of the source and runs both over every French string, rather than keeping a copy that can silently drift. The guard was verified by breaking the shipped function and watching it fail.
- Help: a **Language** section, which had never existed despite four languages shipping. It covers where the picker is, that drawing text and shortcuts are never translated, that search ignores accents and apostrophes, and that untranslated strings fall back to English rather than going blank.
- `locale-resolution.ts` credited `scripts/i18n-check.mjs` for maintaining coverage numbers. That script does not exist and never did; coverage is in fact guaranteed by the type, since a dictionary typed `Dictionary` rather than `Partial<Dictionary>` cannot compile with a key missing. Comment corrected to describe the real mechanism.

## Breaking changes / migration

- None. A browser set to French now resolves to the French interface on first run instead of falling back to English; any explicit language choice already saved is unaffected.
