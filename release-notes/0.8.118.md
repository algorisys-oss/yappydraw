# 0.8.118 — Comics wear the right face

**Date:** 2026-07-20

## Highlights

- An emotion cue in a comic script now sets the character's **expression**, not just
  their body language. `Ann (angry):` looks angry.
- Comic figures are properly restyleable — select one and change its face or hair from
  the Properties panel like any other figure.

## Fixes

Comic Studio builds its characters from the same stick-figure library, so it picked up
faces automatically in 0.8.116 — but only the visible half. Three defects, one cause:
the comic generator carried a hand-copied version of the library's insert logic (it has
to, so a whole panel lands as one undo step), and that copy never got the two steps the
original gained when faces shipped.

- **Changing a comic figure's expression silently deleted its hair.** The generated
  figures carried no record of what they were wearing, so a restyle treated "not
  specified" as "none". Now fixed — changing the expression leaves the hair alone, as it
  already did for library figures.

- **The Face & hair preference was ignored in comics.** Setting, say, Bun + wink in the
  panel had no effect on a generated comic; figures always used the pose default.

- **Monochrome comics kept coloured hair.** Mono stripped the colourful props but not
  solid hair fills.

- **An emotion cue set the pose but not the face.** `Ann (angry):` selects a tense,
  hunched pose that was drawn with a *scared* expression — so the clearest possible
  statement of mood produced the wrong face. Every emotion now carries an expression
  alongside its pose:

  | Cue | Expression |
  |---|---|
  | Happy · Waving · Love | Happy |
  | Laughing · Idea | Excited |
  | Sad | Sad |
  | Angry | Angry |
  | Shouting | Surprised |
  | Thinking · Unsure · Asking | Confused |
  | Neutral · Pointing · Presenting | Neutral |

  The same precedence applies as for poses: an inline cue beats the panel's emotion
  picker, which beats what the words suggested. A pose chosen by the **words** keeps the
  expression it was drawn with — so “lol” still arrives grinning without the emotion
  table having to spell that out.

## Internal / test changes

- Extracted `prepareStickFigureElements(assetId, opts)` from `insertStickFigure`: it
  applies face/hair, tags roles, normalises the outline weight, honours monochrome and
  links each face/hair mark to its head — returning ready-to-commit elements with **no
  store writes**, so a generator that must be one undo step can compose it instead of
  re-implementing it. `insertStickFigure` and the comic generator now share it, so
  neither can drift again. What's left in the comic path is only what is genuinely
  comic-specific: mirroring, the document render style, and the panel group.

- `EMOTIONS` in `comic/pose-rules.ts` gains a `face` column, read by the new
  `faceForEmotion()` and threaded through `planComicPanel` (which now also returns
  `faces` per speaker).

- 3 new Playwright tests (comic figures are linked and restyleable, a restyle keeps the
  hair, a mono panel has no filled hair) and 3 new unit tests for `faceForEmotion` —
  64 in the comic suite, 218 unit tests overall.

- `docs/learnings.md`: a deliberate copy of a function is a silent subscriber to every
  future change to the original; and when a feature gains a new dimension, audit every
  selector that used to fully determine the old one.

## Breaking changes / migration

None, though comics generated with an explicit emotion cue will now look different — the
face matches the cue instead of the pose's authored default. That was the bug.
