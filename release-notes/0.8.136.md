# 0.8.136 — Crop stops distorting images; swatches you can see and remove (2026-07-21)

## Highlights
- **Cropping no longer stretches the image**, and crops now land where you drew them.
- Colours saved from the OKLCH picker appear **in the palette**, with an **×** to remove them.
- Inserting an image leaves you on the **Select** tool.
- Layers panel text is legible in dark mode.

## Fixes
- Bug #194: **cropping changed an image's aspect ratio, and cropped the wrong region.** Two
  separate faults compounding:
  1. **Unit mismatch.** `enterCropMode` converts a stored crop from source pixels into
     element-local coordinates, but `exitCropMode` wrote the element-local rect straight back into
     `el.crop` — which the renderer reads as *source pixels*. On a 1500px photo displayed 500px
     wide, the committed crop covered a third of the region you selected.
  2. **The frame was never resized.** The renderer draws the cropped source rect into the
     element's existing `width`/`height`, so cropping a wide strip out of a tall photo stretched
     it back over the old frame.

  Now the crop is mapped back to source pixels *relative to the region currently displayed* (so
  repeated crops compose correctly) and the frame shrinks to the cropped region. Verified: a 2:1
  image cropped to a 1:1 region yields a 1:1 frame with the crop stored as source pixels.

- Bug #195: **the Layers panel was barely readable in dark mode.** The panel title measured
  **1.30:1**. Root cause: `var(--text-color, #0f172a)` — and **`--text-color` is defined nowhere
  in the codebase**, so every use silently fell back, pinning a near-black literal regardless of
  theme. Six files referenced it; all now use `--text-primary`. Also fixed on the selected layer
  row: the drag handle (1.31–1.45:1) and the layer name (2.54:1 hardcoded white on the accent).

- Bug #196: **saving a colour from the OKLCH picker looked like it did nothing.** It was stored
  correctly, but only surfaced in the Swatches panel — a different, closed panel — so the palette
  you pressed the button in never changed. Saved swatches now render under a **SAVED** row in the
  palette, and saving returns you there so the result is visible.

- After inserting an image the Image tool stayed armed, so the next click reopened the file picker
  instead of letting you move what you just placed. Both insert paths (upload and placeholder) now
  select the new image and switch to Select.

## Features
- **Remove a saved swatch** with the × on its chip — saved colours are often experiments, and
  getting rid of one shouldn't mean opening another panel.
- **Crop is scriptable**: `Yappy.enterCropMode(id)`, `Yappy.updateCropRect(rect)`,
  `Yappy.exitCropMode(apply)`, `Yappy.setCropAspect(ratio)`. Previously crop existed only as a
  UI mode with no API.

## Internal / tests / docs
- New `tests/image-and-swatches.spec.ts` — crop aspect/units, swatch add + remove round trip, and
  the tool switch after image insert.
- The Layers panel had never been covered: the 0.8.134 audit sweep only visits nine named
  surfaces, and that panel wasn't one of them. Worth remembering that the sweep proves the
  surfaces it opens, not the app.

## Breaking changes / migration
- Applying a crop now resizes the image's frame to the cropped region. Existing crops in saved
  documents are unaffected; re-cropping one maps correctly from its current view.
