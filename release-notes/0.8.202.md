# 0.8.202 — Outlined text stays the text, and Select stops editing nodes (2026-08-18)

Both changes come from one piece of outside feedback, sent with three screenshots: a word, the
same word after **Create Outlines** — visibly chewed, polygonal bowls, ragged serifs — and a
third after *Smooth* made it worse. No edit had been made in between. The same message asked the
obvious follow-up question: *"Is it possible that we have a selection tool and a node tool as two
different tools like in all other softwares? Most of the time you just have to move objects
around, and in complex objects there are unnecessary nodes that are distracting."*

## Highlights

- **Text → Outlines is now visually lossless.** Converting a word gives you the same letterforms
  you were looking at, in a sketch-style document too.
- **The Select tool no longer shows path anchors.** It moves, resizes and rotates. Nodes belong to
  the Node tool — press `N`, or **double-click the path**.

## Fixes

### Outlined text was being roughened

Glyphs are drawn by the font renderer, which the sketch style never touches. A `path` in sketch
style is redrawn through rough.js, contour by contour. Converting text to outlines carried the
text's `renderStyle` across, so the outline started honouring a style the text had been ignoring —
and the letters changed shape at the moment of conversion.

Outlines now always render clean (`renderStyle: 'architectural'`), whatever the source text was.
Sketch is still one click away in the Style control if you want a hand-drawn wordmark. The
"smoothing made it worse" third screenshot had the same root cause: smoothing contours that were
already being drawn wobbly compounds it.

### The Select tool drew — and grabbed — every anchor

Selecting a path painted every anchor and Bézier handle. On a four-point curve that reads as
helpful; on an outlined word or an imported icon the artwork vanishes under hundreds of squares
nobody asked for.

It was not only cosmetic. Anchors were hit-tested **ahead of** the bounding-box resize grips (by
design, so an extreme anchor would beat the corner handle sitting on top of it). On any path whose
anchors touch its own bounding box — every outlined glyph — grabbing a corner to scale the object
silently dragged one node instead. Both halves are gone.

## Features

- **Double-click a path → Node tool.** The same gesture that opens a group, a symbol or a compound
  shape now opens what a path contains: its nodes. `N` and the Vector Tools → **Nodes** button
  still work.
- **Alt-click a node to convert it (corner ↔ smooth), Ctrl/⌘-click to delete it** — inside the Node
  tool, where those gestures now live. Previously they existed only under the Select tool, or as
  buttons on the Node options bar.
- **Right-click / long-press a path still offers node operations** without leaving the Select tool:
  *Make Smooth / Corner*, *Delete Anchor*, *Insert Point Here*. A menu is invisible until you ask
  for it, so it costs no clutter.

## Internal / tests

- `getPathHandleAtPosition` (new, exported from `utils/handle-detection.ts`) hit-tests a path's
  anchors and handles on demand. `getHandleAtPosition` no longer returns `path-*` handles at all.
- `frontend/src/utils/select-tool-path-nodes.test.ts` — asserts the Select tool paints no anchor
  squares, still paints its transform chrome, and that a click on a corner anchor resizes.
- `tests/text-outlines.spec.ts` — new case: outlining sketch-style text yields an architectural
  path.

## Migration notes

Documents are untouched — this is render and interaction behaviour only. Existing outlined-text
paths keep whatever style they were saved with; re-outline, or flip the Style control, to get the
clean letterforms. If you had been dragging path nodes with the Select tool, press `N` or
double-click the path first.
