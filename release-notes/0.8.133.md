# 0.8.133 — Accessible button contrast; P3 palette by default (2026-07-21)

## Highlights
- Every filled primary button (Done, Save, Export, …) now meets **WCAG AA** in both themes —
  **19 of them were failing**, and hovering made it worse rather than better.
- The colour palette defaults to **P3 Wide-Gamut** on displays and browsers that support it.

## Fixes
- Bug #191: **filled primary buttons failed AA contrast in every state, both themes.** Reported
  as a hover issue on Settings → Done; measurement showed the hover was the smaller half.

  | State | Before | After |
  |---|---|---|
  | light rest | 3.68 ✗ | **5.17 ✓** |
  | light hover | 3.21 ✗ | **6.70 ✓** |
  | dark rest | 2.54 ✗ | **7.36 ✓** |
  | dark hover | 2.44 ✗ | **10.38 ✓** |

  Two causes. `--primary-color` is tuned for borders, icons and active states, where a lighter
  blue reads better; used as a *button fill under white text* it only reaches 3.7:1. And the
  hover used `opacity: 0.9`, which fades the whole element toward the panel behind it —
  lightening the fill while the label stayed white, so hovering *lowered* contrast.

  New `--btn-primary-bg` / `--btn-primary-bg-hover` / `--btn-primary-fg` tokens, separate from
  `--primary-color` so the two roles can differ. Light themes use a deeper blue with white text;
  dark themes invert to a light accent with dark text, because white on light blue is only
  2.5:1. Hover swaps the fill rather than fading it, so contrast **increases** — and in dark
  mode hover goes lighter, since darkening would drop the button below the 3:1 non-text
  threshold against the panel.

  Applied across all 19 affected rules in 13 files: Settings/AI/Rocket Done, Save, Export
  confirm, unsaved-changes Save, video submit, cloud primary, menu primary, load/export action
  triggers, and the selected-state chrome (`.scale-btn.active`, `.dropdown-item.active`,
  `.command-palette-item.selected`, `.vt-on`, provider buttons). Also added the `:focus-visible`
  ring the Done button never had.
- The command palette's category label no longer fades to `opacity: 0.8` on the highlighted row
  (3.89:1 in light mode). Its 11px uppercase treatment already carries the hierarchy.

## Features
- **P3 Wide-Gamut is the default palette.** Richer colour on modern displays, with an automatic
  fallback: `defaultPaletteId()` checks `CSS.supports('color', 'color(display-p3 1 0 0)')` and
  serves the sRGB palette where P3 isn't understood. This guard matters because an unparseable
  value assigned to `ctx.fillStyle` is *silently ignored* by the canvas spec — it keeps the
  previous style rather than throwing, so an unsupported palette would have drawn shapes in
  whatever colour happened to be set last. An explicitly chosen palette is untouched.

## Internal / tests / docs
- New `tests/contrast.spec.ts`: measures computed foreground, background and backdrop for the
  primary buttons across both themes and both states, asserting 4.5:1 text, 3:1 surface, and
  `opacity: 1` (a faded element composites toward its backdrop, which is what caused this).
  Verified to fail against the original CSS at 3.68:1.
- Also asserts the P3 default, skipping itself on browsers without display-p3 support rather
  than reporting a false failure.

## Breaking changes / migration
- New documents start on the P3 palette. Existing preferences are unaffected, and the palette
  picker still offers every option.
