# 0.8.114 — Narration captions

**Date:** 2026-07-19

## Highlights

- Caption boxes for comic panels — the "MEANWHILE…" box that sets a scene without
  putting anyone in it.

## Features

- **Narration captions.** Start a line with `*`, or wrap it in `[ ]`:

  ```
  * Friday, 5pm
  Ann: Did we ship it?
  [MEANWHILE...]
  Ben: ON IT
  ```

  A caption belongs to the panel rather than to a person, so it:

  - puts **nobody** in the scene (no figure is drawn for it),
  - never starts a new panel on its own, and doesn't count toward the four-character
    limit,
  - sits at the panel's **top-left** with no tail, where the existing reading-order
    rule places it ahead of the balloons beside and below it.

  Rendered as a plain box with left-aligned text. Works in Comic Studio and via the
  API.

  This mirrors Comic Chat §8, where IRC "/me" action messages became narration boxes
  and balloons laid out around them. With this, a single strip can carry the whole
  comic vocabulary: caption, speech, thought cloud and whispered aside.

## Fixes

- **Captions rendered as nothing.** `planComicPanel` narrowed its utterances to those
  whose speaker was in the cast — a filter written when every line had a speaker.
  Captions have none, so each was silently dropped: the balloons appeared and the
  captions did not. Speaker-less lines are now kept.

## Internal / test changes

- 5 new unit tests (both caption syntaxes, casting nobody, joining rather than
  breaking a panel, not counting toward the cast limit, and pinning left / reading
  first) — 55 in the comic suite, 167 overall.
- Verified in the running app: one strip renders caption → speech → thought cloud →
  caption → whisper → shout.
- Recorded in `docs/learnings.md`: a filter that encodes an assumption ("everything
  has a speaker") silently drops the next data shape, and the layout tests couldn't
  catch it because they bypass that filter.

## Breaking changes / migration

None. Scripts without `*` or `[ ]` lines behave exactly as before.
