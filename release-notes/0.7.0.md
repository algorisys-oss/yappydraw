# 0.7.0 — Game Engine: variables, sound, physics & the node graph (2026-07-05)

The game builder grows up. 0.6.0 shipped the Flash-style WHEN→DO builder; 0.7.0
is the engine push on top of it — **variables & conditions, built-in sound,
platformer physics, Scratch-style messages, a Variables panel**, and a
full-screen **node/wire Graph** view where every rule is a node you can now
**edit right in place**. It's all still one model: blocks and nodes are two views
over the same behaviors, compiling to the same `game.*` runtime that the editor
and exported HTML both run.

## Highlights
- **Variables & conditions** — hold lives/health/ammo/timers, react to them, and
  gate rules with *only if* (two opposite conditions = if/else).
- **Sound, no files** — arcade SFX (coin, jump, hit, powerup, explosion, win,
  lose…) and looping background music, synthesised in the browser; works offline
  and in exported games.
- **Physics for platformers** — gravity, jump, and *while touching [Ground] →
  land* so sprites rest on platforms instead of falling through.
- **Messages & logic** — *broadcast a message* / *when I receive […]* wires any
  sprite to any other (a button to a door, a death to a game-over everywhere).
- **Variables panel** — declare vars with a starting value, rename one and every
  rule that uses it updates, undeclared-but-referenced names appear as one-tap chips.
- **Game Graph** — a full-screen Blueprint/Scratch-style map of your whole game:
  each rule is a node, broadcasts draw wires to receivers, and **nodes are now
  fully editable inline**.

## Game Graph — the node view
- **Menu → Game Graph** (or the **Graph** button in the Behaviors panel) opens a
  pannable/zoomable full-screen node view. Every rule is a node (its sprite, WHEN
  trigger, DO actions, only-if); a *broadcast* draws a coloured **wire** to every
  node that *receives* that message.
- **Inline editing (new):** each node carries the same editable controls as the
  Behaviors panel — a WHEN trigger picker, DO action rows (＋ action / × remove),
  and a ＋ only-if guard. Change a dropdown or type a value and it writes straight
  to the game. No more bouncing back to the panel to edit a rule.
- **Wire it up by dragging:** drag a node's output port (the dot on a broadcasting
  rule) onto another node to connect the message — or drop it on a plain sprite to
  add a new "when I receive…" listener.
- **Lay it out:** scroll to zoom, drag empty space to pan, drag a node's header to
  move it (positions persist as `Behavior.graphPos`). ＋ Add rule drops a new node;
  the trash removes one. ▶ Play runs the game. Esc closes.

## Under the hood
- **One model, two views.** The graph and the panel edit the same
  `element.behaviors` / `store.sceneBehaviors`; `generateGameScript` compiles them
  unchanged for Play, Save, and HTML export. No second engine, no export changes.
- **Shared editors.** The trigger/action param editors were extracted from the
  Behaviors panel into a prop-driven `game/behavior-editors.tsx`, so the panel and
  the graph nodes render fully editable rules from one source of truth.
- The node `<For>` keys by the raw behavior reference, so editing one rule
  recreates only that card — the rest of the graph stays put.
