# 0.8.227 — supporting YappyDraw, an About box, and the build that had been broken for a week (2026-09-03)

## Highlights

- **Support YappyDraw**, as a labelled button in the top bar, a menu item, a command and an
  API call. Links out to pages the payment provider hosts, so no payment code, no third-party
  script and no server are added to a static app.
- **`/founders/`**, a prerendered page for the Founding Supporter programme: a fixed price, a
  counter, and an explicit statement that it is not a paid tier.
- **An About box** with version, authorship, licence, links, and the artists who test it.
- **The header wordmark is one word again.** It had been rendering as "Yappy Draw".
- **`npm run build` works.** It had failed at the prerender step on every run since v0.8.226,
  blocking every release.
- **The vibe-architecting article is published** at `/learn/vibe-architecting-yappydraw/`,
  with its six figures.

## Features

- **Support YappyDraw.** A tinted pill in the top bar with a heart and the words *Support
  YappyDraw*, plus an entry in the main menu, one in the ⋮ menu, a command-palette action and
  `window.Yappy.showSupport()`. It opens a small dialog listing the ways to contribute.

  The whole feature is **outbound links**. Razorpay's Standard Checkout needs a server to
  create an Order and verify the payment signature with the account's `key_secret`, and
  YappyDraw's production deploy is static — so instead the app links to pages the provider
  hosts, and the provider does the checkout, the verification and the receipt. Nothing is added
  to the bundle but a URL: no payment SDK, no third-party script on the canvas page, no CSP
  surface, nothing for the service worker to choke on when the app cold-loads offline, and the
  "nothing leaves your computer" promise stays literally true.

  Under 1180px the button drops its label and becomes the icon alone, so it cannot push the
  tools off the bar. The accessible name is unchanged either way.

- **`/founders/`, the Founding Supporter page.** A prerendered page at
  `yappydraw.com/founders/`, in the sitemap with its own canonical: the offer, a progress
  counter, what a founder gets, where the money goes, and what happens to their contact
  details.

  It is deliberately **not a paid tier**. There is no Pro version of YappyDraw and no feature
  behind a payment, which the About and Support dialogs promise in five languages. A paywall in
  an AGPL client is also unenforceable — any fork may delete the check and be entirely within
  its rights. So what a founder funds is the work continuing, and what they get back is the
  part a fork cannot copy: recognition, early access, a vote on the roadmap, and the community.

  The counter is a hand-edited file (`data/founders.ts`) and the page always prints the date it
  was last checked. A shared, durable count needs a server, and there isn't one; a number that
  moves without being tied to real sales is a false scarcity claim rather than a solution.

- **About YappyDraw.** Version (click it for What's new), tagline, *Developed by Rajesh
  Pillai*, *Supported by Algorisys Technologies Pvt. Ltd.*, the licence, links, and an
  **Artwork & testing** section crediting Anshika Shukla and Shriraj Naikwadi, whose drawings
  produce most of the entries in the bug log. Reachable from the main menu, the status bar, the
  command palette and `window.Yappy.showAbout()`.

- **A logo mark in the header.** Inline SVG rather than an asset file, so it inherits the theme
  through `currentColor` and the same `--logo-accent` as the wordmark, cannot disagree with the
  text beside it, costs no request and cannot 404.

- **The article is on the site.** `/learn/vibe-architecting-yappydraw/`, with its six figures
  and a self-referencing canonical.

## Fixes

- **The wordmark rendered as "Yappy Draw", two words** (#335). The markup was correct;
  `.text-logo` is a flex container with `gap: 4px` for the Beta pill, and flex applies that gap
  between every pair of children, including the two halves of the name.

- **Support and About did nothing in Zen mode** (#336). Both were mounted inside `<StatusBar />`,
  which sits under `<Show when={!store.zenMode}>`, so in Zen mode they ceased to exist and
  their menu items silently failed. Both now mount at the top level.

- **Close icons rendered 1.6px wide** (#337). As flex items inside fixed-size buttons the SVGs
  were shrunk rather than drawn small — the same crush as the Layers panel row actions in
  v0.8.222. Found by measuring, not by looking.

- **`npm run build` failed at the prerender step**, on every run since the article landed in
  v0.8.226. `readArticles()` treats every `.md` under `articles/` as a `/learn/` page requiring
  front matter, and the article folder's maintainer `README.md` had none. The reader now skips
  `README`, `CONTRIBUTING`, `NOTES` and `_`-prefixed files.

- **Article figures were never copied into the build.** The markdown references them relatively,
  which is what makes one file work on GitHub, in Medium and on the web — but nothing put the
  files at that path in `dist`, so the article would have published with six broken images. The
  prerenderer now copies each article's `images/` folder beside its page, browser assets only.

- **The bug-report link** in the menu pointed at `github.com/algorisys-oss/` rather than the
  repository.

- **A plain `npm run build` produced a site that disagreed with itself.** `vite build` loads
  `.env`; the prerender step runs as a separate process and did not, so the bundle could offer
  the Founding Supporter option while the prerendered `/founders/` page said it was closed. The
  prerenderer now loads the same environment, with real environment variables still winning.

## Internal

- `config/support.ts` validates every link before rendering it: `https` only, and only hosts on
  a small allowlist, so a mis-set environment variable cannot put a `javascript:` URL into an
  anchor in the editor. Five unit tests cover it, including hosts that merely look allowed
  (`razorpay.me.evil.com`).
- **No payment URL is committed.** The links come only from `VITE_SUPPORT_RAZORPAY_URL`,
  `VITE_SUPPORT_GITHUB_URL` and `VITE_SUPPORT_FOUNDERS_URL`, documented in `.env.example`. A
  fork building from the public mirror therefore ships no Support button pointing at us. An
  unset variable hides the feature rather than breaking it: **if the Support button is missing
  from a deployed build, the host is not passing these through to `vite build`.**
- Secrets are never `VITE_`-prefixed, since Vite inlines those into published JavaScript. The
  build output is swept for them.
- New strings are translated across all five locales (en, fr, de, es, ja).

## Upgrade notes

Set `VITE_SUPPORT_RAZORPAY_URL` and `VITE_SUPPORT_FOUNDERS_URL` in the deployment environment,
or the Support and Founders entries will not appear. This is intentional; see `.env.example`.
