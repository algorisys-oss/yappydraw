# 0.8.242 — Enter labels a shape; a hotkey mid-drag no longer jams the canvas (2026-09-10)

## Highlights
- **Press <kbd>Enter</kbd> on a selected shape to label it** — the Excalidraw/tldraw
  convention. Draw a box, press Enter, type. Only <kbd>F2</kbd> did this before, and F2
  needs <kbd>Fn</kbd> on most laptops.
- **Fixed a canvas-jamming bug:** brushing a single-key shortcut while dragging — `1`, `2`,
  `v`, `r`, Space, Delete, an arrow key — threw away the shape you were drawing and left the
  canvas unable to draw anything at all until reload.

## Features
- <kbd>Enter</kbd> opens the label editor on the selected element, with the existing text
  selected so typing replaces it. Same behaviour as <kbd>F2</kbd>, which still works. A
  freshly drawn shape is left selected, so "drag out a box → Enter → type" runs without
  returning to the mouse.
- Mindmap nodes keep the outline flow: <kbd>Enter</kbd> there still adds a **sibling**, as
  in every outliner. Use <kbd>F2</kbd> to edit a node's own text. That precedence is pinned
  by a test.
- Deliberately **not** added: starting a label by typing a bare letter, the way PowerPoint
  and draw.io do. Single letters are this app's tool shortcuts (`R` rectangle, `V` select),
  so type-to-replace would either cost tool switching or make it silently conditional on the
  selection — an invisible mode. Excalidraw and tldraw settled on Enter for the same reason.
  Reasoning recorded in `docs/type-to-label-spec.md`.

## Fixes
- **#360 — a tool hotkey pressed mid-drag stranded the drag and jammed the canvas.**
  `handlePointerUp` dispatches on `store.selectedTool`, testing `'pan'`/`'laser'`/`'eraser'`
  **before** the branches that finalise an interaction (`selectionOnUp`, `drawOnUp`). The
  app-wide single-key shortcut chain had no guard against running mid-drag, so a keystroke
  could change the tool out from under a live gesture; the release then took the wrong early
  return, the element was never committed, and `pState.isDrawing` — cleared only at the end
  of the branch that got skipped — stayed stuck `true`, blocking every later stroke.
  Delete/Backspace was the worst of them: it deleted the element being dragged.

  The chain is now inert while a pointer interaction is in flight, gated on a
  `__canvasPointerBusy()` probe. Guarded once at the head rather than per-branch, since
  every branch in it is disruptive mid-drag. Escape (cancel drag) and the Shift/Alt
  constrain and duplicate modifiers are unaffected — neither goes through this chain.

- The help doc had been describing a feature that did not exist:
  `help-docs/shapes/basic-shapes.md` said a shape could be labelled by selecting it "and
  start typing". Typing switched tools. It now documents <kbd>Enter</kbd> and <kbd>F2</kbd>,
  and says plainly that bare letters stay tool shortcuts.

## Internal / tests / docs
- `docs/type-to-label-spec.md` — new. Prior-art survey and a three-part design for faster
  shape labelling: F1 (this release), F2 auto-increment labels (`A`, `B`, `C` on create),
  F3 typing during the drag. F2/F3 are specified, not implemented.
- `tests/hotkeys.spec.ts` — three new tests: shortcuts inert mid-drag (A/B-verified against
  the pre-fix tree), Enter opens the label editor, and Enter's mindmap precedence.
- New hotkey row in the in-app help dialog (`editor-editShapeLabel`), translated across all
  five locales.
- Learnings recorded in `docs/learnings.md`; #360 logged in `docs/bugs/bug-fixes.md`.

## Breaking changes / migration
None. <kbd>Enter</kbd> previously did nothing on a non-mindmap selection, so nothing that
worked before behaves differently.
