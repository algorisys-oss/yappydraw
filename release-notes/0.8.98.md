# 0.8.98 — Big text that actually selects: font-box re-fit, no toolbar flicker, font size to 800 (2026-07-14)

## Highlights
- Enlarging a text element's font now grows its **selection/hit box** to match the glyphs — no more
  tiny handles stranded in the corner of huge text.
- The Font Size slider on the floating toolbar no longer **flickers** while you drag it.
- Font Size range now goes up to **800** (was 200).

## Features
- **Font Size slider max raised 200 → 800** for text and shape labels (`properties.ts`). The Transform
  panel's W/H were already uncapped.

## Fixes
- **Text box didn't re-fit when the font changed.** A text/richtext element's `width`/`height` were only
  recomputed when the *text* was edited, so changing `fontSize`/`fontFamily`/`letterSpacing` from the
  panel or quick toolbar left the hit/selection rect at the old size while the glyphs rendered large.
  `updateElement` now re-measures the box on any font-metric change (mirrors `commitText`; skips when the
  caller already sets width/height, so handle-resize is untouched).
- **Quick-toolbar flicker while dragging Font Size.** The floating toolbar anchors to the element's
  world width, which now changes every frame during a font drag. The toolbar's world anchor is frozen
  for the duration of the drag and settles once on release (pan/zoom still track).
- **Web/custom fonts stayed on the fallback face until the next redraw.** Added a `document.fonts`
  `loadingdone` → redraw hook (mirrors the existing image-load hook), so a font that finishes loading
  repaints immediately.

## Internal / tests / docs
- Profiled the font-change path end-to-end (Playwright + Performance API): apply ≈ 2 ms, full redraw
  13–28 ms even with 20 Google fonts loaded — the render path itself is not the bottleneck.
- Learnings + bug-fixes logged.

## Breaking changes / migration
- None.
