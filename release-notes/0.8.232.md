# 0.8.232 — The founders page stops selling and starts explaining (2026-09-04)

## Highlights
- The "1,000 of 1,000 founding places remaining" bar is gone from `/founders/`. The number was
  true and said the wrong thing; it is now behind a flag, off until enough places are taken for
  it to mean anything.
- The help sidebar is gone from that page too. It is a standalone page, and a shape list beside
  a payment decision is only somewhere else to click. The checkout button is untouched.

## Features
- `FoundersData.showCount` (`frontend/src/data/founders.ts`) controls the remaining-places bar.
  `false` by default. Set it to `true` when `claimed` is worth showing — nothing else changes,
  and the `asOf` date stamp and sold-out handling are unaffected either way.
- `buildPage` treats an empty `nav` as *no sidebar* rather than an empty one, and drops the
  search box with it (it only ever filtered the sidebar). Help, Learn and Examples are unchanged.

## Fixes
- **#342 — `/founders/` and `/learn/` served the drawing canvas on localhost.** Both pages exist
  only as prerendered HTML in `dist/`, and the editor has no client route for either, so
  `vite dev` answered with the SPA fallback: the editor, at a URL that is not the editor.
  Production was never affected. A dev-only Vite plugin now renders those pages on demand and
  serves them, so an edit can be seen without a full build.

## Internal / tests / docs
- New `frontend/src/prerender/vite-plugin-prerender-dev.ts` (`apply: 'serve'`). It loads `.env`
  into `process.env` the way `scripts/prerender.ts` does, so dev and the build agree about
  `VITE_SUPPORT_FOUNDERS_URL` — without it, dev said the programme was not open while the built
  page offered checkout.
- `docs/learnings.md`: accuracy and meaning are two separate reviews; a shared page shell puts
  chrome on pages that are hurt by it.

## Breaking changes / migration
- None. `showCount` is a new required field on `FoundersData`, which has exactly one instance,
  in the same file.
