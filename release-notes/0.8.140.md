# 0.8.140 — Finishing a crop releases the Crop tool (2026-07-21)

## Highlights
- After cropping, clicking the image no longer looks like the crop was undone.

## Fixes
- Bug #204: **applying a crop left the Crop tool armed**, so the next click on the image dropped
  straight back into crop mode. Because crop mode now (correctly, since 0.8.139) expands the
  element to show the whole picture while editing, that re-entry looked exactly like the crop
  being discarded — the original image reappeared along with the crop bar. Continuing and applying
  cropped it again, so nothing was actually lost, but the behaviour was alarming and easy to read
  as data loss.

  Finishing a crop — Apply *or* Cancel — now switches to the Select tool and selects the image, so
  it can be moved or resized straight away. Same reasoning as the image-insert fix in 0.8.136: a
  modal edit on a single object shouldn't leave its tool armed.

## Internal / tests / docs
- `tests/image-and-swatches.spec.ts` asserts the tool, the selection and the applied crop after
  finishing, so the tool can't silently stay armed again.

## Breaking changes / migration
- None. Cropping several images in a row now needs the Crop tool re-picked between them
  (<kbd>Shift</kbd>+<kbd>C</kbd>).
