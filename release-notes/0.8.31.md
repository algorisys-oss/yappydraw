# 0.8.31 — Real UML class diagrams from the DSL, on-canvas *and* in exported SVG (2026-07-09)

## Highlights
- Mermaid `classDiagram` and the native text DSL now produce **article-grade UML
  class diagrams** end-to-end: populated attribute/method compartments, every class
  present, and distinct UML arrowheads — and these now survive **SVG export**, not
  just the on-screen canvas.
- New **headless CLI**: `npm run render:dsl -- diagram.ysl -o diagram.svg` renders a
  `.ysl`/`.mmd` to SVG with no manual browser juggling.

## Features
- **YSL class members (Gap 4).** A `[class]`/`[interface]` node's `{ … }` block now
  accepts `attributes:` and `methods:` keys (`;`-separated members), e.g.
  `Subject [class] "Subject" { attributes: "-count: int", methods: "notify(data)" }`.
- **Headless DSL → SVG CLI (Gap 6).** `scripts/render-dsl.mjs` (`npm run render:dsl`)
  boots a headless Chromium, imports via `window.Yappy.importDSL`, and writes
  `exportSVG`. Supports `--url` (reuse a running instance), `--port`, `--selected`,
  and `-o -` (stdout).
- **UML arrowheads in exported SVG (Gap 3, export half).** `triangle` / `diamond` /
  `diamondFilled` now export as the proper hollow-triangle / hollow-diamond /
  filled-diamond polygons instead of a generic open-V.

## Fixes
- **`classDiagram` members never parsed.** `class Foo {` with the opening brace on the
  *same line* (Mermaid's canonical form) didn't match the class-definition regex, so the
  body was mis-parsed and members leaked into a bogus class while the real class stayed
  empty. The parser now opens the multi-line block from a trailing `{`.
- **Member compartments missing from exported SVG.** `exportToSvg` is a separate
  renderer that only drew the box + class name. Added a `umlClass`/`umlInterface` export
  branch (reusing the shared UML layout) that emits the header (stereotype + name), the
  attribute/method compartments, and the divider lines as vector.

## Internal / tests / docs
- Verified the whole pipeline headlessly with the new `render:dsl` CLI (imported the
  observer pattern, rasterized the SVG, confirmed a correct diagram).
- Gap 5 (per-node `borderRadius`/`fill`/`stroke` via the inline `{ }` block, and public
  `window.Yappy.updateElement`) was **already supported** — confirmed and documented.
- Updated help docs (`ysl-tutorial-doc`: class members + CLI; `uml-doc`: arrowheads),
  `docs/learnings.md`, `docs/bugs/bug-fixes.md`, and closed all six gaps in
  `docs/dsl-uml-gaps.md`.
