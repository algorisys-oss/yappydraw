# 0.5.2 — DSL parser strictness + full test-suite cleanup (2026-06-27)

## Highlights
- The DSL parser is now stricter with clearer errors (better DX for AI-generated DSL).
- The entire post-sweep test backlog (13 failures) is resolved — suite is green.

## Features / behaviour
- **Stricter DSL parsing** (a deliberate product choice):
  - `parseDSL` routes JSON arrays (`[…]`) to the JSON parser, so non-object JSON is
    rejected with a clear error ("DSL input must be a JSON object.") instead of
    silently falling through to the lenient text parser.
  - `importDSL` returns `null` when nothing meaningful is parsed (0 nodes) rather than
    an empty result object.

## Fixes
- (No new app bugs — see 0.5.1 for the `deleteSlide` fix.)

## Internal / tests / docs
- Resolved all 13 triaged test failures: 1 real bug (0.5.1) + 12 stale tests/contract
  updates. Highlights:
  - DSL specs: `nodeIdMap`/`edgeIdMap` are Maps (don't survive `page.evaluate`) →
    sizes computed inside the evaluate; `end` is a reserved word in the YSL text parser
    (like Mermaid) → test nodes renamed.
  - UI specs refreshed to current markup / driven via the public API:
    `productivity-features` (verify via `getSelectedTool`), `layer-background`
    (open panel via `toggleLayerPanel`, real colour input, honour `YAPPY_URL`),
    `export_shortcut` (Export menu item disambiguated by its Ctrl+Shift+E shortcut).
- `docs/bugs/known-test-failures.md` marked fully resolved.
- **Process:** `CLAUDE.md` "ship it" now requires a `release-notes/<version>.md` entry
  on every release (this folder + backfilled notes for 0.5.0/0.5.1).

## Breaking changes / migration
- DSL: callers relying on the old lenient behaviour (non-object JSON parsed as text,
  or `importDSL` returning an empty result on garbage) now get a rejection / `null`.
