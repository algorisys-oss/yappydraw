# 0.8.209 — the www hostname was a dead link, and it was our rule (2026-08-21)

## Highlights
- **`www.yappydraw.com` works again.** Every URL on the www hostname was 301-ing to a
  `Location` with no host in it, so the whole site was unreachable for anyone who typed or
  shared a www link — while the apex was perfectly healthy.

## Fixes
- **#309 — `%1` backreferenced the wrong `RewriteCond`.** The canonical-host rule in
  `frontend/public/.htaccess` read:

  ```apache
  RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
  RewriteCond %{HTTPS} on
  RewriteRule ^ https://%1%{REQUEST_URI} [R=301,L]
  ```

  Apache resolves `%N` against the **last `RewriteCond` that matched** — here `%{HTTPS} on`,
  which has no capture group — so `%1` expanded to the empty string:

  ```
  www.yappydraw.com/help/  ->  301  https://help/     (DNS failure)
  www.yappydraw.com/       ->  301  https://          (unparseable)
  ```

  Identical on IPv4 and IPv6, so not a CDN-node split. The conditions are ANDed, so the fix
  costs nothing behaviourally: write the capturing condition **last**.

## Internal / tests / docs
- Corrects a **wrong diagnosis recorded in three places** during v0.8.207–v0.8.208. The cause
  was ruled out by reading the first 60 lines of a 115-line `.htaccess` and not finding a www
  rule; the rule is at line 100. `CLAUDE.md`, the bug log and `scripts/verify-deploy.sh` all
  said it was an un-fixable Hostinger control-panel setting. They now say otherwise.
- **`CLAUDE.md` step 9 no longer lists any standing failure.** Both previous ones are retired
  (bug #280's cacheable `sw.js` was fixed on the host; this one was ours), and it now says
  explicitly not to wave any red line through as "known".
- The *Alternate hostname* check added in v0.8.208 is what pinned the exact malformed
  `Location`. It now verifies this fix instead of excusing the bug.
- Learnings recorded: "not in this file" is a claim about the whole file; Apache's `%N` points
  at the last matched condition; and a bug the browser hides needs a machine to see — typing a
  bare `www.example.com` autocompletes to an apex URL from history, so the hostname can be
  completely broken while every human who checks reports the site works.
