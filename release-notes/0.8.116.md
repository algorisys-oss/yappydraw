# 0.8.116 — Stick figures get a face

**Date:** 2026-07-20

## Highlights

- Every stick figure now has **eyes, a mouth and hair** — 12 expressions and 10 hair
  styles, pickable from the panel or the Properties panel, on dropped figures and
  animated ones alike.

## Features

- **Expressions (12).** Neutral, Happy, Sad, Angry, Surprised, Tired, Excited, Proud,
  Confused, Scared, Wink — plus None for the old blank head. Each is a recipe of eyes,
  brows and mouth, so an expression reads at thumbnail size as well as full page.

- **Hair (10).** Short, Curly, Spiky, Fringe, Long, Bun, Ponytail, Pigtails, Side swept
  — plus None. Solid styles (Short, Curly, Bun, Pigtails, Side swept) take a **hair
  colour**; outline styles follow the figure's stroke.

- **Solid head.** An opt-in white fill behind the face, for figures placed over busy
  artwork or a coloured background. Off by default, so existing figures stay
  see-through.

- **Pick it in two places, one control.** The **Face & hair** section lives at the
  bottom of the Stick Figures panel *and* in the **Properties** panel whenever a figure
  is selected. With nothing selected it sets what the next figure you add will wear (and
  the thumbnails update to match); with a figure selected it restyles that figure
  immediately.

- **Restyleable after the fact.** The face is derived from the head circle alone, so
  changing an expression still works after a figure has been moved, scaled, rotated or
  even ungrouped. Changing the expression leaves the hair alone, and vice versa.

- **Animated figures too.** A `stickRig` draws its face from the head's live position
  every frame, so it keeps up with the motion, follows a **Flip**, and comes along when
  you **Bake** the frame to editable paths.

- **Sensible defaults.** Poses ship with an expression that fits — *Sad* wears a sad
  face, *Jumping for joy* an excited one, *Thinking* a confused one (21 poses in all) —
  and the character variants pick their own hair: Man → Short, Woman → Fringe,
  Boy → Spiky, Girl → Pigtails. An explicit choice always wins.

- **Recolour by part** gains a **Hair** row alongside Outline and Accent. Eyes and mouth
  follow the outline colour, so a recolour never leaves the face out of step. Mono mode
  strips solid hair fills along with the accents.

- **API.**

  ```js
  Y.listStickFaces();        // 12 expressions
  Y.listStickHairStyles();   // 10 hair styles
  Y.setStickFace({ face: 'happy', hair: 'bun', hairColor: '#2b2118' }, ids);
  Y.setStickFace({ face: 'angry' });     // omitted fields left alone; defaults to selection
  Y.getStickFace(ids);                   // { face, hair, hairColor, headFill }
  Y.insertStickFigure('daily-waving', { face: 'wink', hair: 'ponytail' });
  Y.insertAnimatedFigure('walk', { face: 'happy', hair: 'long' });
  Y.recolorStickFigure({ outline: '#7c3aed', hair: '#2b2118' }, ids);
  ```

  `setStickFace` works on dropped figures *and* animated ones, so a whole cast's
  expressions can be driven from a script.

## Internal / test changes

- New `frontend/src/library/stick-figures/face.ts` is the single source of truth: a pure
  module (no DOM, no store, no Solid) that derives every mark from the head circle and
  emits it two ways — drawing primitives for the canvas renderer, role-tagged SVG for
  the library builder, panel previews and bake. One geometry pass, so the two figure
  systems cannot drift.

- Two new part roles, `face` and `hair`, alongside body/head/accent/prop. Dropped marks
  carry `sfHeadId` (which head they belong to, for multi-figure scenes) and the head
  carries `sfFace` (what it currently wears).

- Re-importing generated markup needed a **registration mark**: `svgToElements`
  normalises to the content bbox, so the regenerated face ships a throwaway head circle
  purely to recover the exact scale and offset, then discards it. New parts inherit
  `renderStyle`/`roughness`/`strokeStyle` from the head, and a rotated figure gets the
  rotation baked into the SVG rather than set per-part.

- Verified in **both** render styles: architectural draws the primitives through the
  clean canvas path (filled hair via `fillPath` + `strokePath`), sketch through
  rough.js.

- 7 new Playwright tests (`tests/stick-face.spec.ts`): parts land with the figure,
  restyle is idempotent, face and hair are independent, a restyle survives move+scale,
  regenerated marks inherit the render style, a rig carries its face into both styles
  and into a bake, and the API vocabulary is complete.

- `docs/learnings.md`: one pure geometry module with two dumb emitters when a feature
  spans two rendering systems; re-derivable anchors beat stored source geometry when
  restyling a flattened import; and the arithmetic behind fitting a cap over a circle
  (solve for the arc, don't hand-tune bezier control points).

## Breaking changes / migration

None, but note two behaviour changes:

- Library figures now drop **with a neutral face and variant-appropriate hair** instead
  of a blank head. Pick `None` for either if you want the old look.
- Figures dropped in **older saved documents** have their hair tagged `accent` rather
  than `hair` (they are already flattened paths). Restyling one of those adds new hair
  alongside the old; delete the old strokes or re-drop the figure.
