# 0.8.159 — Node tool, with real multi-node selection (2026-07-29)

## Highlights
- **A Node tool.** Vector Tools → Path → **Nodes**. Every anchor on the selected path is
  visible and editable, with the operations on a toolbar instead of hidden behind
  modifier keys.
- **Multi-node selection.** Click, Shift-click or rubber-band several nodes and move,
  reshape or delete them together — previously every operation acted on exactly one.

## Features
- Nodes are drawn by type: **squares are corners, circles are smooth**, so a path's shape
  is readable without selecting anything.
- Selection: click, `Shift`-click to add/remove, drag a box to rubber-band,
  `Ctrl+A` for all, `Esc` to clear (again to leave the mode).
- Operations across the whole selection: **Corner**, **Smooth**, **Delete** (or `Del`).
  A subpath is never reduced below two anchors.
- Dragging any selected node moves them all by the same delta — the whole drag is one
  undo step.
- `Alt`-click a segment inserts a node; dragging a segment bends it into a curve. Both
  already worked; they now have visible targets.
- **Convert to Path** on the bar when a plain shape is selected, so "make this rectangle
  curvy" is Convert → `Ctrl+A` → Smooth.
- API: `toggleNodeTool`, `setNodeSelection`, `allNodesOfSelection`, `getPathNodes`,
  `moveSelectedNodes`, `setSelectedNodesKind`, `deleteSelectedNodes`.

## Why
Path editing was already capable — anchors could be dragged, converted, inserted and
deleted — but it was ambient behaviour under the Selection tool bound to `Alt`-click and
`Ctrl`-click, with nothing on screen announcing it. It was also strictly single-anchor:
`handlePathNodeDrag` parses one `path-anchor-{sub}-{i}` handle and moves one anchor.
The capability existed; the product didn't.

## Fixes
- The node toolbar sat at the same top-centre position as the transform/angle HUD, which
  painted over it and hid the Smooth and Delete buttons. Moved clear, and the test now
  asserts each button is the topmost element at its own centre rather than merely present.

## Internal / tests
- New `utils/node-editing.ts` — set-based anchor operations, grouped into one history
  entry and one write per element (a loop of the per-anchor helpers could not do that).
- New `components/node-tool-overlay.tsx` + css, following the `*-tool-overlay` convention
  the other vector modes use; a **Nodes** entry in the Vector Tools panel's Path group,
  which brings exclusive activation and active-state for free.
- `editableSubpaths` / `writeEditableSubpaths` exported from `selection-handler`.
- `tests/node-tool.spec.ts` — 8 tests: the mode renders a node per anchor with its
  toolbar, click/Shift-click selection, rubber-band, multi-node drag moves every node by
  the same delta, Corner/Smooth across a selection, Delete never breaking the path,
  one-undo-per-drag, and the selection dropping on exit.
