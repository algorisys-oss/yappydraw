# 0.8.186 — The perspective grid starts working, and corners come to every path (2026-08-10)

## Highlights

- **The Perspective Grid stops being a picture.** It drew a horizon and two fans, and no drawing
  code had ever read it — every line over it was still aimed by eye. It now snaps drawing to its
  vanishing rays, with an adjustable strength that spans "a gentle bias" to "a hard lock", and
  1-, 2- and 3-point modes that persist across sessions.
- **Draw *on* a plane.** A box drag can be laid onto the left wall, right wall or floor, mapped
  projectively rather than bilinearly — so the centre of the shape lands where perspective
  actually puts it.
- **Live Corners for every editable path.** Rectangles already had four independent corners; pen
  paths, polygons, stars, traced artwork and anything converted to a path now round too, and
  non-destructively — the anchor you drag is still the original sharp corner.
- **The Shape Builder tells you what it is about to do.** A `+`/`−` badge follows the cursor and
  flips the moment you press <kbd>Alt</kbd>, instead of only after you have committed to a drag.

## Features

- **Perspective snapping.** With the grid on, the Line, Pen, Rectangle and freehand tools pull
  toward the nearest vanishing-point ray. **Snap strength** is one slider covering both
  behaviours people describe with different words: at 1 it is a true lock (a wall edge is exactly
  on the ray), at low values a whisper you can draw straight through, continuous in between.
  **Snap angle** sets how wide the capture cone is. Hold <kbd>Alt</kbd> to draw free-hand without
  turning anything off, and the ray you are snapping to lights up while you draw.
- **1-, 2- and 3-point modes**, a density control for how many rays are drawn, and draggable
  vanishing points. Every setting persists across reloads — re-placing two vanishing points each
  session was exactly the friction that kept the old grid a novelty. `Yappy.setPerspectiveGrid({
  mode: 3, snapStrength: 0.8, snapAngle: 8 })`, `Yappy.getPerspectiveGrid()`,
  `Yappy.resetPerspectiveGrid()`.
- **Draw on a plane.** Set **Draw on** to *left*, *right* or *floor* and a shape drag becomes a
  quad lying on that plane. It uses a projective map (a homography), not the bilinear warp used
  everywhere else — bilinear keeps the centre of the shape at the centre of the quad, which is
  precisely wrong under perspective.
- **Live Corners.** A **Corners** section in Vector Tools rounds path corners by a radius in px.
  It is non-destructive: the radius lives on the anchor and the rounded outline is rebuilt every
  time the path is drawn, so the anchors stay editable, moving a corner takes its rounding with
  it, and 0 restores the original exactly. With anchors selected in the Nodes tool only those
  round; otherwise all of them do. Radii self-clamp to what the adjacent segments can carry, and
  the trim distance is derived from the corner angle — so an obtuse elbow and a sharp spike at
  the same setting look like the same amount of rounding. Corners between curves round too.
  Applying it to a non-path shape converts it to a path first; rectangles and diamonds are left
  to their own controls. `Yappy.setPathCornerRadius(12)` / `Yappy.getPathCornerRadius()`.
- **Shape Builder mode badge.** A blue `+` for merge, a red `−` for delete, pinned to the cursor
  and matching the colour of the region highlight and the drag stroke. The touch Merge/Delete
  toggle drives it as well.

## Fixes

- **Perspective rays moved when you panned.** They ran from each vanishing point to *fixed points
  on the window edge*, so the "same" guide line was somewhere else after a pan — nothing that
  expected to be aligned to could have been drawn that way. Each line is now defined by two world
  points and clipped in screen space.
- **Shape Builder showed the wrong mode until you were already dragging.** <kbd>Alt</kbd> was read
  only inside the drag handler, so holding it while deciding where to start changed nothing on
  screen. It is now tracked on the keyboard too, and reset on window blur — Alt+drag is a
  window-manager gesture on several Linux desktops and the keyup never reaches the page, which
  left the tool stuck in delete mode.
- **A second segmented control broke the perspective spec's selector.** `.pg-seg` stopped being
  unique once the hint bar grew a plane picker; each control now carries its own modifier class
  rather than the test being pinned to sibling order.

## Internal / tests

- New `utils/path-corners.ts` — fillet construction, per-corner clamping, `maxCornerRadius`. The
  fillet is applied inside `anchorsToPathData`, the single serializer that rendering, filling,
  hit-testing, boolean ops and export all pass through, and that node editing deliberately does
  not. That is what makes Live Corners non-destructive by construction rather than by convention.
- New `utils/perspective-snap.ts` — grid model, guide rays, and the soft-snap curve
  `pull = smoothstep(closeness) ^ (4·(1−strength))`.
- 34 new unit tests across `path-corners`, `perspective-snap`, `perspective-plane`,
  `envelope-warp-projective` and `path-corner-radius`; new e2e coverage for the snap, the config
  popover's persistence, the corner panel (including that hit-testing follows the rounded
  outline) and the Shape Builder badge. 693 unit tests pass.
- Repo convention: throwaway artifacts (verification screenshots, scratch scripts) go in `temp/`,
  now gitignored — not the repo root.

## Breaking changes

None. `warp.projective` and `PathAnchor.cornerRadius` are both optional and absent on existing
artwork, which keeps its current behaviour.
