# 0.8.297 — Animations to and from PowerPoint (2026-11-01)

## Highlights
- **Build animations survive the trip to PowerPoint and back** — item 7 of the DeckCraft-based
  slides backlog (`docs/slides-feature-gaps.md`).

## Features
- **Export** (Editable shapes): each slide's build animations become PowerPoint effects on the same
  objects, in playing order, with Start (On Click / With Previous / After Previous; on-load first),
  duration, delay and repeat. Yappy presets map to the closest effect: Fade, Fly In/Out (same
  side), Bounce, Zoom, Spinner, Swivel, Wipe, Spin (by angle), Pulse, Grow/Shrink, Teeter. Motion
  paths, property and keyframe animations, morphs and hover triggers are left out, and a message
  says how many. Multi-piece objects are grouped; grouped objects animate their outermost group.
- **Import**: a PowerPoint deck's main animation sequence comes back as Yappy build animations,
  in order; effects before the first click play on load; unknown effects come in as a fade or
  pulse, with a warning. Not imported: motion paths, triggers, by-paragraph builds.

## Fixes
- Build order across objects on one layer followed element ids. Animations now carry an optional
  `order`, used first, so an imported sequence plays in PowerPoint's order; existing decks are
  unchanged.

## Internal / tests / docs
- `utils/pptx/anim-map.ts` (preset ↔ effect), `p:timing` writer and reader,
  `utils/build-order.ts` (shared by the show and the exporter). Checked against LibreOffice both
  ways.
- Tests: `anim-map.test.ts`, `build-order.test.ts`, PPTX timing round trip,
  `tests/pptx-animations.spec.ts`.
- Help: Animation (Animations in PowerPoint, mapping table), Workspace (PowerPoint).

## Breaking changes / migration
- None. `BaseAnimation` gains optional `order`.
