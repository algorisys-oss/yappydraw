# 0.8.160 — Node tool keys stay out of your typing (2026-07-30)

## Fixes
- **#229 The Node tool captured `Ctrl+A` and `Delete`/`Backspace` regardless of focus.**
  Its key handler is a capture-phase `window` listener — necessary to beat the canvas —
  but unlike the app's global hotkey handler it had no input-focus exemption, so typing
  in a text field, a layer-rename box or a dialog had those keys stolen. It now reuses
  the same exemption `app.tsx` applies (`INPUT` / `TEXTAREA` / `SELECT` /
  `isContentEditable` / font pickers / `[role="dialog"]`).
- `Ctrl+A` now falls through when no path is selected: with no nodes to take, it reaches
  the app's normal select-all instead of being swallowed. Inside the mode with a path
  selected it still means "all nodes", as it does in Inkscape's node tool.

## Tests
- Two additions to `tests/node-tool.spec.ts`: `Ctrl+A` then `Backspace` in a focused
  input clears the input and leaves both the node selection and the path untouched; and
  `Ctrl+A` with no path selected selects all elements.

## Known
- An icon-alignment regression has been reported in the toolbar. The existing
  `toolbar-grid-align.spec.ts` still passes, which means its coverage is incomplete — it
  only asserts the **wrapped** grid (`.toolbar-container.wrap`), never the horizontal
  bar. Being investigated.
