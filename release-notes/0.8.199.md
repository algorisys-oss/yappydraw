# 0.8.199 — width profiles (2026-08-15)

The last item from the character-illustration feedback: "add an option that allows users to change
the width profile of a line/stroke… uniform, thicker in the middle and thinner at the ends, or
gradually taper from one end to the other."

## Highlights
- **Width Profile picker** in the Properties panel: seven drawn ribbons — Uniform, Bulge, Waist,
  Taper out, Taper in, Chisel, Oval. Click one and the stroke takes that shape.
- **Shapes without fattening.** The widest point of every profile is the stroke weight you already
  set, so switching between them never changes how heavy the artwork reads.
- Also on the Command Palette ("Width Profile: …") and the API.

## Features
- Seven profiles, presented as **drawn swatches rather than names** — "chisel" and "waist" mean
  nothing until you've seen them. Each swatch renders the preset's own curve, so the picker and the
  applied result come from one function.
- **Per-element weights on a mixed selection.** Each stroke is shaped relative to *its own* weight,
  so a thin line and a thick one stay thin and thick.
- **Reports Custom.** Once you nudge width points with the Width tool, the row says Custom instead
  of pretending a preset is still applied.
- Applied in **one undo step**, fully reversible.
- Eligibility matches the Width tool, because they write the same field: a line or arrow is
  converted to a path first, and **closed shapes are refused with a message** rather than being
  given a profile that can never be drawn (the ribbon builder returns null for them).

## API
- `setWidthProfile(preset, ids?)` — `'uniform' | 'bulge' | 'waist' | 'taper-out' | 'taper-in' |
  'chisel' | 'oval'`. Returns how many elements changed.
- `getWidthProfile(ids?)` — the shared preset, or `null` for custom/mixed.
- `widthProfiles` — the list with labels and hints.

## Known behaviour, documented
- **Width points are absolute.** `widthProfile` stores px widths and existing documents are saved
  that way, so a profile is fitted to the stroke weight at the moment you pick it and does **not**
  rescale when you change *Stroke width* afterwards — pick the profile again to re-fit. Switching
  the field to multipliers would have been tidier but would silently rescale every existing drawing.
- Cutting a path still drops its profile: positions along the path don't mean the same thing on a
  shorter piece.

## Docs
- Illustrator-class Tools: a "Width profiles" section with the table of shapes, the
  never-heavier and per-element-weight behaviour, the Custom state, API snippets, and the absolute-
  widths caveat.
- Help search keywords for the profile names and the calligraphic/expressive-line vocabulary.
- `docs/learnings.md`: building presets on top of an absolute-valued field; why a picker for a
  visual property should draw the thing rather than name it; and two test bugs that first looked
  like product bugs.

## Tests
- `frontend/src/utils/width-profiles.test.ts` — 15 cases: every preset spans the path in order with
  positive widths, never exceeds the nominal weight, scales linearly with it, an unknown id yields
  nothing rather than throwing, each named shape actually has the shape it claims (bulge symmetric
  and fattest mid-path, waist thinnest mid-path, the tapers mirroring each other, chisel holding
  then falling), and detection round-trips every preset at any weight while refusing a hand-built
  profile.
- `tests/width-profiles.spec.ts` — 8 cases: all presets apply/read back without fattening, closed
  shapes refused and not silently converted, a plain line converted and profiled, one undo step and
  reversible, a mixed-weight selection keeping its relative weights, the picker showing the applied
  preset then Custom after a Width-tool edit, the picker hidden for a closed shape, and a profiled
  stroke rendering in **both** draw styles.
- 590 unit tests pass.

## This closes the feedback round
All eight items are now answered: four were bugs or gaps and are fixed (0.8.196–0.8.199), and four
already existed and are now documented and reachable. The one open question is whether "reusable
Boolean objects" meant the result staying editable (shipped in 0.8.197) or the cutter being left on
the canvas as a separate object — say which and the second is a small addition.
