# 0.8.38 — Escape closes every dialog (2026-07-09)

## Fixes
- **Some dialogs didn't close on Escape.** Nine dialogs either had no Escape handling
  or relied on an overlay `<div>`'s `onKeyDown` (which only fires when that div is
  focused — usually it isn't, so Escape did nothing). Added a shared `onEscapeKey` hook
  that installs a reliable window-level listener while a dialog is open, and wired it
  into: New Design, Save, Unsaved-Changes, Version History, Video URL, Repeat, Game
  Script, My Games, and New Game. Now every dialog closes on Escape.

## Internal / tests / docs
- New reusable `utils/use-escape.ts` hook (`onEscapeKey(isOpen, handler)`); the ~12
  dialogs that already had a window-level Escape listener are untouched.
- Verified end-to-end by driving the real menu — opening each dialog and pressing Escape
  — for design-size, version-history, new-game, my-games, and game-script (covering the
  props-based, signal-based, and store-getter close patterns), plus a no-regression check
  on a dialog that already supported Escape.

## Breaking changes / migration
- None.
