# 0.8.198 — diagonal and isometric grids (2026-08-15)

The next item from the character-illustration feedback: "along with the existing vertical and
horizontal grid options, add a diagonal grid option for better alignment and construction of
angled design."

## Highlights
- **Two new grid styles**: **Diagonal** (45° cross-hatch) and **Isometric** (30° both ways plus
  verticals). In *Settings → Canvas → Grid Style*, or the Command Palette ("Grid Style: …").
- **Snap follows the lines you can see.** On an angled grid, Snap to Grid puts points on the
  *intersections of the slanted lines* — not on square coordinates. A slanted grid that still
  snapped to squares would drop every point between its own lines.

## Features
- `Diagonal` — 45° in both directions, for angled construction.
- `Isometric` — 30° in both directions plus verticals, for boxes, 3/4 views and character
  construction. The vertical family is drawn but not snapped to: three families of parallel lines
  have no common intersection lattice, so the two 30° families define the snap.
- *Grid size* is the spacing between parallel lines, measured across them, so it means the same
  thing on every style.
- Reachable from the Command Palette for all four styles, and `Yappy.setGridStyle(style)` /
  `Yappy.gridStyles` on the API.

## Implementation notes
- New `frontend/src/utils/grid-lattice.ts` holds the family angles and the snap, so the renderer
  and the snapper cannot drift apart — two copies of `30 * DEG` is a bug that shows up as points
  sitting just off the lines.
- Angled grids **thin out** when you zoom out: below a legible on-screen gap the drawn spacing
  doubles (and doubles again), because three families a few pixels apart covered ~83% of the canvas
  at 5% zoom and cost ~1600 strokes a frame. Doubling specifically, so every drawn line was already
  there and the grid never appears to shift as you zoom.
- That thinning is **purely visual**. Snapping always uses the full grid size, so a point placed
  while zoomed out is still exactly on the lattice at 100%.

## Docs
- Workspace help page: a "Grid styles" section with the four styles, how snapping behaves on the
  angled ones, what *Grid size* measures, the zoom-thinning note, and API snippets.
- Help search keywords for the grid styles.
- `docs/learnings.md`: why a slanted grid is a lattice rather than two rounded axes, and why visual
  thinning must never touch the snap.

## Tests
- `frontend/src/utils/grid-lattice.test.ts` — 12 cases: the family angles per style, and for the
  angled lattices that a snapped point lands *exactly* on it, never moves further than one cell,
  is idempotent, keeps the origin fixed, and survives a zero/negative/NaN spacing without emitting
  NaN coordinates.
- `tests/grid-angled.spec.ts` — 6 cases: a line drawn on each angled grid lands on the lattice
  (checked by projecting both endpoints onto each family's normal), the square grid still snaps to
  square coordinates, all four styles are reachable from the palette, an angled grid doesn't become
  a wash at 5% zoom, and — the one worth having — thinning the drawn grid does **not** coarsen
  where things snap.
- 575 unit tests pass.
