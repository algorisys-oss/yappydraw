# 0.8.127 — Smart shapes actually recognise your stroke (2026-07-21)

## Highlights
- Hold-to-correct now works on essentially every attempt, including with a mouse or
  trackpad. It used to succeed on one try and silently do nothing on the next.

## Features
- **Reliable shape recognition.** Rectangles, squares, triangles, diamonds, circles and
  lines are recognised from deliberately sloppy strokes — wobbly edges, a corner left
  unclosed, or running past your own starting point. Measured over 200 synthetic attempts
  per shape at realistic mouse tremor (~3.4% of the shape's diagonal): rect 100%, square
  100%, diamond 100%, ellipse 100%, triangle 96%, line 86%. At double that noise it
  degrades gracefully, and the failure mode is falling back to freehand ink rather than
  snapping the wrong shape.
- **Open strokes are only ever turned into a line.** A wide arc or a half-drawn box stays
  as ink instead of being closed up into a shape you didn't draw.
- **Nothing is left selected after a snap.** 0.8.126 kept the corrected shape selected so
  the quick toolbar could target it, but with the pen tool still active those handles just
  sit on top of the drawing you're working on — and they aren't interactive while a pen
  tool is active anyway. Press `V` and click the shape when you want to edit it.

## Fixes
- Bug #182: smart shapes only recognised a stroke some of the time. The classifier read
  the corner count straight off RDP simplification and rejected anything above 4 corners —
  and RDP leaves redundant points on straight edges, so even a near-perfect rectangle
  reported 5 corners and was thrown out. Fit quality was never the problem; the count was
  unstable. See `docs/bugs/bug-fixes.md`.

## Internal / tests / docs
- `recognizeStrokeShape` rewritten around greedy corner reduction: RDP over-supplies
  corners, then they are removed one at a time (each step dropping whichever costs the
  least fit accuracy), producing a 3- and 4-corner candidate for any stroke that are then
  judged on fit against an absolute error gate.
- Triangle vs rectangle is decided by whether the stroke actually turns at the fourth
  corner (>45°), not by comparing fit errors — a quad fits a wobbly triangle nearly as
  well, so the error ratio (0.99–1.34 for genuine triangles) cannot separate them.
- `meanEdgeDist` now uses segment distance rather than perpendicular distance to the
  infinite line, which was flattering bad candidates exactly when the gate had to reject
  them. Line detection uses mean deviation with max as a backstop, plus a path-length
  check so a stroke that doubles back can't pass.
- Perf: fit scoring runs on a 240-point even subsample. Greedy reduction is
  O(corners³·points), so a ~2000-sample stroke cost 22ms — fired from the dwell timer with
  the pen still down, where a hitch is felt. Now 5.4ms, with no measurable accuracy change.
- New `frontend/src/utils/shape-recognition.test.ts` (22 tests, `bun test`), including
  recognition-rate assertions over 100 seeded attempts per shape — the property that
  regressed was reliability across attempts, which a single happy-path test cannot catch.
- Help docs: Smart Shapes section of the Drawing Tools doc notes mouse/trackpad support
  and the open-stroke rule.

## Breaking changes / migration
- None.
