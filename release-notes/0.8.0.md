# 0.8.0 — Blueprint: visual execution-flow scripting (2026-07-07)

## Highlights
- **Blueprint** — a full Unreal-style node-graph for game logic, alongside the
  Behaviors panel and Game Graph. Wire **execution** from Events through Actions,
  Branches, Sequences and Delays; drive values with a real **data-flow** layer
  (variables, literals, compare, math, random, sprite properties). Open it from
  **Menu → Blueprint (exec-flow)**. It compiles to the same `game.*` runtime as
  the blocks and runs alongside any behaviors you've built.

## Features
- **Scene-flow wires in the Game Graph (C.3):** rules that *go to a state* or
  *go to a page* now draw a dashed flow wire to a target pill (violet = state,
  sky = page), so level/scene flow is visible next to message wires.
- **Blueprint exec-flow model (C.4):** Event / Action / Branch nodes wired by
  execution edges — an event fires and flow runs along the wires in order; a
  Branch routes true/false. Persisted per document; Play compiles + runs it.
- **Per-sprite Blueprints (C.5):** an owner dropdown (Scene or a sprite). Sprite
  owners bind actions to that sprite and unlock the full trigger (hit / touching /
  leaveScreen) and action set; Scene keeps the safe subset.
- **Flow control (C.6):** **Sequence** (N ordered outputs, run in turn) and
  **Delay** (wait N seconds, then continue — one-shot scheduler).
- **Data pins (C.7):** a second wire type. **Get** (read a variable), **Value**
  (constant), **Compare** (`a ⟨op⟩ b → bool`) carry values along cyan data wires;
  a Branch's condition can be *wired* from a Compare (overrides the inline fallback).
- **Computed values (C.8):** a **Math** node (`a ⟨+ − × ÷ %⟩ b`) plus data-driven
  numeric action params — e.g. wire `level × 10` into a *change score* node so the
  amount is computed at runtime.
- **Data getters (C.9):** **Random** (a number in a range) and **Sprite**
  (a sprite's x / y / width / height) source nodes.
- **API:** `Y.getBlueprint(owner)`, `Y.setBlueprintFor(owner, {nodes, edges})`,
  `Y.getBlueprints()`, `Y.toggleBlueprint(visible)`.

## Fixes
- **Blueprint header overflow:** the growing node palette clipped the Play button
  on the right edge of the fixed-width header; the action row now wraps.

## Internal / tests / docs
- New modules: `game/blueprint-types.ts` (model), `game/blueprint-to-script.ts`
  (compiler — merges into `generateGameScript` fragments), `components/blueprint-graph.tsx`
  (editor). Blueprints persist in `SlideDocument.blueprints` (owner-keyed map) with
  legacy `blueprint → blueprints['']` migration.
- e2e: `tests/blueprint-graph.spec.ts` (17 specs) and `tests/game-graph.spec.ts`
  (flow wires); arcade + behaviors suites regression-green throughout.
- Learnings + Arcade help doc + `docs/canva-features-plan.md` (phases C.3–C.9) updated.

## Breaking changes / migration
- None. A document's legacy scene-level `blueprint` field is migrated into the new
  owner-keyed `blueprints['']` on load; existing games and behaviors are unaffected.
