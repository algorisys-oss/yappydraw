# 0.8.192 — the Reload button that finally reloads (2026-08-14)

## Highlights
- **"Reload" on an error screen genuinely did nothing.** Yappy's service worker uses the `prompt`
  strategy, so a newly deployed build installs and *waits* — and it only activates once every
  client is gone. A page reload does not lose the client, so the old worker kept serving the same
  broken build. That is exactly why the reported workaround was "go back completely and reopen".
  Every reload path on an error screen now clears the worker and its caches first.
- **A failed help doc no longer takes down the whole Help page.** The error is caught in the
  content pane; the sidebar keeps working, and clicking another doc works.
- **The colour eyedropper picks the right colour on gradients.** It used to report the gradient's
  first stop no matter where you clicked, which between two shades of one hue read as "the picker
  grabs a slightly different, duller shade".
- **The Pen tool can be paused and picked up again.** Hover either end of an open path, click the
  ringed anchor, and carry on from there — then click the other end to close the shape.

## Features
- **Pen: continue an unfinished path.** Finishing a path (`Esc` / `Enter` / double-click / switching
  tools) leaves it on the canvas as an ordinary open object. Select the Pen again and hover either
  *end* anchor: a blue ring marks the point the next click will continue from. Click it and the path
  goes back into building mode with that anchor as the live end — rubber-band, `Backspace` to undo
  an anchor, the lot. Clicking the *other* end closes the shape.
  - Clicking the **start** anchor resumes backwards: the anchor list is reversed and each anchor's
    in/out handles are swapped, so the curve is unchanged and new points still extend the end you
    clicked.
  - Deliberately refused: **rotated** paths (anchors are stored in unrotated local space, so a
    world-space click would land in the wrong place) and **compound** paths with holes (several
    ends, no single "the" end). Both remain editable with the Node tool (`N`).
  - New transient store field `penResumeHint` drives the hover ring; cleared when the tool changes.

## Fixes
- **Help doc fails to load, and reloading does not help** (the reported symptom, verbatim: "I have
  to go back completely and reopen the document"). Help doc pages are `lazy()` chunks deliberately
  excluded from the service-worker precache, so each is fetched on first open — and after a deploy
  that content-hashed URL is gone. The recovery was `location.reload()`, which cannot work under a
  `prompt`-strategy service worker: the waiting build activates only when there are no clients left,
  and a reload keeps the client alive. Closing the tab is what released it. All error-screen reloads
  (`recoverFromStaleBuild`'s automatic recovery, the route error screen, the boot-failure screen and
  the new per-doc one) now go through `forceReloadLatest()` → `hardRefresh()`: unregister the service
  workers, clear Cache Storage, navigate to a cache-busted URL.
- **One broken help doc replaced the entire Help page.** The only boundary was the route-level one in
  `index.tsx`, so nav and all went to "Something went wrong". There is now an `ErrorBoundary` around
  the content pane (`DocError` in `help-page.tsx`), keyed on the doc id — Solid's `ErrorBoundary`
  latches its error, so without the key one failed doc would keep showing its error screen for every
  doc clicked afterwards.
- **A status-0 response could poison a chunk URL for 30 days.** The `yappy-lazy-chunks` runtime cache
  accepted `cacheableResponse: { statuses: [0, 200] }`. These are same-origin assets, so a
  legitimate response is always a real 200; status 0 stored in a **CacheFirst** cache with a 30-day
  expiry means that URL serves an unparseable body until it expires, with no network fetch to correct
  it. Tightened to `[200]`.
- **The colour eyedropper returned the wrong colour on gradients** (#302). `elementPickColor`
  answered "what colour is this shape?" with the first gradient stop, when the user had asked "what
  colour is this *point*?". Measured before the fix: clicking at 10 / 50 / 90% across a red→blue
  gradient returned `#ef4444` every time while the screen showed `#c25370`, `#94639d`, `#6772ca`.
  It now prefers the rendered pixel for gradient fills and gradient strokes; the first stop remains
  the fallback for callers with no click point. Flat paint is unchanged and still reports the
  *authored* colour — including the sketch-hachure case, where a naive pixel sample would return the
  white gap between hatch strokes.
- **The eyedroppers recorded the previous colour in the picker's "recents" strip.** `commitRecent()`
  read the `h/s/v` signals immediately after `onChange`, before the syncing `createEffect` had run.
  It now takes the picked hex explicitly.

## Internal / tests / docs
- `elementPickColor(el, wantStroke, renderedHex?)` — new optional third argument. Backwards
  compatible; `Yappy.getElementPickColor` is unchanged.
- New `forceReloadLatest()` in `utils/stale-build.ts` — the manual escape hatch behind every error
  screen's reload button. Clears the loop guard first, since the user asked for this one.
- New specs: `tests/pen-resume.spec.ts` (3), `tests/color-eyedropper.spec.ts` (2),
  `tests/help-doc-recovery.spec.ts` (2). The colour spec asserts the pick equals the on-screen pixel
  at three points across a gradient *and* that flat fills still report the authored colour.
- Help docs: Vector Paths (pause/resume the Pen, and what is not resumable), Masks & Appearance
  (what the eyedropper does on gradients vs flat paint), Workspace (why a plain browser refresh is
  not enough when a page asks you to reload). Search keywords updated for pen-resume phrasing.
- `docs/learnings.md`: the `prompt`-strategy service worker vs `location.reload()` trap; Solid's
  latching `ErrorBoundary` and `lazy()` caching its rejection; CacheFirst + `statuses: [0, 200]`;
  resuming a pen path as an anchor-order problem.

## Breaking changes / migration
None.
