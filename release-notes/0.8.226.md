# 0.8.226 — the crash behind "Something went wrong", and five more from one tester's session (2026-08-30)

## Highlights

- **"Something went wrong" on Delete and on Pathfinder was one bug, not two** — and it took
  the whole editor down, which is why the work could not be undone afterwards. Fixed at the
  read, at the write, and at the blast radius.
- **Tool flyouts open on screen from every dock edge.** Docked right or bottom, the expanded
  tools of every tool group were off the window entirely.
- **The Pen shows you what you are drawing** even with the stroke set to *None* — a blue
  construction guide, independent of the shape's own paint.
- **Ctrl/Cmd + drag a corner = free distort:** move one corner and leave the other three.
- The **P3 palette** now moves the colour picker with it, and the **Layers panel** can be
  dragged with a finger, says so, and can no longer be lost off-screen.

All six come from one tester's session (Anshika, 2026-08-30), reported with two screen
recordings.

## Features

- **Free distort — move one corner on its own.** Hold <kbd>Ctrl</kbd>/<kbd>⌘</kbd> and drag a
  **corner** handle: that corner follows the pointer and the other three stay exactly where
  they are. The corner counterpart of the existing <kbd>Ctrl</kbd>+side-handle shear, so the
  modifier keeps one meaning — *deform rather than resize* — and the handle says on what.
  Stored as a 2×2 **projective** envelope cage, so it renders in both Sketch and Architectural
  styles, hit-tests, exports to SVG and undoes in a single step; the shape keeps its type
  (no silent conversion to a path), and the orange cage handles stay available afterwards for
  adjusting any other corner. API cross-reference on `Yappy.toggleEnvelopeWarp`.

- **A construction guide for the Pen.** While a path is being built, a thin blue guide is
  drawn through the anchors — square anchor markers, a hollow marker for the uncommitted
  rubber-band point, and the Bézier arms of the anchor being pulled. It is deliberately
  independent of the element's own stroke and fill, which is the whole point: with the stroke
  set to *None* (what you do when the goal is a filled shape with no outline) the Pen
  previously drew a row of anchor squares connected by nothing. Hairline at any zoom, with a
  white casing so it stays legible over dark artwork, and gone the instant the path is
  finished. New `frontend/src/rendering/pen-construction.ts`.

## Fixes

- **#334 — "Something went wrong" on Delete, and again on Pathfinder > Unite, with no way to
  undo.** `store.selection` holds *ids*, and removing the elements it names took two store
  writes: drop the elements, then clear the selection. Solid runs effects **between** them, so
  for one frame the selection named elements that no longer existed — and
  `paintColorIsMixed` read `sel[0].strokeColor` off the resulting empty array. That read
  happens inside the Fill & Stroke swatch's reactive `title` binding, so the throw did not
  break one control: it reached the **top-level ErrorBoundary** and replaced the entire
  editor. Every operation that consumes a multi-selection went through that window — Delete,
  all four Pathfinder booleans, compound shapes, Shape Builder, Scissors, Distort; Backspace
  looked "safe" purely by timing. Fixed at three levels: the guard in `paintColorIsMixed`,
  the window itself (`deleteElements` batches, and `replaceElementsPreservingOrder` now sets
  the new selection inside the same `batch()` — all eight call sites, so the invariant is
  structural rather than a convention), and the blast radius (below).

- **#334b — the error screen was a trap.** When the crash comes from an *edit*, the document
  and the whole undo stack are still intact in the module-level store; only the UI is gone,
  and with it every route to <kbd>Ctrl</kbd>+<kbd>Z</kbd>. The screen now offers **Undo last
  change**, which undoes the offending edit and remounts the editor with the work restored.

- **#333 — tool flyouts opened off-screen from a right- or bottom-docked toolbar.** Seventeen
  tool-group components each carried a byte-identical `{ top: rect.bottom + 4, left: rect.left }`,
  correct only while the bar is docked left or top. One shared `placeFlyout` now asks "where
  does it fit?" in the order a menu should try — below → above → left of the anchor → right of
  the anchor → clamped — and **measures** the panel before placing it, because these range
  from a three-icon strip to a titled four-column grid. A right-docked bar gets the *side*
  placement rather than a clamp: clamping alone slides the panel under the toolbar and hides
  the buttons it belongs to.

- **#332 — the P3 palette moved the swatch but not the colour picker.** Every P3 Wide-Gamut
  swatch is stored as `color(display-p3 r g b)`, and the picker synced itself with a hex-only
  parser — so picking one updated the Fill chip and the object while the saturation square,
  hue slider and hex field went on showing the previous colour. New `cssColorToRgb255` handles
  hex, `color(display-p3 …)` (via a proper linear-P3 → linear-sRGB homography), `color(srgb …)`
  and `oklch(…)`, and delegates `rgb()`, `hsl()` and CSS colour names to the browser — the
  forms imported SVG brings. Out-of-sRGB colours clamp for *display* only; the object keeps
  the true P3 value.

- **#331 — the Layers panel could be moved, and could also be lost.** It had always been
  draggable by its title bar; three things made that untrue in practice. No
  `touch-action: none` on the handle, so on a touch-capable machine a finger drag scrolled the
  dock zone instead (`preventDefault()` on `pointerdown` does not stop scrolling — only the
  CSS property does). No affordance — `cursor: move` is invisible until you are already on the
  bar; there is now a grip (⣿) beside the panel name and a tooltip. And no clamp on the
  persisted float position, so dragging a panel past an edge, or reopening the app in a
  smaller window, put its title bar off-screen or behind the opaque top bar — and the title
  bar is the only handle a panel has. Positions are clamped on every move and on window
  resize. Plus `setPointerCapture` and a `pointercancel` teardown, so a fast drag cannot hand
  the pointer stream to the canvas mid-gesture.

- **#330 — the Pen drew nothing when the stroke was set to None.** See *Features* above.

## Not bugs — documented instead

The transform report had three parts, and two of them already worked:

- **Stretching one side** is what a plain drag on a side (edge-midpoint) handle already does —
  the opposite edge stays pinned. The confusion is that <kbd>Shift</kbd> here **constrains
  proportions**, the opposite of the reflex from some other apps, so reaching for it turns a
  single-axis stretch into a uniform one.
- **W and H in the Properties panel are already independent fields.**

Both are now stated explicitly in the Free Transform help, alongside the new distort. The one
thing that genuinely could not be done — moving a single corner — is the feature above.

- New specs: `tests/selection-teardown-crash.spec.ts` (8), `tests/tool-flyout-dock.spec.ts` (5),
  `tests/panel-move.spec.ts` (4), `tests/pen-construction-guide.spec.ts` (3),
  `tests/free-transform-distort.spec.ts` (8). Every one was A/B'd against the pre-fix code to

- New shared modules: `frontend/src/utils/tool-flyout.ts` (flyout placement, replacing 17
  duplicates) and `frontend/src/rendering/pen-construction.ts`.
- Hotkeys list gains *Stretch one side*, *Free distort* and *Shear*, translated into de/es/fr/ja.
- Help docs updated: `features/logo-toolkit.md` (stretch one side, free distort),
  `shapes/vector-paths.md` (the Pen guide), `features/workspace.md` (flyouts follow the dock
  edge, the picker follows the swatch, panels are moved by their title bar).
- `docs/bugs/bug-fixes.md` #330–#334; `docs/learnings.md` gains five entries, including why a
  throw inside a reactive read is an app-level bug and why a pixel test that does not fail on
  the old code is not a pixel test.

Two pre-existing failures are unchanged by this release and were A/B-confirmed against a clean
tree: `tests/swatches.spec.ts` ("global swatches: link, propagate, unlink, persist") and the
crop test in `tests/image-and-swatches.spec.ts`.

## Breaking changes / migration

None. One behaviour change worth knowing: <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + dragging a **corner**
handle previously did an ordinary resize (the modifier was ignored there) and now distorts
that corner. Plain corner drags are unchanged.
