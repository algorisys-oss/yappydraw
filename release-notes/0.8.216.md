# 0.8.216 — figures land where you are looking (2026-08-22)

## Highlights
- A stick figure dropped from the panel now lands in the middle of the **visible canvas**,
  not in the middle of the page. Reported as "the shape is placed on the right edge of the
  screen".

## Fixes
- **Panel drops ignored the viewport.** `insertAnimatedFigure` and `svgToElements` — between
  them every animated figure, static figure, illustration and SVG import — defaulted to
  centring on the active page. That is the same point as the middle of the screen only when
  the page fills the canvas, and it stops being so in two independent ways: pan/zoom anywhere
  else, or simply open a right dock, which shrinks the drawing area without moving the view.
  On a fresh document with one panel open the figure landed ~150px right of centre of a
  1020px canvas; zoomed in, it landed off-screen entirely.

  Both paths now drop at the centre of the visible drawing area via a new `canvasCenterWorld()`
  in `utils/dock-layout.ts`, which un-projects the drawing-area centre in the canvas-local
  coordinates the view transform is actually defined in. Page centring remains as the SSR/test
  fallback, and an explicit `x`/`y` still wins — the comic-panel builder, the TeX typesetter and
  drag-drop are unchanged.

## Internal / tests
- New `tests/stick-figure-drop-position.spec.ts`: both drop paths must land dead centre of the
  canvas at the default view and when zoomed in and panned away, and an explicit `x`/`y` must
  still win. The four placement assertions fail on the previous code.
- Docs: `docs/bugs/bug-fixes.md`, `docs/learnings.md` (why "the middle of the screen" is three
  different numbers here), the two stick-figure help docs, and the `api.ts` doc comments for
  `insertStickFigure` / `insertAnimatedFigure` / `insertElement`.

## Known, not fixed here
- Three call sites that place the **symmetry axis** "where the user is looking" (`app.tsx`,
  `utils/command-registry.ts`, `centerSymmetryOnView`) un-project `canvasCenterClient()`, which
  double-counts the left/top dock insets. Same family of bug, different feature — noted in
  `docs/learnings.md`.
- `createComicPanel` still centres on the page. A comic panel is a page-sized composition, so
  that is defensible, but it is the same default and worth revisiting if it is ever reported.
