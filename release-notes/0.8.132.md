# 0.8.132 — Toasts stop covering the presentation toolbar (2026-07-21)

## Highlights
- Pop-up messages no longer sit on top of the presentation toolbar, hiding its buttons and
  swallowing clicks aimed at them.

## Fixes
- **Toast vs presentation toolbar.** Both are `position: fixed`, bottom-centre — the toast at
  `bottom: 24px`, the toolbars at `bottom: 40px` — and the toast wins on z-index (10010 vs
  10000). Measured overlap was **59px**, directly over the tool buttons, with the toast's 300px
  minimum width covering the middle of the bar. Two independent fixes:
  - The toast body is now `pointer-events: none`, so clicks pass through to whatever is beneath
    (the close button opts back in). A transient notification should never intercept a press —
    it vanishes on its own, leaving no trace of why the click did nothing.
  - `bottom` is now `var(--toast-bottom, 24px)`, and the shared `PresentationCaptureButtons`
    sets that variable to `110px` while mounted, lifting toasts clear of the toolbar. It lives
    there because that component renders inside *both* presentation toolbars and unmounts with
    their auto-hide, so the offset tracks visibility for free and the two toolbars can't drift
    apart on it.

## Internal / tests / docs
- **Help-doc API audit.** Every API reference in `frontend/src/help-docs/` was checked against
  the real surface of `api.ts`: 139 distinct `Yappy.*` names plus 154 aliased `Y.*` /
  `window.Yappy.*` call sites, against 593 API members — **zero unresolved**. The
  `Yappy.startRecording()` mistake fixed in 0.8.130 was isolated, not symptomatic.
- New regression test in `tests/recording-capture.spec.ts` (9 total) asserting a visible toast
  neither covers nor blocks the toolbar: it checks computed `pointer-events`, that the toast's
  bottom edge clears the toolbar's top edge, and — the real proof — that a toolbar button still
  responds to an ordinary click while a toast is showing, with no forced click and without
  removing the toast first.
- Both assertions were verified to fail independently against their own half of the bug.

## Breaking changes / migration
- None.
