# 0.8.164 — The mobile shell works again (2026-07-31)

## Highlights
- On a phone the toolbar had become a **full-screen invisible panel**: the tool icons sat
  stranded in the middle of the window and nothing on the canvas responded to a tap. It is
  a proper bottom strip again, with the canvas between the header and the tools.
- Five further mobile-layout defects fixed alongside it — overflowing width, 28px touch
  targets, chrome painted over the drawing area, a dead band at 601–699px, and undo/redo
  landing on top of the tools.

## Features
- None. This release is entirely repair of the mobile layout introduced by the v0.8.16x
  shell/dock refactor.

## Fixes
- **The phone toolbar covered the entire screen.** The refactor added
  `.toolbar-container:not(.docked) { top: … }` (specificity 0-2-0) to clear the new header;
  the phone rule it must lose to is `@media (max-width: 600px) { .toolbar-container { top:
  auto } }` (0-1-0). A media query adds no specificity, so `top: auto` never applied and the
  bar had `top` *and* `bottom` pinned — which stretches an auto-height element between the
  two edges. Measured 796px tall on an 844px phone, painted in `--bg-panel` (white on white,
  hence invisible) and swallowing every pointer event. The phone rule is scoped
  `:not(.docked)` now, so it ties on specificity and wins on source order.
- **The phone toolbar was 24px wider than the phone** — `width: 100%` plus 12px side padding
  with no global `box-sizing: border-box` reset. The last tool was cut off and the page
  scrolled sideways. Fixed with `box-sizing: border-box`.
- **Tool buttons were 28px, not 40px.** The mobile `.toolbar-btn { width: 40px }` is
  declared *above* the base `.toolbar-btn { width: 28px }`; equal specificity, so the later
  base rule won on source order. Scoped to `.toolbar-container .toolbar-btn`.
- **The header and the toolbar strip painted over the canvas.** `dockInsets()` skipped the
  top-bar inset on narrow viewports, but `app.tsx` mounts the header whenever the app isn't
  in Zen or Presentation mode — phones included — so an opaque z-10050 bar covered the top
  52px of the "drawing area" and reserved nothing. The inset is now conditioned on exactly
  what gates the render, and a phone-width viewport reserves the toolbar strip at the bottom
  too.
- **601–699px docked the toolbar on top of the drawing.** The phone breakpoint was written
  three times — 600 in `toolbar.tsx`, 600 in `toolbar.css`, **700** in `dock-layout.ts` — so
  in that band the bar took an edge while the insets still called the viewport narrow. One
  exported `PHONE_MAX_WIDTH` / `isPhoneWidth()` now, consumed by all three.
- **Floating undo/redo sat on top of the tools**, pinned at a hand-tuned `bottom: 60px` that
  cleared a 36px status bar but not that bar plus the 57px strip. Offsets by
  `var(--dock-bottom)`, which is correct in the phone and the 601–768px tablet layout alike.
- `--statusbar-h` was published as a flat 28px while `status-bar.css` makes the bar 36px at
  ≤768px, leaving mobile chrome anchored to it 8px out. It follows the viewport width now.

## Internal / tests / docs
- New `tests/mobile-shell.spec.ts` — six specs covering the strip's geometry, viewport fit,
  touch-target size, the canvas band being reserved *and* drawable, undo/redo clearance, and
  the 640px breakpoint band. All six verified to fail against the pre-fix tree.
- `utils/dock-layout.ts` gains `PHONE_MAX_WIDTH`, `PHONE_TOOLBAR_H`, `STATUS_BAR_MOBILE_H`,
  `isPhoneWidth()` and `statusBarHeight()` as the single source for the phone breakpoint and
  the real chrome heights.
- Help: `workspace-doc.tsx` gains an "On a phone" section — it described the dock cycle but
  never said what happens below 600px.
- Four new entries in `docs/learnings.md` (media queries and specificity; reading the box
  model when the broken element is invisible; one concept one constant; chrome that paints
  must also reserve) and bugs 231–236 in `docs/bugs/bug-fixes.md`.

## Breaking changes / migration
None. The canvas is slightly smaller on phones because the header and toolbar now reserve
their bands instead of covering the drawing — that space was never usable.
