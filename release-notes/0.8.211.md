# 0.8.211 — the two "high severity" alerts were inert (2026-08-21)

## Highlights
- The two long-standing HIGH Dependabot alerts on the OSS repo were investigated, found to be
  **unreachable in this project**, and dismissed as `not_used` with the evidence recorded.
- New `docs/security/dependency-audit.md` so the same investigation is not repeated the next
  time a scanner reports them.

## Internal / docs
- **`image-size` CVE-2025-71329 / CVE-2025-71330** (DoS via infinite loops in the ICNS and
  JXL/HEIF parsers, `<= 2.0.2`). Arrives only via `pptxgenjs@4.0.1`, which excludes it from
  browser builds itself — `"browser": { "image-size": false, … }`. It is a Node-only path for
  reading image dimensions off disk, and Yappy is client-only. Verified rather than assumed:
  **0 of 160** files in `dist/assets/` contain any image-size fingerprint (`icns`, `ic10`,
  `mif1`, `ftypheic`, `jxlc`), the 372 KB `pptxgen.es-*.js` chunk included.
  There is also no fix to take — `first_patched_version` is `null`, and npm's only remedy is
  downgrading pptxgenjs **4.0.1 → 1.1.5**, three majors back, for a vulnerability that does not
  ship.
- Documented alongside them: `brace-expansion`, `fast-uri` and `nanoid` appear in local
  `npm audit` but sit under `vite` / `vite-plugin-pwa` — devDependencies, build-time only,
  operating on our own source. Dependabot does not raise them and no action is warranted.
- The audit doc records the re-open conditions (pptxgenjs run server-side, or its `browser`
  field ceasing to exclude `image-size`) and the cheap check that settles this class of
  question: the parent's `browser` field, plus a fingerprint grep of the built output.

## Breaking changes / migration
None. No dependency or application code changed.
