# 0.8.261 — Doodles, and sketch style that no longer redraws everything (2026-09-25)

Doodles are seeded pattern generators that fill a page. They are behind Dev Mode while more
generators are added. Building them showed that sketch style had been regenerating every shape
on every frame, because its render cache had never been switched on. That fix applies to every
drawing.

## Highlights
- **Doodles (Dev Mode).** Truchet tiles, a Flow Field of evenly spaced lines, and Topography
  contour maps. Turn the knobs, reroll the seed, pick from six variations, and colour it by role
  (paper, ink, two fills) or as line art for colouring. Every change shows on the canvas live;
  Cancel puts everything back.
- **A doodle stays editable.** Select it → *Edit Doodle…* reopens it with its settings. It
  regenerates where it now is, keeping any move, resize or rotation, and a duplicate is its own
  doodle.
- **Faster sketch style everywhere.** Panning and zooming no longer regenerate each shape's
  hand-drawn geometry every frame: a pan now runs zero rough.js generations (measured by test)
  where it used to regenerate every shape. A page-sized doodle had cost ~400 ms per sketch frame.

## Features
- Entry points (Dev Mode): main menu → **Doodle Generator…**, canvas right-click → **Insert →
  Doodle…**, command palette **Doodle Generator…**, and **Edit Doodle…** on a selected doodle.
- A doodle is 2–5 grouped paths, one per colour role, however dense the pattern.
- API: `createDoodle(kind, x, y, width, height, opts)`, `updateDoodle(id, patch)`,
  `getDoodle(id)`, `doodleGenerators`. Same seed + same params + same region = same doodle.
- New help page: **Doodles (Pattern Generator)**.

## Fixes
- **#397** The sketch-style render cache never hit: every element carried a static animation
  state and the renderer treated that as "animated".
- **#398** The render-cache key left out path geometry, so an edited path would have replayed its
  old drawing once the cache worked. The draw-in trace shared that key and could mix up two
  similar paths.

## Behaviour changes
- Stick rigs and symbol instances are never cached, because they draw from outside their own
  fields (the clock, the symbol definition). Everything else is cached and keyed on every field
  that can affect its drawing, plus the theme.

## Known limitations
- Ungrouping a doodle turns it into ordinary paths.
- A doodle several screens across takes a fraction of a second to rebuild on each change.

## Internal / tests / docs
- `utils/doodles/` (generators, seeded noise, curve chaining), `components/doodle-dialog.tsx`,
  `DrawingElement.doodle` stamp, `discardLastSnapshot()` in the store.
- `rough-cache.ts`: structural digest of every element field except a short denylist;
  `animation-utils.ts`: `isStaticAnimatedState`.
- Tests: `doodles.test.ts`, `rough-cache.test.ts`, `animation-utils.test.ts`,
  `doodle-generator.spec.ts`, `rough-element-cache.spec.ts`, each seen failing against a broken
  build before passing.

## Breaking changes / migration
- None. Documents gain an optional `doodle` field on doodle members; older builds ignore it.
