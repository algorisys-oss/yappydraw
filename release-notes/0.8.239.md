# v0.8.239 — A check instead of a comment (2026-09-07)

The guard that would have caught v0.8.238's bug before it was pushed, plus a copy pass
over everything the contribute page says.

## Highlights

- **`publish-oss.sh` refuses to push a tree that is missing something the build reads.**
  We test this repo; the host builds the OSS mirror, so every `.ossignore` exclusion is an
  untested edit to the deployed artifact. That has now broken deploys twice.

## Features

- **Derived required-paths check**, run unconditionally including on dry-run. The list is
  *derived, not hand-written*, because a hand-maintained list would go stale exactly the way
  the `.ossignore` comment did: the prerenderer declares its inputs as
  `path.join(REPO, '<path>')`, so the guard greps for that pattern and inherits every future
  input for free. Re-introducing the v0.8.238 bug now fails the publish with an explanatory
  error instead of a green push.
- **`--verify` flag** runs `npm ci` and `npm run build` inside the published tree before
  pushing. It is the only check that tests what Hostinger tests, and it would have caught
  bug #344 (an OOM kill) as well as the ENOENT. Opt-in for ad-hoc runs; the ship-it flow in
  `CLAUDE.md` now passes it on every release.

## Fixes

- **Copy pass across everything the contribute flow says.** Em-dashes removed from the
  `/founders/` page, the help doc's Support section, both legal pages and the `en`/`de`
  locale strings, in favour of colons, parentheses and full stops. Also caught two things
  the rewrite introduced: a doubled "and", and a sentence stacking three commas.

## Internal / tests / docs

- **`CLAUDE.md`'s "no logs means OOM" heuristic corrected.** It is the reasoning that cost
  time on v0.8.238. "No logs" narrows the field to things that *kill* rather than fail; it
  does not exclude a host that never surfaced an error the build did write. Run the clean
  clone first and measure memory second, and clone the **OSS mirror** — a clone of this repo
  cannot see anything `.ossignore` removed.
- `docs/learnings.md`: *"We publish a tree nobody builds."* Both times this failed, someone
  understood it well enough to write an accurate comment, and writing it down did not help.
  A lesson in a doc changes what the next person knows; only a check changes what they can do.

## Breaking changes / migration

- None. `--verify` is opt-in and the required-paths check only fails a publish that was
  already going to break the deploy.
