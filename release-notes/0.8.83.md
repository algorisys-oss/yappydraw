# 0.8.83 — Embed & drive the full editor from another project (cross-origin API bridge) (2026-07-13)

## Highlights
- You can now build **interactive diagrams in another project** by embedding the
  full Yappy editor in an `<iframe>` and driving its API from the host page —
  same-origin works with zero setup, and a new **secure cross-origin
  `postMessage` bridge** covers the different-origin case.

## Features
- **Cross-origin embed control bridge** (`frontend/src/embed-bridge.ts`, wired into
  `initAPI()`). A trusted parent page can call any `window.Yappy` method over
  `postMessage`. Secure-by-default:
  - **Default-deny** for cross-origin. Same-origin is always allowed.
  - Allowlist is **operator-controlled only** — `VITE_EMBED_ALLOWED_ORIGINS`
    (build-time) or `window.YAPPY_EMBED_ALLOWED_ORIGINS` (runtime, set in Yappy's
    own `index.html`). A page that merely frames Yappy cannot grant itself access.
  - Only own, callable API methods are invokable (prototype members / non-functions
    rejected); requests carry a `__yappy` marker; replies go only to the verified
    `event.origin`; non-serializable results are reported, not thrown.
  - `'*'` wildcard opts trusted internal deployments out of the origin check (logs
    a warning).
- **Host-side client** (`frontend/public/yappy-embed-client.js`, served at
  `/yappy-embed-client.js` and copy-pasteable). `createYappyEmbed(iframe, { targetOrigin })`
  returns `{ ready(), call(method, ...args), destroy() }`; `call` invokes any
  `window.Yappy` method and returns a Promise of its result.

## Fixes
- None (additive feature).

## Internal / tests / docs
- Help doc **Embedding** (`help-docs/features/embedding-doc.tsx`) gains an
  "Interactive control (drive the full editor)" section: same-origin vs
  cross-origin, the operator allowlist, the `'*'` security warning, and the client

## Breaking changes / migration
- None. The bridge is off unless an operator configures an allowlist; existing
  read-only `#/embed/` viewer behaviour is unchanged.
