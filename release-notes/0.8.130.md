# 0.8.130 — Capture a looping GIF from the presentation toolbar (2026-07-21)

## Highlights
- A **film button** beside Record captures a looping GIF: press to start, press to stop.
  Made for READMEs, wikis and chat, where a GIF plays inline with no player.
- The GIF export dialog finally exposes **frame rate** instead of always using 12fps.

## Features
- **Live GIF capture (start/stop).** Present (`F5`), press the film button, do the thing,
  press it again. The file downloads immediately. It captures the canvas as you drive it, so
  slide changes, build steps, ink and the laser pointer all land in the GIF — and the toolbars
  never do. Available on **both** presentation toolbars (paged docs and infinite canvas).
- **Start/stop rather than a fixed duration.** Animations fire on clicks, build steps and
  conditions, so there is usually no length to pick up front — a timer either cuts off the
  payoff or burns frames waiting. Stopping by hand also lands a cleaner loop: press Stop the
  moment the motion returns to where it began and the join is invisible, which a blind timer
  can't do. Captures auto-stop at 60s as a backstop.
- **Live cost readout.** While capturing, the button shows elapsed time and the file size as it
  grows (`0:04 · 210 KB`). A GIF stores every frame whole, so length costs bytes directly and
  that is worth seeing before the download, not after.
- **Framed to the page.** Presentation zooms a page to fit and letterboxes it; the capture crops
  to the page rect so the workspace bars don't end up baked into a README image. On an infinite
  canvas — no page bounds — it captures the viewport.
- **GIF frame rate in the export dialog.** Previously hardcoded to 12fps with no way to change
  it from the UI. Now settable (5–30), with a live frame-count estimate.
- New API: `Yappy.startGifCapture(fps)`, `Yappy.stopGifCapture()`, `Yappy.isCapturingGif()`,
  and `Yappy.captureGif(seconds, fps)` for unattended scripts that have no one to press Stop.

## Fixes
- Bug #189: a failed GIF capture killed the feature until reload. The rAF loop had no error
  handling, so a throw ended it silently *and* left the capturing flag set — which disables the
  buttons, turning one transient failure into "nothing happens" on every later click. Failures
  now always clear the flag and report the cause, with a specific message for the cross-origin
  image case (`SecurityError` from a tainted canvas). See `docs/bugs/bug-fixes.md`.
- Fixed the capture readout wrapping onto a second line and stretching the toolbar pill.

## Internal / tests / docs
- Both presentation toolbars now render a shared `PresentationCaptureButtons` component rather
  than each carrying their own copy. They had already diverged once (v0.8.129, #188); a control
  added there now lands in both by construction.
- The live canvas is resolved via the registered getter *or* a DOM fallback, so a stale
  hot-reload registration reports "reload the page" instead of doing nothing.
- Help docs: the Animation doc gains a "Capturing a looping GIF" section, and the format table
  and doc-type table were corrected. A leftover `Yappy.startRecording()` — a method that has
  never existed — was removed from a code sample.
- Verified in a real browser by inspecting the downloaded bytes: `GIF89a`, correct dimensions,
  NETSCAPE loop block present, arbitrary stop length, idle state restored afterwards.

## Breaking changes / migration
- The 3s/5s/10s duration presets briefly present in the toolbar are gone, replaced by start/stop.
  `Yappy.captureGif(seconds, fps)` still does a fixed-length capture for scripts.
