# 0.8.137 — The crop fix now reaches the editor (2026-07-21)

## Highlights
- Cropping in the UI genuinely keeps the image's shape. **0.8.136 fixed the same bug in a code
  path the editor never calls.**

## Fixes
- Bug #198: **0.8.136's crop fix did not apply to the editor.** The fix went into
  `exitCropMode(apply)`, which is what the new `Yappy.exitCropMode()` API calls — and what the
  test exercised. But the UI has **two other apply paths**, both in `canvas.tsx`: pressing
  <kbd>Enter</kbd>, and clicking outside the crop rectangle. Each converted the rect inline via
  `finalizeCropRect` and called `exitCropMode(false)`, so neither resized the frame. Pressing
  Enter still stretched the image.

  Both now call `exitCropMode(true)` — a single apply path that converts to source pixels *and*
  shrinks the frame. `exitCropMode` also absorbed `finalizeCropRect`'s "a crop covering the whole
  frame means no crop" rule, so that behaviour is preserved.

  Verified through the real interaction this time — crop tool, drag a handle, press Enter — and
  the test was confirmed to **fail against the old code** (frame stayed 2:1 while displaying a
  1:1 region) before being kept.

## Internal / tests / docs
- `tests/image-and-swatches.spec.ts` gains a UI-driven crop test that drives the pointer and the
  keyboard rather than the API. The existing API-level test stays: they cover different paths, and
  that distinction is the whole substance of this release.

## Breaking changes / migration
- None.
