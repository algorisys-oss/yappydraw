# 0.8.166 — Connectors leave a box the way they should (2026-07-31)

## Highlights
- A connector's departure direction came from the **chord's dominant axis** instead of the
  **box edge it is anchored to**, so on wide cross-hierarchy edges the curve left a bottom edge
  heading *sideways* — hugging the box, sliding past its corner, with the arrowhead lying flat
  against the edge. 97 of 653 edge-anchored endpoints in the audited corpus; now **0**.
- Connector labels were wrapped to the connector's bounding-box width, which for a vertical
  connector is **zero** — so `one at a time` exported as four stacked single words dropped down
  the line. Now one line, centred on the path.

## Fixes
- **Departure direction now comes from the anchor's edge normal.** `defaultControlPoints()`
  chose its axis from `Math.abs(width) > Math.abs(height)` — a property of where the two boxes
  sit relative to each other, not of which edge the endpoint attaches to. The two rules agree
  for a typical tree-down layout (top/bottom anchors, vertically dominant), which is why this
  went unnoticed; they diverge exactly when a node is far enough sideways that `|dx| > |dy|`
  while the anchor is still on a horizontal edge. Every failure measured *exactly* 90° off its
  edge normal — laid flat along the edge, not merely askew. The offset **magnitude** is
  unchanged, so connectors where the two rules already agreed re-render bit-for-bit identically.
- **The arrowhead was never wrong here** — it faithfully followed a curve that left in a
  direction no box connector should. Fixing the curve fixes the glyph.
- **Connector labels no longer wrap.** `el.width` for a connector is the chord's `dx`, so
  `maxWidth = el.width - 20` went negative on a vertical connector and forced one word per line.
  The canvas renderer never wrapped connector labels; this was another export-only divergence of
  the same family as the v0.8.165 arrowhead bug.
- **Connector labels sit on the path midpoint**, not the bounding-box centre. The two coincide
  for a default-control-point curve — which is why only the wrapping was visible — but diverge
  for any connector with authored control points.
- **`textAlign: left`/`right` is ignored for connector labels**, matching the canvas, which
  hard-codes centre. It was offsetting by `el.x + 10` / `el.x + el.width - 10`: the chord's
  corner and `dx`, which describe no text box.

## Internal / tests / docs
- `connectorGeometry` gained `anchorEdge()` (reads the `anchorFractionX/Y` that
  `api.connect()` already records) and a `mid` field for the path midpoint. Non-box shapes —
  circle, diamond, star, hexagon — anchor at neither 0 nor 1 and keep the chord rule; giving
  them a radial normal is the obvious follow-up.
- The label branch in `connector-renderer.ts` was the **seventh and last** inline copy of the
  control-point derivation in that file. It now uses the helper.
- `connector-geometry.test.ts` +9 cases (23 total); new `tests/connector-anchor-direction.spec.ts`
  (5 cases, four of which fail on the pre-fix tree — the fifth is the "unchanged" control).
- All 101 corpus diagrams re-rendered and re-audited: parallel-to-edge **97 → 0** (worst
  residual 0.1°), and the v0.8.165 arrowhead fix re-verified at **74/74 within 0.5°, max 0.0°**.
- `docs/connector-anchor-direction-spec.md` committed with verification notes marked **[R]**,
  including an audit caveat: these diagrams are sketch-style, so rough.js emits two jittered
  strokes per connector and a naive cubic scan over-counts 1697/354 instead of 653/97. Filter
  to exactly axis-aligned tangents before trusting the numbers.

## Breaking changes / migration
None. Connectors whose departure axis already matched their anchor edge are byte-identical.
