# 0.5.13 — Live-link pattern swatches + pattern stack-fills (2026-06-29)

## Highlights
- **Live-link pattern swatches.** Applying a library pattern now *links* the shape
  to the swatch — **redefine the swatch and every linked shape updates at once**.
- **Patterns in the appearance stack.** A stacked appearance fill can now be a
  pattern (built-in motif or library swatch), not just a solid colour — layer a
  pattern over a base gradient, or stack two patterns, on one object.

## Features
- `el.patternSwatchId` links a shape to a library pattern swatch (mirrors the
  colour-swatch `fillSwatchId` model):
  - `applyPatternSwatch` sets the link.
  - `updatePatternSwatch` (redefine) pushes the new pattern to **all** linked shapes.
  - Editing a shape's pattern directly (PATTERN editor / built-in motif) breaks its
    link, so your manual tweak survives a later redefine.
  - Deleting a swatch drops dangling links; linked shapes keep their current pattern.
- `PaintFill.pattern` — each appearance fill row in the Properties panel gains a type
  dropdown: **Solid**, a built-in motif (Stripes/Grid/Dots/Checker/Crosshatch), or a
  saved **★ library pattern**. Pattern stack-fills render clipped to the shape in both
  Sketch and Architectural styles.

## Internal / tests / docs
- `patternSwatchId` + `appearance` added to the `normalizeElement` passthrough.
- `renderAppearance` gains a pattern branch (rasterize → clip → drawImage, reusing the
  base pattern-fill path); appearance SVG export approximates pattern fills with the
  foreground colour.
- Help doc (Appearance Stack + Patterns library sections), learnings, roadmap updated.
- Verified end-to-end: applying/redefining a swatch updates linked shapes, direct edits
  break the link, and a dots stack-fill renders over a base fill — zero console errors.

## Breaking changes / migration
- None. Both fields are additive and default to absent.

## Known limitations
- Appearance **pattern** stack-fills export to SVG as their foreground colour (the
  appearance SVG builder doesn't yet emit a tiling `<pattern>`); canvas rendering is
  full-fidelity in both styles. Base pattern fills already export as true `<pattern>`
  in architectural style (0.5.10).
