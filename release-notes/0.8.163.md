# 0.8.163 — Recursive symbols, and every on-canvas guide finally lines up (2026-07-30)

## Highlights
- A symbol can now contain **itself**, and the nesting is drawn — Droste pictures, spirals and
  fractal trees from one small drawing.
- Symmetry axes, artboard frames and rulers/guides were all drawn **46px left and 52px above**
  the geometry they annotate. Every one of them is now exact. If symmetry looked like it wasn't
  following the axis, this was why — the strokes were right, the dashed line was in the wrong place.
- Fill mode shows the fill **while you draw** instead of snapping to it when you let go.

## Features
- **Recursive symbols.** Edit a symbol in place, drop another instance of the same symbol inside,
  press Done — the nesting is drawn from then on. Each level re-applies the transform you gave the
  nested copy, so translate alone gives a receding corridor and translate+rotate+scale traces a
  logarithmic spiral. Off by default (a self-referencing symbol still shows the grey "cyclic"
  placeholder until you opt in), and the `⟳` button with its **Depth** field appears on the
  Symbols-panel card only for symbols that actually contain themselves.
  Drawing stops at whichever comes first: the Depth cap (default 64), a level smaller than a pixel
  on screen, or an internal per-object draw budget — the last of which is what stops a symbol
  containing *two* of itself (which doubles the work every level) from hanging the frame.
  API: `setSymbolRecursive(symbolId, recursive?, depth?)`, `symbolSelfReferences(symbolId)`, and
  `listSymbols()` now reports `recursive` / `recursionDepth`.
- **Toolbar position button.** The button at the top of the tool column now cycles the toolbar
  through **left → top → right → bottom → floating**, and its icon shows where the bar currently
  sits. Previously it flipped a setting that only applied to a floating toolbar — which nothing in
  the UI could select any more, so clicking it did nothing at all.
- **Fill mode previews live.** With Fill on, a freehand stroke draws as a filled silhouette from
  the first move, closing across the gap as you go, so you can judge the mass mid-stroke. With
  symmetry on, every mirrored copy fills live too.

## Fixes
- **Symmetry axis drawn in the wrong place.** The overlay painted canvas-local coordinates onto a
  window-fixed layer. Those were the same thing until the toolbar and top bar became docked chrome;
  since then the guide sat 46/52px off the line strokes actually mirrored about. Dragging the axis
  centre was off by the same amount, and the centre handle sat 2px off its own axis (a 2px border
  outside an 18px box).
- **Artboard chips, frames and handles**, and **ruler ticks, labels and guides**, were offset by
  the same amount for the same reason. Rulers now start at the canvas origin and span the canvas
  instead of the window.
- **The left ruler was the wrong shape** — long-standing: both strips were laid out as horizontal
  bars, so the vertical one painted its content into a 22px-tall bitmap and clipped the rest.
- **Symmetry/Fill buttons vanished on hover.** Hovering an *active* button replaced its solid fill
  with the hover tint while keeping white text — white on near-white, 1.13:1. Every state in every
  theme now clears WCAG AA.
- **Exported HTML** now draws recursive symbols (the bundled player was rebuilt).
- The boot splash shows the **YappyDraw** wordmark above the bicycle.

## Internal / tests / docs
- New `utils/overlay-transform.ts` owns world↔window for fixed overlays. Three overlays had each
  inlined the same formula, which is why one shell change broke all three at once.
- New specs: overlay alignment (measured in two dock layouts with different canvas origins, so a
  hardcoded offset fails), symmetry axis alignment, tool-options-bar contrast (all 12 state×theme
  combinations), recursive-symbol termination (shrinking chain, non-shrinking chain, branching
  fractal) and live fill. Each was verified to fail against the bug it guards.
- Repaired 6 pre-existing red specs orphaned by the 0.8.162 dock migration: they assumed selection
  opens the Properties panel, or that the toolbar floats by default.
- Help docs updated: recursive symbols, toolbar position, live fill.

## Breaking changes / migration
- None. Recursive rendering is opt-in per symbol, so no existing document changes how it draws.
