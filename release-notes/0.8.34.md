# 0.8.34 — UML relations: spread fan-in arrowheads + edge arrowheads in the text DSL (2026-07-09)

## Highlights
- Inheritance/realization **fans no longer overlap**: when several relations point at
  one base class (or interface), their arrowheads now spread along the shared border
  instead of piling up on a single point.
- The **native text DSL** can now set an edge's arrowhead from its `{ }` block, e.g.
  `sub -> base { endArrowhead: triangle }`.

## Fixes
- **Fan-in arrowheads overlapped on a shared base.** Every edge into one class/interface
  clipped to the same center-line point, so the heads stacked. Added
  `distributeClassEdgeAnchors`, which spreads each group of edges evenly (fractions
  0.2–0.8, off the corners) along the border facing its neighbours; `connect()` gained
  optional `startAnchor` / `endAnchor` fraction overrides to honour it. Scoped to edges
  with `umlClass` / `umlInterface` on both ends — sequence, flowchart, and ER diagrams
  are untouched, and a lone edge keeps its natural center clip.
- **Text-DSL edge `{ endArrowhead: … }` was ignored.** Arrowhead keys inside an edge's
  `{ }` block were treated as style props and dropped. They're now hoisted to edge-level
  props (`none` / `null` = no head), so `sub -> base { endArrowhead: triangle }` works.

## Internal / tests / docs
- Verified end-to-end via the `render:dsl` CLI: three `Shape <|-- X` edges land at
  distinct border fractions (0.2 / 0.5 / 0.8) as three separate triangles; a native-YSL
  edge carries `endArrowhead: 'triangle'`.
- Help doc (`ysl-tutorial-doc`) documents the edge arrowhead keys; recorded in
  `docs/learnings.md` and `docs/bugs/bug-fixes.md`.

## Breaking changes / migration
- None. `connect()`'s new `startAnchor` / `endAnchor` options are optional and default
  to the previous center-clip behaviour.
