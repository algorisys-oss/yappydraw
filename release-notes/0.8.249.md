# 0.8.249 — Ready for social (2026-09-13)

## Highlights
- **One-click export for social platforms.** The Export dialog now opens with *Ready for social*:
  a button for every platform whose shape matches the current page. Click one and the page is
  saved as a JPG at that platform's exact size — no format or scale to pick.

## Features
- Platforms: Instagram Post and Story, Facebook Post and Cover, X / Twitter Post, LinkedIn Post,
  YouTube Thumbnail (the social and video page presets).
- Matches on shape, not size: a 1080 × 1080 design exports as both an Instagram Post and a
  1200 × 1200 LinkedIn Post; a 16:9 page as a YouTube Thumbnail, X Post and Facebook Cover.
- Rendered directly at the target pixel size, not resampled from another export.
- Files named after the document and platform, e.g. `autumn-sale-instagram-story.jpg`.
- Stays under YouTube's 2 MB and X's 5 MB upload limits by lowering JPG quality if needed, with
  a message if a file still cannot fit.
- Pages no platform fits (A4, posters…) point to **Menu → Magic Resize…** instead of cropping.
- **API:** `Yappy.getSocialTargets(pageIndex?)`, `Yappy.listSocialTargets()`,
  `Yappy.exportForPlatform(presetId, { pageIndex?, download?, name? })` — resolves to the file
  details and blob, or `{ ok: false, reason }`.
- Translated in English, German, Spanish, French and Japanese.

## Fixes
- Help → Design Studio said JPG page exports are always on white; they use the document's
  background colour. Corrected.

## Internal / tests / docs
- New `utils/social-export.ts` (targets derived from the page presets, shape matching,
  quality step-down, file naming) with 14 bun tests; `formatFileSize` added to `i18n/format.ts`.
- `renderPageAtSize` in `export.ts` renders a page to an exact pixel size; `exportPageToPng` now
  uses it.
- `tests/social-export.spec.ts` (5 tests): exact sizes and pixel mapping, shape filtering and
  refusal reasons, worst-case YouTube file size, one-click download from the dialog, and the
  Magic Resize hint.
- Measured: random-noise 1280 × 720 at JPEG 0.92 is ~0.8 MB in Chromium, so the limit guard is
  a safeguard for other encoders rather than a common path.

## Breaking changes / migration
None.
