# 0.8.240 — GIF export reaches the infinite canvas (2026-09-08)

## Highlights
- **Menu → Export** now offers **Animated GIF** on an infinite-canvas document. It was
  implemented, tested and documented; it was simply not offered there, and outside
  presentation mode there was no other way to reach it.

## Fixes
- **#358 — the Export dialog hid Animated GIF on an infinite canvas.** The radio sat behind
  `<Show when={isPaged()}>`, which matches `slides | design | game | animation` and not
  `infinite`. The gate had a real reason — `exportPageGif` renders offline against page bounds
  and cannot run without them — but WebM and MP4 carry the identical constraint and stayed
  visible, because `handleExport` gives them a fallback: no page bounds means capture the live
  canvas instead. GIF never got that fallback, so it was hidden rather than wired up. It now
  takes the same route: paged documents keep the offline page-framed render, everything else
  captures the live view at the frame rate you choose.

## Features
- **A capture indicator you can stop while editing.** A blue **GIF** badge now appears at the
  top of the canvas during a live capture, with the elapsed time, the file size as it accrues,
  and a **Stop**. Previously that control existed only on the two presentation toolbars, so a
  capture started while editing could only end by reaching the 60-second cap.
- The GIF **Frame rate** control now belongs to the format rather than the document type. The
  "roughly N frames" estimate is shown only where a duration exists to compute it from.

## Internal / tests / docs
- `RecordingOverlay` takes optional `label` / `accent` / `elapsedMs` / `detail` props and
  serves both the video recorder and the GIF capture; the elapsed/size readout moved to
  `gifElapsedText()` / `gifSizeText()` in `recording-manager.ts` so the toolbar button and the
  overlay cannot drift apart on formatting.
- `tests/recording-capture.spec.ts` gains two tests: one drives the dialog on an infinite canvas
  and asserts the downloaded bytes are a valid looping GIF, the other asserts a paged document
  still takes the offline route (no capture overlay), so the fallback cannot swallow the case it
  was added beside.
- `help-docs/features/animation.md` updated — it previously stated the limitation as a fact
  ("The Export dialog offers no GIF here").

## Breaking changes / migration
- None.
