# 0.8.139 — Re-cropping, and crop you can actually use on a tablet (2026-07-21)

## Highlights
- **Re-cropping works.** Re-entering crop shows the whole picture again, so a crop can be widened
  back out or removed. Previously you could only ever cut further in.
- **Apply / Cancel buttons.** Crop had no on-screen controls at all: on a tablet cancelling was
  impossible and applying meant tapping an unmarked area.

## Fixes
- Bug #201: **you could never widen or undo a crop.** `renderCropOverlay` draws the full image
  into the element's frame — and after 0.8.136 shrank that frame to the cropped region, re-entering
  crop mode squeezed the entire picture into the small frame, with the crop rect clamped to it. A
  regression introduced by the crop fix itself.

  Crop mode now temporarily expands the element to show the whole image (positioned so the visible
  region doesn't move) and clears the crop for the duration of the edit. The rect starts on the
  region currently kept, so you can drag outward to reveal more, or out to the edges to remove the
  crop entirely. Cancel restores the original geometry exactly.

- Bug #202: **crop was keyboard-only.** Apply was <kbd>Enter</kbd> or a click outside the crop
  rectangle; cancel was <kbd>Esc</kbd>. On a tablet that leaves applying to an undiscoverable
  tap-outside, and **cancelling was not possible at all**. A crop bar now shows *Drag the handles
  to crop* with **Cancel** and **Apply**. The keyboard shortcuts still work.

- A store-proxy aliasing bug found while building the above: `enterCropMode` read `el.crop.x`
  *after* an `updateElement` had set `crop: null` on the same live proxy, throwing and leaving crop
  mode half-entered. Values are now snapshotted before the update.

## Internal / tests / docs
- `tests/image-and-swatches.spec.ts` gains the full re-crop cycle — crop, re-enter (frame expands,
  crop cleared), widen back to the whole image (crop removed), cancel (geometry restored exactly)
  — plus the crop bar's Apply and Cancel.
- The crop bar lifts toasts clear of itself while open, the same `--toast-bottom` mechanism the
  presentation toolbars use, so it can't be covered by a notification.

## Breaking changes / migration
- None.
