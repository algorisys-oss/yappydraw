# 0.8.277 — The sitemap fix, actually shipped (2026-10-09)

v0.8.276 contained the fix for #429 and changed nothing in production. This ships it, and adds
the check that would have caught both.

## Fixes
- **#430 The generated sitemap date map never reached the mirror.** #429's fix writes
  `frontend/src/prerender/lastmod.json` into the published tree and gitignores it in the source
  repo, because a committed copy could only ever be stale. `.gitignore` travels into the mirror
  with `git archive`, so the mirror's `git add -A` obeyed it and dropped the file — written,
  then discarded. Every signal said success: the publish log read "43 files, 15 distinct
  dates", `--verify` built clean, and all fourteen deploy checks were green, while the live
  sitemap still carried one identical date across 42 URLs. `publish-oss.sh` now force-adds the
  file past the inherited rule and **fails the publish if it is not staged**.
- **#431 `verify:deploy` confirmed the sitemap was served, never that it said anything useful.**
  It asserted `<loc>` elements existed and counted them, which is why #429 survived four
  releases and #430 survived its own fix. It now asserts the `lastmod` dates **vary across
  pages** — diversity rather than freshness, because the signature of both bugs is one date
  moving for everything at once. Skipped on sitemaps with fewer than five URLs.
