# 0.8.152 — Logarithmic axes, and an audit that can't go stale (2026-07-28)

## Highlights
- **Logarithmic axes** — log-log and semi-log plots, so exponential growth and power laws
  read as straight lines.
- The manim-parity audit now **probes behaviour instead of method names**, after it spent
  a release confidently reporting shipped features as missing.

## Features

### Logarithmic axes
```js
// log-log: y = x and y = x² become straight lines of slope 1 and 2
const ax = Yappy.plot.axes({ xMin: 1, xMax: 1000, yMin: 1, yMax: 1000, scale: 'log' });
Yappy.plot.graph(ax, x => x);
Yappy.plot.graph(ax, x => x * x);

// semi-log: exponential growth becomes a straight line
const semi = Yappy.plot.axes({ xMin: 0, xMax: 5, yMin: 1, yMax: 1e5, yScale: 'log' });
Yappy.plot.graph(semi, x => Math.pow(10, x));
```

- `scale` sets both axes; `xScale` / `yScale` override per axis for semi-log plots.
- On a log axis `sx` / `sy` mean **pixels per decade**. `point()` and `coords()` account
  for the scaling in both directions — never do the arithmetic by hand.
- Ticks are placed one per decade, with the unlabelled 2…9 inside each (`minorTicks`),
  giving the familiar log-paper look that makes the scaling obvious at a glance.
- Curves are sampled **geometrically** on a log axis. Uniform sampling would crowd almost
  every point into the last decade — where the axis is most compressed — and draw the
  first decades from two or three samples.
- A log axis has no zero, so its axis line runs along the low edge rather than through the
  origin. A zero or negative bound is clamped to a small positive value rather than
  producing `NaN`.

## Internal / tests / docs
- `tests/manim-parity.spec.ts` rewritten. It answered "what's missing?" by checking for
  method *names* that were guesses at what an implementation might be called
  (`createTex`, `createAxes`); LaTeX shipped as `Yappy.tex`, so the report listed LaTeX,
  vector fields and updaters as MISSING for a whole release after they existed — while
  still passing and still printing a tidy report. Every probe now exercises the capability
  and classifies from the result, and the report cites real evidence ("24 normalised
  arrows", "1/x splits into 2 subpaths"). A behavioural probe can't drift, because the
  only way to report PASS is to make the feature work.
- Current parity: **13 PASS, 2 PARTIAL, 1 MISSING** (3D scene graph).
- `AxesSpec` gains optional `xScale` / `yScale`; older specs without them stay valid.
- New helpers in `utils/plot.ts`: `axisOffset`, `axisValue`, `logTickValues`, `formatTick`.

## Known limitations
- No 3D axes or surfaces — needs a scene graph and camera, the one genuinely large piece
  remaining.
- `texPart` matches by rendered character, so `TransformMatchingTex` proper (matching two
  equations by LaTeX source) is still not implemented.
- `setExpression` has no dependency graph between elements: one object cannot yet redraw
  from another's live state.

## Breaking changes / migration
None. `AxesSpec` gained optional fields only, and axes without them behave exactly as before.
