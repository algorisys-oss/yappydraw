# 0.8.153 — Equation morphing, and a canvas that repaints when you scrub (2026-07-28)

## Highlights
- **`Yappy.texTransform`** — morph one equation into another, matching shared symbols.
  manim's `TransformMatchingTex`, and the move that makes a derivation read as one
  continuous idea instead of a slideshow.
- **Scrubbing the Scene Timeline while paused now repaints the canvas.** It never did:
  the values were always right, the pixels were stale.

## Features

### Equation morphing (`Yappy.texTransform`)
```js
const a = await Yappy.tex(200, 200, 'a^2 + b^2 = c^2', { fontSize: 54 });
const b = await Yappy.tex(200, 200, 'c = \\sqrt{a^2 + b^2}', { fontSize: 54 });

Yappy.texTransform(a.groupId, b.groupId, { duration: 1.5 });
// → { matched: 7, faded: 1, introduced: 2 }
```
Shared symbols glide to their new positions; unmatched source glyphs fade out and new
target glyphs fade in. Glyphs pair by rendered character in reading order, so repeated
symbols match left-to-right. Create the target first — it is held invisible until the
morph runs and is what you are left with afterwards, so morphs chain. Schedules on the
`Yappy.scene` playhead and advances it, so it sequences with `scene.play`/`wait`.

Options: `duration`, `easing`, and `fadeRatio` (how much of the span the fades occupy,
so the glide stays the main event).

## Fixes
- **Seeking while paused never repainted the canvas.** `seekScene(t)` moved the playhead
  and `evaluateComposition(t)` returned the right values, but the canvas kept showing the
  frame it last painted — so an opacity keyframe looked like it did nothing, and a
  position keyframe looked like it worked only sometimes (whenever an unrelated
  interaction happened to trigger a repaint). The render effect tracked the animation
  clock but not `storyTime`, so playback was fine and scrubbing was not. (#218)
- **A second equation re-used the first one's group id.** `texPart` returned glyphs from
  both equations and `texTransform` saw one merged equation rather than a source and a
  target. `generateId` computes "max + 1" by scanning element `.id` fields, and
  `texGroupId` is a tag, not an id — the same shape as two patches already in that file.
  (#219)

## Internal / tests / docs
- Regression for #218 compares canvas **pixels** across two seeks. Every value-based
  assertion in the suite passed throughout the bug's lifetime, including tests written
  for composition playback — only pixels could catch a render-trigger fault.
- Help doc gains a "Morphing one equation into another" section.
- Learnings recorded: why a value assertion can't catch this class of bug, and why
  "works sometimes" points at scheduling rather than logic.

## Known limitations
- Matching is by rendered character, not LaTeX source, so `\alpha` and `a` are distinct
  but two visually identical glyphs from different terms may pair unexpectedly in dense
  expressions. Structural marks without a glyph (fraction bars, radical vinculums) don't
  participate in matching and cross-fade instead.
- No 3D axes or surfaces — still the one genuinely large piece remaining.

## Breaking changes / migration
None.
