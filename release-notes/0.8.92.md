# 0.8.92 — Native colour picker drags again in the Appearance stack (2026-07-13)

## Highlights
- Fixed the "can't drag the colour picker" bug: the browser's native colour popup
  in the **APPEARANCE** fill/stroke rows now tracks a live drag instead of resetting.

## Features
- None.

## Fixes
- **Appearance fill/stroke colour swatch wouldn't drag.** Opening a per-fill/stroke
  colour swatch (the native `<input type="color">` SV square + hue bar + R/G/B
  fields) and dragging the crosshair did nothing / kept resetting. Cause: every
  `onInput` tick rebuilt all fill/stroke objects with fresh identities, and the
  reference-keyed `<For>` then disposed & recreated each row's DOM — destroying the
  open native picker mid-drag (same root cause as the earlier Recolor fix #114).
  The rows now render with `<Index>` (keyed by position), so the native picker's
  element survives a live drag.

## Internal / tests / docs
- `property-panel.tsx` `AppearanceEditor`: fills & strokes lists migrated `<For>` → `<Index>`.
- Logged as bug-fix #162 in `docs/bugs/bug-fixes.md`; learning recorded in `docs/learnings.md`.

## Breaking changes / migration
- None.
