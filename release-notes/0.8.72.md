# 0.8.72 — Blank-on-load fix + dropdown legibility (2026-07-12)

## Highlights
- Fixed the intermittent **blank page on first visit** to the deployed app (it used to only
  appear after a manual refresh). Root cause was the service worker auto-activating a new build
  mid-load; the app now uses a prompt-to-update service worker so the running page is never
  hijacked.

## Fixes
- **Blank on first load, fine on refresh** — the PWA service worker used `autoUpdate`
  (`skipWaiting()` + `clientsClaim()`), so a freshly-deployed worker would activate and evict the
  old precache while the previous page was still fetching its old content-hashed chunks. Those
  chunks 404'd, the app failed to boot, and `#root` was left empty. Switched to the `prompt`
  strategy: a new build now installs and *waits*, and is applied only on an explicit user action
  (offline-ready / update-available toasts; tap the status-bar version number to update).
- **Palette / Background dropdown unreadable** — native `<select>` option popups hardcoded
  `color-scheme: light dark`, so they followed the OS light/dark preference instead of the app
  theme. In dark theme on a light-mode OS this rendered light option text on a white system popup.
  `color-scheme` is now bound to the app theme and the selects inherit it.

## Internal / test changes
- New `frontend/src/utils/pwa.ts` (service-worker registration + update prompt via
  `virtual:pwa-register`); `registerType: 'prompt'`, `injectRegister: false` in `vite.config.ts`;
  `vite-plugin-pwa/client` added to `tsconfig.app.json` types.
- `hard-refresh.ts` doc comment corrected (the app now ships a service worker; the version-tap
  refresh doubles as the "apply the waiting update" button).

## Breaking changes / migration
- None. New builds now apply on the next natural reload or via the version-tap refresh rather than
  silently auto-updating mid-session.
