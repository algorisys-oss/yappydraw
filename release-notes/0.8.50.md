# 0.8.50 — Desktop app Phase 2: native files, recent, associations & auto-update (2026-07-10)

## Highlights
- The **native desktop app** gains a real file experience — Open/Save `.yappy`/`.json`, an Open
  Recent list, double-click file associations, and **auto-update**.

## Features (desktop / Tauri)
- **Native menu bar** — File (New · Open… · **Open Recent** · Save · Save As… · Export PNG ·
  Export SVG · Quit), Edit (Undo · Redo), View (Reset View · Toggle Properties Panel), Help
  (Check for Updates…). File actions have accelerators (⌘/Ctrl+N/O/S/⇧S/E).
- **Native Open/Save** of `.yappy` (GZIP JSON) and `.json` — files interchangeable with the web app.
- **Recent files** — last 10 opened/saved documents, in File ▸ Open Recent.
- **File associations** — double-clicking a `.yappy` opens it in Yappy (single-instance: focuses
  the running window instead of opening a duplicate).
- **Auto-update** — Help ▸ Check for Updates… checks the release endpoint and, on confirm,
  downloads + installs + relaunches. Updates are signature-verified (embedded public key).

## Internal / tests / docs
- Rust commands `read_file` / `get_launch_file` / `set_recent_files` / `check_update` /
  `install_update` + `tauri-plugin-single-instance` + `tauri-plugin-updater`; frontend
  `desktop/desktop-bridge.ts` handles `open-path` events, recents, and the update prompt (all behind
  `isTauri()` — web build unaffected). `utils/document-io.ts` shares the `.yappy` (de)serialization.
- `desktop/README.md` documents the **update-publishing flow** (signing key, `createUpdaterArtifacts`,
  `latest.json`). Updater signing key generated (private key gitignored; public key embedded in
  `tauri.conf.json`).
- Verified: Rust compiles with single-instance + updater + dynamic recent-files menu; frontend
  typechecks; web build inert (no `__TAURI__`, no errors). App version kept in step across
  `package.json` / `tauri.conf.json` / `Cargo.toml`.

## Breaking changes / migration
- None (web build unchanged).
