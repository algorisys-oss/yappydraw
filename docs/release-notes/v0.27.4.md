# Release Notes - v0.27.4

**Release Date:** May 6, 2026

## Overview

Two iPad-related fixes following v0.27.1's palm-rejection rework:

1. **Alternate strokes were dropping** when writing fast with Apple Pencil — every other character would silently fail.
2. **Canvas Settings was unreachable** on iPad because the only entry point was the canvas right-click context menu, which now requires a real mouse right-click.

## Fixes

### Alternate-stroke loss with Apple Pencil

**Symptom.** Writing quickly with Apple Pencil: first letter draws, next is empty, third draws, fourth is empty. Cursive strokes (one continuous stroke) work fine.

**Cause.** iPad Safari occasionally misclassifies the first `pointerdown` of a rapid consecutive Pencil tap as `pointerType: 'touch'` instead of `'pen'`. v0.27.1's palm rejection blocks any touch event for 700 ms after a pen contact, so the misclassified Pencil-down was rejected and `drawOnDown` never ran. The follow-up `pointermove` and `pointerup` events arrived correctly as `'pen'`, but with `pState.isDrawing` still false there was nothing to append to.

**Fix.** Added a contact-area heuristic. `PointerEvent.width` and `height` report the contact patch in CSS pixels:

| Input source                    | Typical width/height |
| ------------------------------- | -------------------- |
| Apple Pencil tip                | 1-2 px               |
| Finger                          | 25-40 px             |
| Palm                            | 50+ px               |

If a `pointerType: 'touch'` event has `width ≤ 5 && height ≤ 5`, we treat it as a misclassified Pencil tip and let it through (also promoting it to "active pen" so subsequent palm contacts in the same stroke are still rejected). Real palm contacts (large area) are still blocked.

### Pointer-cancel cleanup

Added `onPointerCancel={handlePointerUp}` on the canvas. iOS sometimes fires `pointercancel` (instead of `pointerup`) when it interrupts a stroke to handle a gesture. Without a handler, `pState.isDrawing` and `currentId` would stay set, leaving the next stroke in an inconsistent state. Mirroring `pointerup` cleans up the state machine.

## Added

### Canvas Settings menu entry

Added "Canvas Settings" to the main hamburger menu, right under "Properties Panel". Tapping it clears the current selection, switches the property panel to canvas-properties view, and opens the panel. This restores iPad access — the only previous entry point was the canvas right-click context menu, which v0.27.1 restricted to real mouse right-clicks.

## Key Files Modified

- `frontend/src/components/canvas.tsx` — `isPencilSizedTouch` heuristic; updated palm-rejection in `handlePointerDown` / `handlePointerMove` / `handlePointerUp`; `onPointerCancel` handler
- `frontend/src/components/menu.tsx` — Canvas Settings menu item
- `package.json` — version bump to 0.27.4
