# Release Notes - v0.27.1

**Release Date:** May 6, 2026

## Overview

Targeted fix-up release for iPad + Apple Pencil. Resting a palm on the screen no longer pops the context menu or property panel, and Apple Pencil strokes feel as smooth as the device can draw.

## Fixes

### Palm rejection on iPad

While a stylus (`pointerType === 'pen'`) is active or was used within the last 700 ms, all `pointerType === 'touch'` events are dropped at the top of `handlePointerDown` / `handlePointerMove` / `handlePointerUp`. A resting palm during an Apple Pencil stroke can no longer:

- Draw a stray line
- Pan the canvas
- Pop a context menu
- Open the property panel from a toolbar button

The canvas also picks up `-webkit-user-select: none` and `-webkit-touch-callout: none` so iOS's own copy/look-up callout doesn't interrupt long strokes.

### Context-menu suppression on touch/pen long-press

iOS Safari synthesizes a `contextmenu` MouseEvent on every long-press, including a resting palm. Previously this triggered:

- The canvas context menu
- The property panel from any tool-group button (right-click shortcut)

Every `contextmenu` handler — the canvas surface plus all 17 toolbar/tool-group `handleRightClick` functions — now early-returns unless `e.button === 2` (real mouse right-click). Touch and pen long-press are silently swallowed.

### Apple Pencil stroke smoothness

`pen-handler.ts` previously buffered coalesced events but flushed the store at most once every 16 ms wall-clock. Combined with the outer pointermove RAF, an Apple Pencil sample at ~120 Hz could sit one full frame in the buffer before being drawn — visibly laggy and jittery.

The 16 ms throttle is removed. `getCoalescedEvents()` still surfaces every Pencil sample (so no resolution is lost), but the buffer now flushes on every pointermove and batches naturally with the existing RAF draw. Strokes now keep up with the Pencil tip without dropping frames.
