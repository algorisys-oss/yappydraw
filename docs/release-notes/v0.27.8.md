# Release Notes - v0.27.8

**Release Date:** May 6, 2026

## Overview

Real fix for the iPad/Apple Pencil "alternate empty characters" bug after four prior attempts. Crucial new diagnostic from the user: **finger works fine. Mouse works fine. Only Apple Pencil fails.**

## What That Tells Us

If finger and mouse work but Apple Pencil fails, the cause **isn't**:

- ❌ JS thread blocking — would affect finger too.
- ❌ `pushToHistory` cost — would affect finger too.
- ❌ Reactive cascade overhead — would affect finger too.
- ❌ `setPointerCapture` timing — would affect both pen and finger.

It must be something **specific to how iPad Safari delivers Apple Pencil events** during rapid lift+recontact.

## The Real Cause

**iPadOS Apple Pencil double-tap gesture detection.** When the user lifts the Pencil and re-contacts within ~150 ms, the system briefly checks whether this is the "tap-the-side-of-the-Pencil" shortcut that toggles tools (or the alternative "Apple Pencil 2 double-tap to switch eraser" gesture). During that check, **iPadOS suppresses the alternate `pointerdown` event from being dispatched to JavaScript** while it disambiguates.

What still fires:
- ✅ `pointerup` of stroke N — finalizes stroke N normally.
- ✅ `pointermove` events of stroke N+1 — but `isDrawing` is `false` because `drawOnDown` never ran.
- ✅ `pointerup` of stroke N+1 — but `drawOnUp` early-returns because `!isDrawing`.

Result: stroke N+1 is silently lost. The user sees alternate empty characters because each lift+recontact has a chance of triggering the gesture detector.

This explains the entire fingerprint of the bug:
- Cursive works → no lift, no double-tap detection.
- Slow writing works → time gap exceeds the double-tap window.
- Finger works → no Apple Pencil gesture to detect.
- Mouse works → not a Pencil gesture.

## The Fix

Recovery in `handlePointerMove`: when a `pointerType: 'pen'` move arrives with `pressure > 0` while a pen-drawing tool is active and `!pState.isDrawing`, synthesize the missed `drawOnDown` from the move's coordinates and fall through to the normal pen-on-move handling.

```ts
const isPenStrokeStart = e.pointerType === 'pen'
    && (e as any).pressure > 0
    && !pState.isDragging
    && !pState.isPolylineBuilding
    && !pState.draggingFromConnector;
const drawingTool = store.selectedTool === 'fineliner' /* or inkbrush, marker, ink */;
if (isPenStrokeStart && drawingTool) {
    drawOnDown(x, y, pState, pHelpers);
    // Fall through to penOnMove below.
}
```

The synthesized stroke starts ~1 pointermove later than the original would have — but at Apple Pencil's 120 Hz event rate that's ~8 ms, well inside the same animation frame. The visible difference between "real" and "synthesized" stroke starts is imperceptible.

## Why a Workaround?

Web JavaScript can't intercept iPadOS-level gesture detection. We can only react to what events do or don't reach our handlers. The recovery path catches the case where the OS swallowed the `pointerdown`, restoring the stroke to its intended geometry (minus the very first sample).

## Key Files Modified

- `frontend/src/components/canvas.tsx` — recovery branch in `handlePointerMove` that synthesizes a missed `drawOnDown` when a pen stroke arrives without one
- `package.json` — version bump to 0.27.8
