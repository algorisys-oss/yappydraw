# Release Notes - v0.27.2

**Release Date:** May 6, 2026

## Overview

Hotfix for iPad + Apple Pencil drawing reliability. v0.27.1 introduced a regression where pen strokes were dropped between characters and inkbrush appeared to erase itself mid-stroke. This release reverts to a RAF-driven flush that's both smooth and stable.

## Fixes

### Dropped strokes between letters with Apple Pencil

**Symptom:** With fineliner selected, write one letter — works. Write the next — nothing. Write a third — works again. Sometimes a stroke produces nothing at all. Cursive (continuous) strokes work fine. Mouse on desktop is unaffected.

**Cause:** v0.27.1 removed the 16 ms wall-clock throttle in `pen-handler.ts` and started calling `updateElement` on **every** `pointermove`. Apple Pencil fires `pointermove` at ~120 Hz, so iPad's JS main thread was hit with 120 Solid `setStore` mutations per second, each cascading through reactive subscribers. The thread saturated, and incoming `pointerdown` events for new strokes were occasionally swallowed.

**Fix:** Coalesced events still flow into the points buffer on every move (no input resolution lost), but the buffer is now flushed to the store at most **once per animation frame** via `requestAnimationFrame`. This caps store mutations at the display refresh rate (~60 Hz on iPad), frees the main thread for pointer events, and matches the existing `requestAnimationFrame(draw)` cadence in `handlePointerMove`.

### Inkbrush appears erased / overwritten with white

Same root cause. With `updateElement` firing 120 Hz, the canvas was redrawing inkbrush mid-render, producing visibly incomplete frames that looked like the stroke was being washed out. Capping store updates to one per frame eliminates the flicker — each render now sees a consistent, complete points array.

## Why This Is Different from the Original 0.27.1 Approach

v0.27.1's intent was right (don't add wall-clock throttle on top of RAF), but the implementation went too far the other way. The original 0.27.0 code had:

```js
if (now - lastPenUpdateTime >= 16ms) flushPenPoints();
else if (!penUpdatePending) requestAnimationFrame(flushPenPoints);
```

That logic could leave a sample sitting one extra frame in the buffer when the wall-clock window hadn't elapsed. v0.27.1 removed it and flushed every move — which over-corrected. v0.27.2 keeps only the RAF branch:

```js
if (!penUpdatePending) {
    penUpdatePending = true;
    requestAnimationFrame(() => {
        penUpdatePending = false;
        flushPenPoints();
    });
}
```

Exactly one flush per frame, no wall-clock check, no extra latency. Apple Pencil samples at 120 Hz still all reach the buffer (via `getCoalescedEvents`), and the next vsync paints them.

## Key Files Modified

- `frontend/src/utils/tool-handlers/pen-handler.ts` — RAF-driven flush; removed sync flush-every-move
- `package.json` — version bump to 0.27.2
