# Release Notes - v0.27.14

**Release Date:** May 6, 2026

## Fixed

### Strict alternate-empty-stroke pattern (1, _, 3, _, 5)

User report after v0.27.13: writing 1-2-3-4-5 with Apple Pencil produced only odd-numbered strokes. Strict alternation is diagnostic — it means stroke 2's `touchstart` *was* reaching my handler, but bailing because `pState.isDrawing` was still `true` from stroke 1. Stroke 1's `touchend` had not finalized.

The cause: v0.27.11 added a "find the tracked Touch in `changedTouches`" gate to `handleTouchEnd` for palm safety. On iPad, `touchend` events sometimes don't carry our tracked identifier in `changedTouches` — and when that happens, the gate silently dropped the legitimate end. `pState.isDrawing` and `touchDrivingPenStroke` stayed stuck. Stroke 2 saw the stuck state, bailed, and was lost. After stroke 2's silent failure, the state finally reset and stroke 3 started clean. Stroke 4 hit the same trap. Hence: 1, _, 3, _, 5.

## Two fixes

1. **`handleTouchEnd` finalizes unconditionally** when `touchDrivingPenStroke` is true. iPadOS's system-level palm rejection means non-pen touches don't reach us when an Apple Pencil is paired, so the gate was over-defensive. Drop it.

2. **`handleTouchStart` self-heals stale state**. New helper `finalizeTouchStroke()` unconditionally finalizes any in-flight stroke. `handleTouchStart` calls it at the top if the previous stroke is somehow still active. Any stuck flag from any cause now resolves on the next touchstart instead of blocking every subsequent stroke.

## Key Files Modified

- `frontend/src/components/canvas.tsx` — `finalizeTouchStroke()` helper; `handleTouchStart` self-heal; `handleTouchEnd` unconditional finalize
- `package.json` — version bump to 0.27.14
