# Release Notes - v0.27.12

**Release Date:** May 6, 2026

## Fixed

### iPad Apple Pencil stroke latency on both Safari and Chrome

User confirmed the lag was identical on Chrome on iPad — both Safari and Chrome use WebKit on iOS, so the bottleneck is engine-wide. The reference demo at https://github.com/shuding/apple-pencil-safari-api-test runs smoothly on the same iPad because it has no reactive system at all.

The canvas's main redraw effect was iterating every element and reading 80+ properties on each:

```ts
store.elements.forEach(e => {
  e.x; e.y; e.width; e.height; e.angle; e.opacity; ... e.bpmnEventType; ...
  e.orbitDirection; // ~80 in total
});
```

This subscribed the effect to every per-property change so any mutation triggered a redraw. At Apple Pencil's ~120 Hz event rate every `flushPenPoints` fired this effect. With even 50 elements that's `50 × 80 = 4000` proxy reads per flush — tens of thousands per second. JS thread saturation, visible stroke lag.

## The Fix

Replace the per-element forEach with a single dependency on `store.dirtyRevision`:

```ts
createEffect(() => {
  effectiveTime();
  store.appMode;
  // ...
  store.elements.length;
  store.dirtyRevision;          // single coarse "something mutated" counter
  // ...
  requestAnimationFrame(draw);
});
```

`updateElement` (and the existing `addElement` / `deleteElements` paths) bump `dirtyRevision` on every mutation. The effect fires the same way it did before — but at O(1) cost instead of O(elements × properties).

## Key Files Modified

- `frontend/src/components/canvas.tsx` — drop the 80-property element forEach, add `store.dirtyRevision` dep
- `frontend/src/store/app-store.ts` — `updateElement` now calls `bumpDirtyRevision()`
- `package.json` — version bump to 0.27.12
