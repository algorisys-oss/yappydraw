# Release Notes - v0.27.13

**Release Date:** May 6, 2026

## Fixed

### Sync flush + sync draw in touchmove (match the reference demo's latency)

The reference demo at https://github.com/shuding/apple-pencil-safari-api-test calls `drawOnCanvas()` synchronously inside its `touchmove` handler — that's where its low-latency feel comes from. Our app was scheduling `flushPenPoints` and `draw` via `requestAnimationFrame`, adding 1-2 frames of delay between Pencil tip and visible stroke.

Switched touchmove to:

```ts
const handleTouchMove = (e) => {
  // ... pick stylus touch, push to buffer ...
  flushPenPoints();   // sync
  draw();             // sync
};
```

With v0.27.12's O(1) reactive cascade, sync flush is sub-ms and sync draw is O(elements) — fits inside a frame at typical doc sizes. The display compositor picks up the new canvas state at next vsync, same as the demo.
